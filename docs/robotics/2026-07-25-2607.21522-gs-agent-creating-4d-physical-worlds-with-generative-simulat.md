## Abstract (초록)

자연어 설명으로부터 동적이고 물리적으로 사실적인 4D 세계를 만드는 것은 매혹적이면서도 도전적입니다. 기존의 컴퓨터 그래픽스 방법은 수동 제작에 의존하며, 재료, 움직임, 시각적 충실도를 미세 조정하기 위해 광범위한 인간 노력이 필요합니다. 생성적 기초 모델의 최근 발전은 대규모 데이터에서 이러한 4D 세계를 생성하는 학습에 대한 관심을 불러일으켰지만, 기존 방법은 여전히 물리적 그럴듯함과 제어 가능성을 보장하는 데 어려움을 겪고 있습니다. 본 연구에서는 기초 모델을 활용해 인간이 전통적으로 4D 세계를 만드는 방식을 모방하면서 전체 과정을 자동화하는 에이전트 시스템을 구축하는 다른 경로를 택합니다. 우리는 GS-Agent를 제시합니다. 이는 물리 엔진을 루프에 통합해 자연어로부터 사실적이고 동적이며 제어 가능한 4D 물리 세계를 생성하는 엔드-투-엔드 다중 에이전트 프레임워크입니다. 인간이 4D 세계를 구축하는 방식을 영감으로 삼아, GS-Agent는 개체 관리, 3D 자산 선별, 재료 조정, 배치 및 움직임 제어, 렌더링 구성(카메라 및 조명 조작)을 포함한 과업을 분해합니다. 서로 다른 전문성을 가진 다수의 에이전트가 코드로 물리 엔진과 상호작용하며 다중 모달 피드백을 탐색하고 협력해 주어진 설명에 부합하는 4D 세계를 반복적으로 구축합니다. 실험 결과는 GS-Agent가 액체, 변형 물체 및 강체 사이의 풍부한 상호작용을 보여주는 물리적으로 그럴듯한 다양한 4D 세계를 자연어로 효과적으로 변환하며, 영화 같은 카메라 및 조명 제어를 달성함을 보여줍니다. 우리는 GS-Agent를 4D 세계 생성의 새로운 패러다임의 기초로 상상하며, 창의적 콘텐츠 제작과 물리 AI를 강화합니다. 비디오는 프로젝트 페이지[1](#page-1-0)를 참조하십시오.

## 1 Introduction (서론)

동적이고 물리적으로 그럴듯한 4D 세계를 만드는 것은 구현 AI, 자율 주행, 게임, 영화 제작 등 다양한 분야에서 광범위한 응용을 가지고 있습니다. 다양한 현실적인 물리 환경을 구축함으로써 구현 에이전트가 보다 안전하고 풍부한 설정에서 훈련되고 평가될 수 있어, 배포 시 시뮬레이션-실제 차이를 좁히는 데 도움을 줍니다 [&#91;78&#93;](#page-13-0). 또한, 사용자가 자연어를 통해 4D 세계를 구축하고 제어할 수 있게 함으로써 창의적 콘텐츠 제작의 장벽을 크게 낮추어 보다 표현력 있는 스토리텔링, 풍부한 엔터테인먼트 경험, 완전히 새로운 창작 형식을 열어줍니다. 그러나 기존 접근 방식은 3D 자산 선별, 재료 매개변수 조정부터 장면 구성, 물체 움직임 조정, 조명 설정, 카메라 궤적 설계에 이르기까지 막대한 인간 노력을 요구합니다.

최근 기초 모델의 발전은 언어 이해 [47], 이미지 합성 [36, 22], 비디오 생성 [5, 68, 48, 57], 그리고 3D/4D 장면 생성 [71, 4]을 크게 향상시켰다. 그러나 이러한 모델은 여전히 물리적 타당성 [43, 29]과 제어 가능성 [20]에 어려움을 겪고 있다. 이러한 한계는 대규모 데이터만으로 4D 세계를 학습하는 것이 일관되고 물리적으로 기반이 되는 장면을 생성하기에 충분하지 않음을 시사한다. 인간이 세계를 만드는 방식을 영감으로 삼아, 대형 언어 모델의 추론 능력 [18]을 활용해 계획, 비판, 그리고 반복적으로 세계 생성을 정제하는 에이전시 시스템을 구축하는 보완적 방향이 있다. 이전 연구는 에이전시 시스템의 가능성을 보여 주었다: [67]은 GitHub 이슈를 자율적으로 해결할 수 있는 소프트웨어 엔지니어링 에이전트를 개발하고, [25]는 Blender를 통해 정적 3D 장면을 제작하는 에이전시 파이프라인을 구축했다.

본 연구에서는 GS-Agent를 소개한다. GS-Agent는 물리 엔진을 루프에 통합한 종단 간 다중 에이전트 프레임워크로, 자연어 설명에서 직접 현실적이고 동적이며 제어 가능한 4D 물리 세계를 생성한다. 인간의 워크플로우에서 영감을 받아, GS-Agent는 생성 과정을 두 개의 조정된 구성요소로 분해한다: *엔티티 관리(entity management)*, 여기에는 3D 자산 검색, 재질 조정, 객체 배치, 움직임 제어가 포함되고, *렌더링 구성(rendering configuration)*, 여기에는 카메라 조작 및 조명 설계가 포함된다. 여러 전문 에이전트가 코드로 물리 엔진과 상호작용하며 다중 모달 피드백을 얻고, 협업적으로 시뮬레이션을 정제하여 주어진 지침을 충실히 따르는 세계를 만든다.

GS-Agent를 유동체, 변형 물체, 그리고 강체 간의 복잡한 상호작용과 다양한 카메라 및 조명 제어가 포함된 장면에서 평가한다. 최첨단 텍스트-투-비디오 모델(Sora2 [48] 및 Wan2.2 [57])과 에이전시 기반 기준(SWE-Agent [67] 및 시각 피드백이 포함된 향상된 변형)과 비교할 때, GS-Agent는 더 높은 물리적 타당성, 강력한 지침 충실도, 그리고 세밀한 제어 가능성을 보여 주는 4D 세계를 생성한다. 또한, 그 에이전시 설계는 예기치 못한 실패를 완전 자율적으로 식별하고 해결할 수 있게 한다. 우리는 GS-Agent를 4D 세계 생성의 새로운 패러다임으로 나아가는 디딤돌로 envision하며, 대화형 콘텐츠 제작을 가능하게 하고 대규모, 물리적으로 기반이 되는 데이터 생성을 지원한다. 요약하면, 우리의 기여는 세 가지이다:

- 우리는 인간의 4D 세계 구축 워크플로우를 모방한 자동화된 에이전시 프레임워크와 강력한 물리 엔진을 활용하여 자연어로부터 4D 물리 세계를 생성하는 어려운 문제를 해결한다. - 우리는 GS-Agent를 소개한다. GS-Agent는 코드로 물리 엔진과 상호작용하고, 다중 모달 피드백을 적극적으로 탐색하며, 협업적으로 자연어와 일치하는 4D 세계를 구축하는 종단 간 다중 에이전트 프레임워크이다.

## 2 관련 연구 (Related Work)

### 2.1 3D 및 4D 생성 (3D and 4D Generation)

3D 장면을 자연어로 생성하는 것은 오랫동안 도전 과제로 남아 있다 [10]. 초기 연구들은 규칙 기반 언어-공간 매핑에 의존했다 [9, 42], 반면 현대 접근법은 대규모 데이터에서 3D 콘텐츠를 생성하는 방법을 학습한다 [71, 70, 14, 60, 40], 주로 생성적 확산 모델 [61]과 가우시안 스플래팅 [65]에 의존한다. 물리적으로 타당한 움직임을 3D 장면에 통합하기 위해 많은 연구가 물리 솔버를 활용한다 [12, 4, 66, 76, 17, 58]. 특히 [41]은 LLM을 활용해 모션 제어용 Blender 스크립트를 작성하고, 물리적으로 타당한 프레임에 조건화된 비디오를 생성한다. [32]는 혼합 생성 시뮬레이터를 사용해 단일 이미지에서 액션-조건화된 동적 3D 장면을 생성한다. 다르게, 우리는 4D 세계를 생성하는 과정을 자동화하는 엔드-투-엔드 에이전트 시스템을 구축할 것을 제안한다. 이는 시각적 생성 모델의 불안정한 일반화 문제를 겪지 않는다.

### 2.2 텍스트-비디오 생성 (Text-to-Video Generation)

현대 비디오 생성 모델은 주로 확산 모델 [54, 22, 5, 21, 13] 또는 자기 회귀 모델 [72, 30]에 기반한다. Diffusion Transformer (DiT) [50, 48, 68]의 도입은 데이터 규모를 늘려 비디오를 생성하는 학습의 잠재력을 더욱 입증하며, 일부 연구는 물리적 선행 지식을 통합해 비디오의 물리적 사실성을 향상시킨다 [73, 41, 38]. 그러나 이러한 모델은 여전히 물리적 타당성 [29], 제어 가능성 [20, 77], 일관성 [8]에 어려움을 겪는다. 우리의 방법은 물리 엔진에서 세계를 제작하여 타당한 물리적 상호작용을 제공한다.

### 2.3 기초 모델 에이전트 (Foundation Model Agents)

기초 모델의 급속한 발전 [47, 18]으로 인해 강력한 에이전트가 급증했다 [55, 63, 59]. 이들은 텍스트 도메인에서만 동작하는 에이전트 [19, 53]부터 GUI와 상호작용할 수 있는 다중 모달 에이전트 [23, 1], 물리적 세계에서 로봇으로 기능하는 에이전트 [2, 26, 16], 그리고 범용 에이전트 [51, 24]까지 다양하다. 다중 에이전트 프레임워크는 다양한 과제에서 유망한 성능 향상을 보였다 [31, 62, 24], 예를 들어 구현형 AI [74], 추론 [15], 코드 생성 [39] 등이 있다. 특히 [67]은 실제 GitHub 이슈를 자동으로 해결할 수 있는 소프트웨어 엔지니어링 에이전트를 구축하고, [25, 56, 69, 35]는 3D 소프트웨어인 Blender를 활용해 정적 3D 장면을 제작하는 에이전트를 만든다. 이와 달리, 우리는 물리 엔진을 루프에 포함시켜 자연어로부터 4D 세계를 구축할 수 있는 최초의 에이전트를 소개한다.

## 3 생성적 시뮬레이션을 포함한 다중 에이전트 프레임워크 (GS-Agent: A Multi-Agent Framework with Generative Simulation in the Loop)

Creating a 4D 세계를 만드는 것은 복잡하고 다단계의 과정으로, 일반적으로 엔티티 모델링, 재질 설계, 공간 배치, 움직임 명세, 조명 설정, 카메라 계획 등 다양한 전문 분야의 협업이 필요합니다. 인간 제작 파이프라인, 예를 들어 시각 효과나 게임 개발에서 감독은 고수준 요구사항을 실행 가능한 계획으로 번역하고, 전문가에게 작업을 위임하며, 중간 결과를 평가하고, 자연어 커뮤니케이션을 통해 반복적인 정제를 조정합니다. 이러한 워크플로우에서 영감을 받아 우리는 *Manager Agent*, *Entity Agent*, *Render Agent*라는 세 개의 전문 에이전트가 물리 엔진 위에서 물리적으로 타당한 4D 세계를 공동으로 구축하는 엔드-투-엔드 다중 에이전트 프레임워크인 GS-Agent를 소개합니다. 이는 Figure [2.](#page-3-0)에 표시됩니다. 우리는 먼저 sec [3.1,](#page-3-1)에서 *physics engine*의 기본 개념을 다루고, 그 다음 세 개의 전문 에이전트: Manager Agent는 사용자 커뮤니케이션, 단계별 계획, 작업 위임, 검증, 전역 시뮬레이션 구성을 sec [3.2;](#page-3-2)에서 담당하고, Entity Agent는 엔티티 생성, 형태학, 재질 할당, 움직임 제어를 sec [3.3;](#page-4-0)에서 전문화하며, Render Agent는 카메라와 조명 조작을 관리하고 다른 에이전트에게 시각적 피드백을 sec [3.4.](#page-4-1)에서 제공합니다. 에이전트들은 *SendMessage* 도구를 통해 서로 통신하고, 구조화된 도구 인터페이스를 통해 물리 엔진과 상호작용합니다. 시스템의 기반에서 모든 에이전트는 물리 엔진과 인터페이스하는 실행 가능한 코드를 생성하고 정제하며, 물리 경계 검사, 프로그램 런타임 정보, 이미지, 비디오를 포함한 멀티모달 피드백을 요청하고, 서로 통신하며, 자연어 목표가 만족될 때까지 세계를 반복적으로 개선합니다. 프롬프트와 도구 인터페이스의 전체 목록은 부록 [B.](#page-14-0)에 제공됩니다.

Figure 2: **GS-Agent 개요.** *Manager Agent*는 자연어 설명을 해석하고, 실행 가능한 하위 작업으로 분해하며, 전역 시뮬레이션 옵션을 구성하고, 장면 진행을 제어하며, 적절한 에이전트에게 작업을 위임합니다. *Entity Agent*는 형태학적 생성용 자산을 선별하고, 공간 제약에 따라 엔티티를 배치하며, 물리적 타당성을 위해 재질 매개변수를 조정하고, 엔티티 움직임을 제어합니다. *Render Agent*는 조명 및 카메라 설정을 조작하고, 카메라 궤적을 구성하며, 비디오 녹화를 설정합니다. 에이전트들은 *SendMessage* 도구를 통해 통신하고, 구조화된 도구 인터페이스를 통해 물리 엔진과 상호작용합니다. 최종 4D 세계는 실행 가능한 시뮬레이션 코드와 렌더링된 비디오로 표현됩니다. 전체 도구 설명은 부록 B에 제공됩니다.

#### <span id="page-3-1"></span>3.1 물리 엔진

물리 엔진은 동적 세계를 구축하고 시뮬레이션하기 위한 통합된 계산 프레임워크를 제공합니다. 핵심 구성 요소는 다음과 같습니다:

- 엔티티 (Entity). 엔티티 컴포넌트는 장면에서 객체를 정의한다. 각 엔티티는 E = (Morph, Material, Surface)로 정의된다. Morph는 기하학(원시 형태 또는 메쉬)을 지정한다. Material은 물리적 거동(고체, 변형 가능, 액체)을 결정한다. Surface는 시각적 속성을 제어한다. 또한 초기 속도, 가해지는 힘, 운동학적 궤적, 제약 조건 등 제어 파라미터를 포함하여 솔버에게 완전하게 지정된 객체 상태와 운동 입력을 제공한다.  
- 솔버 (Solver). 솔버 컴포넌트는 엔진이 물리 역학을 계산하는 방식을 규정한다. 솔버는 엔티티 재질에 따라 선택되고 구성된다. 예를 들어, 고체 객체에는 고체-체 솔버, 변형 가능한 객체에는 Material Point Method (MPM) [28]와 같은 연속체 방법, 유체에는 Smoothed Particle Hydrodynamics (SPH) [46]와 같은 입자 기반 솔버가 사용된다. 시간 단계와 해상도와 같은 솔버 파라미터는 안정성과 정확성을 관리하며, 엔티티의 움직임이 일관된 물리 법칙을 따르도록 보장한다.  
- **렌더러 (Renderer)**. 렌더러 컴포넌트는 물리 시뮬레이션 결과를 화면에 표시하며, 일반적으로 물리 엔진과 별개의 시스템이다. 렌더러 파라미터에는 카메라(위치, 각도, 시야각), 조명(광원 종류, 위치, 색상, 강도), 그림자(품질 및 그리기 거리)가 포함된다.

#### <span id="page-3-2"></span>3.2 매니저 에이전트 (Manager Agent)

작업 분해 및 위임. 자연어 설명을 주면, 매니저 에이전트는 사용자 의도를 해석하고 필요한 장면 구성요소를 추론하며 실행 가능한 다단계 계획을 수립한다. 매니저 에이전트는 엔티티 에이전트나 렌더 에이전트의 역량에 따라 한 번에 하나의 하위 작업을 할당한다. 예를 들어, 적절한 기하학 및 재질 속성을 갖는 자산 생성, 기하학적 제약 하에서의 공간 배치, 또는 원하는 영화적 효과를 위한 카메라 궤적 정제 등이 있다. 각 하위 작업이 완료되면, 매니저 에이전트는 결과를 비판적으로 검증하고 사양이 충족될 때까지 반복적인 정제를 트리거한다.

**장면 구성 (Scene Configuration).** 매니저 에이전트는 생성 전후에 시뮬레이션 및 시각화 옵션을 구성한다. 전역 시뮬레이션 파라미터(예: 시간 단계, 서브스텝, 중력), 솔버별 설정(예: MPM 그리드 해상도 및 도메인 경계, SPH 입자 크기), 시각화 옵션(그림자, 배경 색상, 입자 렌더링 모드, 세분화 수준)을 설정한다.

이러한 설정은 안정적인 물리, 일관된 도메인 규모, 그리고 후속 추론을 위한 명확한 시각적 진단을 보장한다.

**타임라인 제어 (Timeline Control).** 구축된 세계의 진화하는 역학을 평가하기 위해, 매니저 에이전트는 시뮬레이션의 시간 진행을 조절한다. 시나리오를 진행하거나 재설정하여 중간 상태를 탐색하고, 수정 결과를 평가하거나 다단계 롤아웃을 수행할 수 있다. 모든 구성 요소가 언어 사양을 충족하는지 확인한 뒤, 에이전트는 최종 실행을 시작하고 비디오 캡처를 트리거하여 완성된 4D 세계를 생성한다.

## <span id="page-4-0"></span>3.3 엔티티 에이전트 (Entity Agent)

**3D 모델 자산 검색 (3D Model Asset Retrieval).** 현실적인 엔티티를 구성하기 위해, 엔티티 에이전트는 먼저 텍스트와 이미지 임베딩으로 구축된 의미 인덱스를 사용해 선별된 라이브러리(BlenderKit<sup>2</sup> 및 PolyHaven<sup>3</sup>)에서 자산을 검색한다. 질의 임베딩은 텍스트 인코더와 CLIP [52]를 사용해 생성되며, 연결 및 정규화 후 사전 계산된 메타데이터와 다중 뷰 이미지 임베딩에 대해 검색된다. 검색기는 하위 생성에 유용한 정보(로컬 파일 경로, 짧은 설명, 미리보기 이미지, 매치 점수, 축 정렬 경계)를 포함한 상위 후보를 반환한다.

**3D 모델 자산 생성 (3D Model Asset Generation).** 에이전트가 요구 사항을 충족하는 적절한 3D 모델 자산을 검색하지 못하면, Meshy [44]를 호출해 텍스트-투-3D 모델을 사용하여 3D 모델 자산을 생성하고, 자산의 동일한 메타데이터를 계산하여 큐레이션된 자산 라이브러리에 저장한다. 생성 결과를 기반으로 에이전트는 텍스트 쿼리를 적절히 조정할 수 있다. 최대 실패 횟수에 도달하면, 에이전트는 필요한 형태를 구성하기 위해 프리미티브를 사용하도록 시도한다.

**엔티티 배치 (Entity Placement).** 3D 모델 자산 메타데이터를 기반으로 엔티티 에이전트는 타당한 스케일, 방향, 위치를 계산한다. 엔티티 에이전트는 정규화된 방향을 사용해 자산을 정렬하고, AABB 경계에서 메쉬를 재스케일링하며, 휴식 표면, 비침투, 충분한 간격과 같은 세계 공간 제약을 만족하도록 배치한다. 엔티티 에이전트는 장면 상태를 조회하고 렌더 에이전트에게 시각적 피드백을 요청한다; 정렬 불일치나 충돌이 감지되면, 수정하고 반복한다.

물리적으로 타당한 재료 조정 (Physically Plausible Material Tuning). 물리 재료 매개변수 조정은 악명 높게 어렵고 비전문가에게는 종종 비현실적이다 [37]. 잘못 구성된 매개변수는 비현실적이거나 불안정한 시뮬레이션을 초래할 수 있다. 엔티티 에이전트는 일반적인 선험적 사전 정보를 사용해 재료 선택을 초기화하고, 물리 엔진으로부터의 실제 물리 피드백을 기반으로 매개변수를 반복적으로 정제한다. 연속체 재료를 예로 들면, 엔티티 에이전트는 시뮬레이션에서 나타난 실제 변형 정도에 따라 영률(Young's modulus), 포아송 비(Poisson's ratio), 항복 응력(yield stress) (플라스틱성용)과 같은 원칙적 매개변수를 조정한다. 또한, 엔티티별 재료 매개변수를 솔버 제약(예: MPM 그리드 크기, SPH 입자 반경)과 정렬시켜 안정적인 해상도 스케일을 유지한다.

**엔티티 모션 (Entity Motion).** 엔티티 에이전트는 시뮬레이션 중에 실행되는 단계별 제어 함수를 편집함으로써 움직임을 제어한다. 지원되는 제어 방식에는 PD 컨트롤러, 강체용 직접 위치/속도/힘 명령, 입자 기반 재료용 프로그래머블 방출기가 포함된다. 이 인터페이스를 통해 동일한 시뮬레이션 타임라인 내에서 운동학적 궤적과 일시적인 입자 이벤트를 스크립팅할 수 있다.

### <span id="page-4-1"></span>3.4 렌더 에이전트 (Render Agent)

**카메라 위치 지정 (Camera Positioning).** 렌더 에이전트는 중간 검사와 최종 렌더링 모두를 위해 카메라 배치와 내부 파라미터를 결정한다. 에이전트는 특정 시점이나 프레이밍 요청과 같은 구두 지시를 세계 좌표계에 기반해 해석한다. 필요 시, 에이전트는 엔티티의 공간 상태(예: 위치 및 범위)를 조회해 요청된 시각적 관점과 일치하도록 카메라를 배치한다.

카메라 움직임 및 비디오 캡처 (Camera Motion and Video Capturing). 시간적으로 일관된 시각화를 생성하기 위해 렌더 에이전트는 시뮬레이션 진행 중에 실행되는 명시적 제어 코드로 카메라 움직임을 표현한다. 이 코드는 카메라 궤적(예: 궤도, 돌리 움직임, 또는 엔티티 추적 움직임)과 해당 프레임 캡처 일정(프레임 캡처 스케줄)을 지정한다. 궤적이 픽셀에 베이크되는 대신 코드로 지정되므로, 물리 시뮬레이션을 변경하지 않고도 예를 들어 부드럽게 하거나 재매개화하는 등 추가 정제 작업이 가능하다. 카메라 업데이트는 시뮬레이션 타임스텝과 동기화되어 기록된 프레임이 물리적으로 일관된 시간적 진화를 반영하도록 보장한다.  
조명 (Lighting). 렌더 에이전트는 장면의 서술적 요구사항을 충족하면서 시각적 및 물리적 일관성을 유지하도록 조명을 구성한다. 렌더링 백엔드에 따라 방향광, 환경 맵, 또는 로컬 광원을 채택할 수 있다. 에이전트는 요청된 분위기나 강조를 달성하기 위해 조명 배치와 강도를 조정하며, 가시적인 광원 발광이나 일관성 없는 조명과 같은 아티팩트를 피한다. 이를 통해 생성된 장면이 의도된 조명 조건을 안정적이고 해석 가능한 방식으로 반영할 수 있다.

## 4 Experiments (실험)

### 4.1 Experimental Setup (실험 설정)

GS-Agent가 4D 물리 세계를 구축하는 능력을 체계적으로 평가하기 위해, 우리는 두 개의 평가 세트에서 실험을 수행한다. 첫 번째 세트는 NewtonGen 벤치마크 [&#91;73&#93;](#page-13-5)에서 24개의 장면으로 구성되며, 12개의 서로 다른 물리 법칙(예: 포물선 운동, 변형)을 테스트하도록 특별히 설계되었다. 우리의 방법이 열어준 새로운 기능을 평가하기 위해, 우리는 다중 객체 상호작용(예: 충돌)과 동적 카메라 제어에서 비연속적인 역학을 특징으로 하는 30개의 복잡한 장면으로 구성된 두 번째 세트를 수집했다.

Metrics. NewtonGen 벤치마크는 물리적 불변성 점수(PIS)를 보고하며, 이는 이론적으로 불변인 물리량(예: 포물선 운동 중 수직 가속도)의 상대 표준 편차를 측정한다. 원본 논문은 SAM2를 사용해 프레임마다 객체를 분할하고 중심점을 근사하여 이 계산(비디오-PIS)을 수행하지만, 우리의 에이전트-시뮬레이션 프레임워크는 보다 엄밀한 지표를 제공한다. 우리는 물리 엔진에서 매 타임스텝마다 정확한 3D 무게 중심 동역학을 직접 추출해 State-PIS를 계산한다. 이 실제 측정값은 픽셀 데이터만 출력하는 표준 텍스트-투-비디오 모델에서는 본질적으로 접근할 수 없다. 또한 Perception Encoder 특징 유사도 [&#91;7&#93;](#page-9-13)를 사용해 생성된 비디오와 텍스트 지침 간의 Alignment Score를 측정하고, VBench [&#91;27&#93;](#page-10-14)에서 제공하는 Aesthetic metric를 채택한다.

### 4.2 주요 결과 (Main Results)

기준 모델과의 비교. 정성적 비교는 Figure 3에, 정량적 결과는 Table 1에 상세히 제시된다. 전반적으로 GS-Agent는 자연어 프롬프트와 보다 충실하게 일치할 뿐만 아니라 물리적 타당성에서도 우수한 비디오를 생성한다. 텍스트-투-비디오 확산 모델은 종종 텍스트 지침을 표면적으로 따르면서 기본 물리 원칙을 위반한다. 예를 들어, 스폰지 파손 시나리오에서 이러한 모델은 갑작스럽고 비현실적인 파손 메커니즘을 환각한다. 그들의 생성 과정이 순전히 텍스트-조건화된 픽셀 분포에 의해 주도되기 때문에 시각적으로 매력적인 프레임을 제공하지만 시간적 일관성을 유지하거나 물리 법칙을 준수하지 못한다. 물방울 구체를 관통하는 총알 사례에서 Sora2는 문자 그대로이지만 물리적으로 부정확한 "cavitation trail"을 생성하고, Wan2.2는 총알이 구체를 통과하면서 실제적인 유체 분해 없이 비디오를 생성한다. 또한, 180° 카메라 회전 후에도 동일하게 남아 있는 정적 배경 침대와 같은 불일치는 실제 3D 장면 추론의 부재를 강조한다. 반면, SWE-Agent와 그 변형은 물리적으로 타당한 결과를 생성하지만 종종 텍스트 지침을 완전히 충족하지 못해 시뮬레이션 코드와 정확한 재료 매개변수, 고품질 렌더링을 동시에 구성하는 어려움을 드러낸다. 반대로 GS-Agent는 물리적 사실성, 지침 충실도, 시각적 일관성을 성공적으로 균형 있게 조화시켜 물리-인-루프, 다중 에이전트 설계를 검증한다.

**인간 평가자들은 GS-Agent를 선호한다.** 물리적 타당성[45, 75], 카메라 제어성[33], 내용 정합성에 대한 자동화된 평가는 아직도 미해결 연구 과제이다. 보다 견고한 평가를 위해 우리는 15명의 참가자를 대상으로 사용자 연구를 수행했다. 참가자들은 우리 방법과 기준 모델이 생성한 다섯 개의 무작위 순서 비디오를 5점 리커트 척도로 *물리적 타당성, 카메라 제어성, 내용 정합성*, 그리고 *미학* 측면에서 평가하도록 지시받았다. 270개의 유효 응답(표 2)을 기반으로 인간 평가자들은 물리적 타당성, 카메라 제어성, 내용 정합성 측면에서 GS-Agent가 생성한 비디오를 강하게 선호했으며, 순수 미학 측면에서는 우리 방법이 최첨단 폐쇄형 모델보다 약간 뒤처진다. 연구 프로토콜 및 인터페이스에 대한 추가 세부 사항은 부록 C.2에 제공된다.

다중 에이전트 설계의 효능. 우리는 제안한 아키텍처를 모든 도구 접근을 단일 거대 에이전트로 통합하여 제거한다. Table [4](#page-8-0) 및 Figure [6,](#page-7-1) 에서 보듯이 다중 에이전트 설계는 세계 생성 파이프라인을 전문화된 하위 작업으로 분해함으로써 현저히 우수한 성능을 달성한다. 각 에이전트를 잘 정의된 컨텍스트에 제한하면 프롬프트 산만을 줄이고 도구 오용을 최소화하여 보다 신뢰할 수 있는 추론과 실행을 이끈다. [&#91;31&#93;](#page-10-12) 의 결과와 일치하게 다중 에이전트 시스템은 논리 추론을 위한 사용 가능한 컨텍스트 창을 효과적으로 확장하여 고급 과제 해결 능력을 열어준다.

특수 에이전트-시뮬레이터 인터페이스의 중요성. 인터페이스의 영향을 고립시키기 위해 우리는 GS-Agent를 *SWE-Agent w/ Visual* 기준선과 비교한다. 일반 물리 시뮬레이터 API는 전통적으로 인간 전문가를 위해 설계되었으며, 이러한 방대한 저수준 동작 공간을 자율 에이전트에 직접 노출하면 종종 문법 오류, 치명적인 파라미터 선택, 또는 물리 엔진 충돌이 발생한다. 원시 시뮬레이터 동작을 구조화되고 의미 있는 도구로 추상화함으로써, 우리의 인터페이스는 에이전트 행동을 제한하면서도 창의적 표현력을 보존하여 안정적이고 물리적으로 정확한 세계 생성을 직접적으로 이끈다.

## 5 토론 (Discussions)

**GS-Agent는 비디오 이상의 것을 생성합니다.** 우리의 정량적 지표는 렌더링된 비디오 출력에 초점을 맞추지만, **GS-Agent**는 본질적으로 멀티모달 4D 환경을 구축합니다. 이는 메트릭 깊이 맵, 정밀한 세분화 마스크, 표면 법선, 입자 수준의 역학 등 풍부하고 정렬된 데이터 구조를 자연스럽게 제공합니다. 최종 출력이 실행 가능한 시뮬레이션 스크립트이기 때문에, 하위 강화 학습 및 평가를 위한 로봇 구현체와 원활하게 통합될 수 있습니다. 따라서 GS-Agent는 단순한 비디오 생성기가 아니라 구현된 데이터 합성을 위한 엔진으로서 역할을 합니다.

물리적 및 시간적 일관성 보장. 공간-시간 일관성을 유지하는 것은 *Genie3* [49]와 같은 대화형 세계 모델을 개발하는 데 있어 중요한 병목 현상입니다. 순수 확산 모델은 장기적으로 기하학적 일관성을 유지하는 데 어려움을 겪습니다 [64], 반면 우리의 방법론은 결정론적 물리 엔진에서 실행되는 절차적 코드에 세계 구성을 기반으로 합니다. 이 접근 방식은 기하학, 움직임, 물질 상호작용의 내부 일관성을 수학적으로 보장하여, 향후 제어 가능한 세계 모델을 위한 견고한 기반을 제공합니다.

### 5.1 한계 (Limitations)

현재 시뮬레이션 기술의 제약. 실제 세계를 정확하고 효율적으로 시뮬레이션하는 것은 여전히 개방형 과제입니다 [6]. 현대 그래픽 및 물리 시뮬레이션 알고리즘의 충실도와 확장성은 본 방법의 성능 한계를 본질적으로 제한합니다. 그럼에도 불구하고, 현재의 시뮬레이션 도구만으로도 인간은 이미 현대 게임과 영화에서 볼 수 있는 것처럼 매우 복잡한 4D 세계를 제작할 수 있으며, 이는 광범위한 수작업을 필요로 합니다. 우리의 연구는 이 과정을 자동화하고 그래픽 및 시뮬레이션의 지속적인 발전을 활용하여 확장 가능하고 물리적으로 기반이 되는 세계 생성을 위한 유망한 경로를 제시합니다 [11].

기초 모델의 시네마틱 이해 한계. 우리의 방법은 기초 모델의 자기 비판 능력, 특히 생성된 장면이 예상되는 움직임과 일관된 시네마틱 표현을 보이는지 평가하는 능력에 의존합니다. GPT-5와 같은 고급 모델은 이 분야에서 눈에 띄는 개선을 보여주었지만, 여전히 완벽에 이르지 못합니다 [29, 34]. 움직임 및 시네마틱 이해의 지속적인 진전 [45, 33]은 우리 프레임워크가 정밀하고 물리적으로 일관되며 미학적으로 풍부한 세대를 생성하는 능력을 더욱 향상시킬 것입니다.

## 6 결론 (Conclusion)

본 연구에서는 자연어로부터 동적이고 물리적으로 그럴듯한 4D 세계를 생성하기 위해 물리 엔진을 루프에 통합한 다중 에이전트 프레임워크인 GS-Agent를 제시했습니다. GS-Agent는 실행 가능한 코드로 물리 엔진과 상호작용하며, 다중 모달 피드백을 적극적으로 탐색하고 다른 에이전트와 협력하여 일관되고 제어 가능한 세계를 반복적으로 구축합니다. 실험 결과는 GS-Agent가 물리적으로 그럴듯한 세계를 생성하고 기존 방법을 넘어서는 세밀한 제어 가능성을 제공함을 입증합니다. 앞으로 우리는 이 접근법을 대규모, 대화형, 일관된 세계 시뮬레이터를 구축하기 위한 기반으로 envision하며, 생성 모델, 구현된 지능, 물리 기반 시뮬레이션 간의 격차를 해소하여 확장 가능한 멀티모달 데이터 생성과 새로운 경험 형식을 가능하게 할 것입니다.

## 더 넓은 영향 (A Broader Impact)

GS-Agent의 개발은 상당한 긍정적 잠재력을 제시하면서 중요한 윤리적 및 사회적 고려사항을 제기합니다.

콘텐츠 민주화 및 체현형 AI. 긍정적인 측면에서, 우리의 프레임워크는 복잡하고 물리적으로 기반된 4D 환경을 만드는 기술적 장벽을 크게 낮춥니다. 이로써 독립 개발자, 교육자, 게임 및 영화 산업의 창작자들에게 고품질 콘텐츠 제작을 민주화하며, 광범위한 수동 애니메이션과 전문 엔지니어링에 대한 필요성을 줄입니다. 또한, 다중 모달이며 물리적으로 정확한 합성 데이터를 생성함으로써 GS-Agent는 로봇공학 및 체현형 AI 커뮤니티에 강력한 촉매 역할을 합니다. 이것은 다양한 훈련 환경을 생성하기 위한 확장 가능한 파이프라인을 제공하며, 심‑투‑리얼 전이를 가속화하고 느리고 비용이 많이 드는 실제 데이터 수집에 대한 의존도를 줄일 수 있습니다.

Dual-Use 위험과 허위정보. 반대로, 물리학적으로 일관된 고품질 시나리오를 빠르게 생성할 수 있는 능력은 독특한 이중 사용 위험을 초래한다. 다른 고충실도 생성 모델과 마찬가지로, GS-Agent는 기만적인 콘텐츠를 합성하는 데 악용될 수 있다. 우리의 생성된 세계는 학습된 픽셀 근사치가 아니라 실제 물리 법칙에 의해 지배되기 때문에, 결과 매체는 예외적으로 신뢰성 있게 보일 수 있으며, 표준 확산 모델의 특징적인 “환각”이 없으므로 허위정보를 반박하기가 더 어려워진다. 또한 실제 세계 역학을 정확히 시뮬레이션할 수 있는 능력은 이론적으로 물리적 보안 인프라의 취약점을 시뮬레이션하는 등 악의적 계획에 악용될 수 있다.

경제적 및 환경적 고려사항. 3D 모델링, 애니메이션 및 시뮬레이션 작업의 자동화는 시각 효과 아티스트와 기술 감독의 노동 시장을 혼란시킬 수 있다. 환경적으로는 복잡한 물리 엔진과 함께 대규모 멀티모달 기초 모델을 실행하는 것이 계산 집약적이며, 상당한 탄소 발자국을 기여한다.

완화. 이러한 위험을 해결하기 위해 우리는 생성된 시뮬레이션 코드와 렌더링된 프레임 모두에 암호학적 워터마크를 삽입하는 등 견고한 디지털 출처 추적 기술의 통합을 옹호한다. 또한 기초 모델 백본 내부에서 악의적 시뮬레이션 요청을 거부하도록 엄격한 안전 가드레일의 중요성을 강조한다. 우리는 커뮤니티가 투명성과 공개 안전 평가를 우선시하며 책임감 있게 인터랙티브 세계 생성 기술을 배포하도록 권장한다.

### B.1 에이전트-시뮬레이션 인터페이스

대부분의 기존 시뮬레이션 API는 인간 전문가를 위해 설계되었으며, 기초 에이전트용이 아니다. 이 격차를 메우기 위해 우리는 에이전트가 물리 시뮬레이터와 신뢰성 있고 유연하게 상호작용할 수 있도록 의미론적으로 구조화된 인터페이스를 도입한다. Figure [2,](#page-3-0)에서 보듯이 각 에이전트는 책임에 맞게 맞춤화된 도구 상자와 모든 에이전트가 접근할 수 있는 공유 일반 도구 세트를 갖추고 있다. Table [5](#page-15-0)은 전체 인터페이스를 요약한다.

일반 도구. 일반 도구 상자에는 모든 에이전트가 공유하는 필수 기능을 지원하는 세 가지 도구가 포함되어 있다: 시뮬레이션에서 정보를 검색하고 다른 에이전트와 통신한다.

매니저 에이전트의 도구. 매니저 에이전트는 두 가지 범주의 도구를 사용한다. 첫 번째는 전역 시뮬레이션 및 시각화 옵션을 구성하고, 두 번째는 시뮬레이션의 시간 진행을 제어한다. 모든 구성 도구는 신뢰성 있는 파싱 및 실행을 보장하기 위해 엄격하고 구조화된 형식으로 선택적 매개변수를 허용한다.

엔티티 에이전트의 도구. 엔티티 에이전트의 도구는 가장 표현력이 풍부하다. 각 도구는 <name>이라는 엔티티 또는 방출기를 식별하고, <code>에 정확한 기하학, 물리학 또는 제어 논리를 포함하는 두 개의 필수 인수를만 허용한다. 이 설계는 통합된 인터페이스 내에서 상세한 계산과 세밀한 조작을 가능하게 한다. 우리는 도구 설명 내에서 자세한 함수 설명과 시연을 제공한다.

렌더 에이전트의 도구. 렌더 에이전트의 도구 상자에는 현재 카메라 및 조명 구성을 쿼리하고, 카메라 모델, 렌더링 방법 및 여러 조명 유형을 엄격한 매개변수 형식으로 지정하는 도구가 포함된다. 에이전트는 또한 현재 프레임을 시각적 디버깅을 위해 렌더링하고, <code>-기반 제어 도구를 통해 유연한 카메라 움직임 및 비디오 기록 논리를 정의할 수 있다.

- 물리적 타당성: 움직임과 상호작용은 물리 법칙과 연속성을 존중해야 하며, 재료는 일관성을 유지해야 합니다 (고체/연성/탄성/액체); 순간이동/스냅핑이 없어야 하고, 에너지/물질은 보존되어야 합니다 (갑작스러운 등장/소멸/병합 없음); 액체는 흐름/스플래시/산란이 일관되게 동작해야 하며, 힘은 비례적 반응을 일으켜야 합니다 (과장되거나 과도하게 감쇠된 반응 없음).
- 카메라 제어성: 카메라는 프롬프트를 따라야 하며 안정적이어야 합니다 (프레이밍, 부드러운 팬/틸트/줌/돌리기, 합리적 속도) 그리고 흔들림, 노출 깜빡임, 클리핑, 무작위 타깃 전환이 없어야 합니다. 프롬프트가 특정 카메라 움직임을 요청하고 비디오에 없으면 감점(점수 낮춤)합니다.
- 콘텐츠 정합성: 비디오가 텍스트 프롬프트와 얼마나 잘 일치하는가 (정확한 객체, 동작, 장면, 그리고 묘사된 스타일).
- 미학: 전반적인 시각적 품질과 매력—구도, 선명도, 조명/그림자, 색상/대비, 그리고 방해가 되는 아티팩트(노이즈, 밴딩, 과도한 흐림/깜빡임, 시간적 결함)의 부재.

## C.3 실패 분석 (Failure Analysis)

자기 비판에서의 컨텍스트 오염. 현재의 기초 모델은 여전히 강력한 동작 및 시네마틱 이해가 부족하다. 중간 렌더링된 비디오를 평가할 때, 에이전트는 때때로 “컨텍스트 오염” 때문에 자기 비판을 정확히 수행하지 못한다. 에이전트의 컨텍스트 창에 비디오가 어떻게 보여야 하는지에 대한 긴, 상세한 계획이 포함되어 있기 때문에, 가끔은 확인 편향을 보이며 최종 렌더링 결과가 계획을 성공적으로 실행했다고 스스로 확신하지만 실제 시각적 내용을 비판적으로 평가하지 않는다.

실패의 잘못된 귀인. 시뮬레이션이나 시각적 검사가 실패할 때, 에이전트는 때때로 불일치의 근본 원인을 잘못 진단한다. 이는 에이전트가 완전히 잘못된 시뮬레이션 매개변수를 지속적으로 조정하여 예상되는 물리적 결과를 달성하려고 시도하는 반복 루프에 빠지게 만들 수 있다 (예: 실제 실패가 초기 공간 속도의 부정확성에서 비롯되었음에도 불구하고 재료 마찰을 반복적으로 조정함).

존재하지 않는 규칙의 환각. 에이전트는 가끔 물리 엔진 API, 지원되지 않는 재료 속성, 또는 실제 백엔드 인터페이스에 존재하지 않는 물리 시뮬레이션 규칙을 환각한다. 이로 인해 실행 오류가 발생하며, 이를 해결하기 위해 여러 번의 대체 시도가 필요하다.

리스트 1: 매니저 에이전트용 시스템 프롬프트.

<span id="page-19-0"></span>당신은 매니저 에이전트이며, Genesis Physics Engine과 자산 라이브러리를 사용해 자연어 지침을 물리적으로 그리고 시각적으로 사실적인 동적 세계로 변환하는 고도로 발전된 AI 에이전트입니다. 당신은 두 명의 협력자를 보유하고 있습니다: 엔티티 에이전트와 렌더 에이전트. 엔티티 에이전트는 현실적인 자산을 검색하고, 한 번에 하나의 엔티티를 생성 및 관리하며, 엔티티 움직임을 제어하는 데 특화되어 있습니다. 렌더 에이전트는 카메라, 조명 및 렌더러 설정을 구성하고, 카메라 움직임, 렌더 빈도 및 비디오 녹화 타이밍을 제어하는 책임이 있습니다.

사용자의 지침을 바탕으로 물리적 타당성과 시각적 사실성을 모두 보장하도록 각 단계를 신중히 계획하십시오. 작업을 명확하고 관리 가능한 과제로 나누고, 협력자에게 한 번에 하나씩 할당하십시오. 지침은 과도한 세부 사항 없이 정확하고 간결하게 유지하고, 그들의 출력을 비판적으로 검증하며, 결과가 기대에 부합할 때까지 반복하십시오. 협력자에게 과제를 할당하고 출력을 검증하는 것 외에도, 솔버 및 시각화 매개변수를 포함한 장면 옵션을 구성하고, 계획과 협력자의 피드백에 따라 장면을 진행 및 재설정하는 책임이 있습니다. 완전한 동적 물리 세계를 구축하고 최종 비디오를 렌더링할 때까지 계속 진행하며, 불확실성 때문에 일찍 중단하거나 반환하지 마십시오. 필요하다면 합리적인 가정을 하고, 이후에 문서화하십시오.

#### Reminders:

- Genesis Physics Engine에는 두 개의 렌더러가 있습니다: 빠른 Rasterizer와 고품질 RayTracer. 기본적으로 사용되는 Rasterizer는 실시간 렌더링과 빠른 미리보기에 적합하며, RayTracer는 보다 현실적인 조명과 그림자를 제공하지만 느리므로 최종 결과에만 사용해야 합니다.  
- 서로 다른 렌더러는 서로 다른 조명 옵션을 지원합니다. Rasterizer는 DirectionalLight만 구성할 수 있고, RayTracer는 SphereLight와 EnvSphere만 구성할 수 있습니다. 렌더러를 구성하면 모든 조명이 초기화됩니다.  
  - **DirectionalLight**는 무한히 멀리 있는 것처럼 행동하며 지정된 방향으로 지정된 색상과 강도로 빛을 방출하는 조명 소스입니다.  
  - **SphereLight**는 구형 메쉬 조명으로, 장면 어디에든 배치할 수 있으며 위치, 반경, 색상, 강도를 가집니다. 포인트 라이트는 적절한 반경과 강도를 가진 SphereLight로 시뮬레이션할 수 있으며, 방향성 라이트는 매우 큰 반경과 강도를 가진 무한대의 SphereLight로 시뮬레이션할 수 있습니다. SphereLight는 장면에 보이므로 렌더링된 이미지나 비디오의 외관에 영향을 줄 수 있습니다. SphereLight를 장면의 주요 피사체를 가리지 않도록 배치하고 카메라 시야 밖에 두도록 하세요.  
  - **EnvSphere**는 hdri/exr 이미지 텍스처가 적용된 구형으로, 전체 장면에 주변 조명을 제공합니다. 위치, 반경, 색상, 강도를 가집니다. 일반적으로 장면에 기본 조명 수준을 제공하는 데 사용됩니다.  
- 장면에 없거나 아직 생성되지 않은 엔티티를 렌더링할 수 없습니다. 항상 `get_scene_info`를 호출하여 존재하는 엔티티를 확인하고, 렌더링 전에 `get_entity_info`를 호출하여 관심 있는 엔티티에 대한 정보를 얻으세요.  
- 비디오를 직접 렌더링할 수 없습니다. 대신 `configure_camera_control` 도구를 사용하여 카메라 움직임과 녹화 타이밍을 설정하고, Manager Agent가 장면을 진행할 때 비디오를 렌더링하도록 하세요.  
- Genesis Physics Engine의 좌표계를 항상 엄격히 따라야 합니다. 다른 3D, 그래픽스, 물리 엔진의 관례를 가정하지 마세요. 공간 방향(예: '앞쪽', '오른쪽에서 바라보기' 등)을 해석할 때는 항상 Genesis 좌표계에 매핑하세요:  
  - **원점:** 세계 중심 ([0, 0, 0])  
  - **양의 x축:** 전방  
  - **양의 y축:** 오른쪽  
  - **양의 z축:** 위쪽

- 공간 언어(예: “앞에”, “오른쪽에서”, “위에”)가 포함된 사용자 요청의 경우, 사용자가 어떤 축을 올바르게 사용한다고 언급했더라도 “공간 번역” 단계를 먼저 수행한 뒤 최종 명령을 생성해야 합니다.  
- 카메라 뷰 지시사항:  
  - “앞에서 보기” : 카메라가 +X 위치에 있으며, 음의 x축을 바라봅니다.  
  - “뒤에서 보기” : 카메라가 -X 위치에 있으며, 양의 x축을 바라봅니다.  
  - “오른쪽에서 보기” : 카메라가 +Y 위치에 있으며, 음의 y축을 바라봅니다.  
  - “왼쪽에서 보기” : 카메라가 -Y 위치에 있으며, 양의 y축을 바라봅니다.  
- “위에서 보기/위에” : 카메라가 +Z 위치에 있으며, 음의 z축을 바라봅니다.  
- 지시가 명확하지 않거나 추가 정보가 필요하면, 지시를 준 사람에게만 메시지를 보내서 명확히 하세요. 다른 동료를 포함시키지 마세요.  
- 사용 가능한 도구를 활용해 카메라를 조작하고, 조명을 구성하며, Genesis Physics Engine에서 이미지를 렌더링하세요.  
- 기본적으로 엔티티의 세부 사항을 포착하기 위해 클로즈업 카메라 위치를 사용하세요. 지시가 다른 카메라 위치를 명시하면 그에 맞게 조정하세요.  
- 렌더링 결과를 분석한 뒤, 지시사항에 명시된 요구사항을 충족하는지 확인하세요. 만족하지 않으면 카메라 설정이나 렌더링 매개변수를 조정하고 재렌더링하세요. 그 후 ‘send_message’ 도구를 사용해 렌더링된 출력과 함께 완료를 확인하세요.  
- 렌더링 결과를 가정하거나 허구를 만들어서는 안 됩니다. 실제 결과를 검토하지 않고는 결론을 내리지 마세요.  
- 렌더링 결과가 기대와 일치하지 않으면, 무엇이 잘못됐는지 반성하고 카메라 설정이나 렌더링 매개변수를 조정한 뒤 필요하면 재렌더링하세요.  
- 비디오의 재생 빈도와 fps를 정렬해 비디오 길이가 시뮬레이션의 실제 지속 시간과 일치하도록 하세요.  
- 실패가 발생했을 때 문제를 명확히 드러내도록 설계하고, 방어적 코드보다 유익한 코드를 선호하세요.  
- 새로운 작업 지시를 받기 전에 ‘send_message’ 도구를 사용해 호출자에게 답변해야 합니다.
