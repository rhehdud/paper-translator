#### 초록 (Abstract)

최근 AI 에이전트의 발전은 그들의 기초 모델에 네이티브 기능을 점점 더 내부화하여 멀티모달 기초 모델과 대규모 추론 모델을 탄생시켰다. 그러나 에이전트 메모리는 여전히 주로 외부 모듈을 통해 구현되어 네이티브 메모리 기능이 크게 탐구되지 않았다. 본 논문에서는 메모리 기초 모델을 도입함으로써 기초 모델에 네이티브 메모리 기능을 부여하여 이 방향으로 첫 번째 단계를 제시한다. 우리는 네이티브 메모리를 두 관점에서 공식화한다: 백본 내부에서 지속적이고 동적으로 진화하는 메모리 상태, 그리고 모델 계산을 통해 자율적으로 정보를 저장하고 활용하는 네이티브 메모리 절차. 우리는 네이티브 메모리가 아키텍처, 엔드‑투‑엔드 최적화, 효율성 측면에서 이점을 제공함을 보여준다. 이 공식화에 기반하여 우리는 메모리 기초 모델의 첫 번째 프로토타입인 Metis를 제안한다. Metis는 기초 모델에 네이티브 메모리 상태를 갖춘 새로운 아키텍처를 도입하여 과거 정보를 모델에 압축하고 메모리 어텐션을 통해 접근할 수 있게 한다. 우리는 대규모 메모리 전용 훈련 데이터를 구축하고 중간 훈련을 통해 이러한 네이티브 메모리 절차를 획득하기 위한 다중 최적화 목표를 도입한다. Metis의 온라인 메모리 유지 관리는 그래디언트가 필요 없으며, 메모리 업데이트는 오직 순방향 패스만으로 수행된다. 추론 시에는 모든 학습된 모델 가중치가 고정되고, 네이티브 메모리 상태는 표준 순방향 계산을 통해 자율적으로 변환된다. 광범위한 실험을 통해 Metis가 네이티브 메모리 기능을 갖추었음을 입증하고, 그 강점, 한계 및 동작에 대한 상세 분석을 제공한다. 메모리 기초 모델에 대한 향후 연구를 촉진하기 위해 우리는 프로젝트와 모델 체크포인트를 공개한다.

## 1 서론 (Introduction)

최근 대규모 기초 모델은 급속한 발전을 이루었으며, 언어 모델링[1, 2], 코드 생성[3–5], 복잡한 추론[6–8] 등 다양한 측면에서 뛰어난 성능을 보여준다. 이는 AI 에이전트를 구축하기 위한 견고한 기반을 제공하며, 에이전트가 보다 복잡한 작업을 수행할 수 있게 한다. 기초 모델의 추론 능력 외에도 메모리는 과거 정보를 보존하고 이를 활용해 미래 추론을 지원하는 AI 에이전트의 또 다른 핵심 기능이다[9, 10]. 대부분의 기존 연구에서 메모리는

기초 모델 외부의 모듈을 통해 구현되며, 그들의 아키텍처에 네이티브로 통합되지 않는다[11–14]. 대표적인 접근법으로는 Retrieval-Augmented Generation(RAG)을 사용하여 관련 텍스트 정보를 검색하고 이를 프롬프트에 통합하여 추론을 촉진한다[11].

그러나 외부 메모리는 Figure 1에 제시된 여러 한계를 갖는다. 첫째, 외부 메모리는 백본과 분리된 목표와 처리 단계[11, 13]로 인해 분리된다. 외부 메모리는 일반적으로 입력으로서 유익한 컨텍스트를 구성하는 것을 목표로 하며, 백본은 구성된 컨텍스트에 대해 조건부 언어 모델링만 수행한다. 따라서 외부 메모리는 백본 추론을 지원하는 데 가장 유용한 정보를 제공하지 못할 수 있으며, 백본은 메모리를 최적으로 활용하지 못할 수 있다. 둘째, 외부 메모리는 그라디언트가 이산 메모리 연산을 통해 효과적으로 전달될 수 없기 때문에 엔드‑투‑엔드 최적화가 어렵다[15]. 그 결과 도메인‑특정 사후 훈련을 수행하는 것이 매우 어려워진다. 일부 RL 기반 전략[16, 17]은 보상 신호를 통해 메모리 연산을 최적화함으로써 이 문제를 부분적으로 완화할 수 있지만, 효율성 문제에 시달린다. 마지막으로, 외부 메모리는 백본 외부 저장소에 대한 추가 명시적 연산을 필요로 하므로 온라인 추론 지연을 불가피하게 증가시킨다[9].

외부 메모리의 한계를 해결하기 위해, 우리는 대형 기초 모델에 **native memory**를 부여하는 **memory foundation models**를 도입한다. 이는 메모리를 외부 모듈에서 백본의 내부 메커니즘으로 변환하여 순방향 계산에 직접 참여하도록 한다. 구체적으로, memory foundation models는 입력 지시와 그들의 native memory를 기반으로 자율적인 메모리 변환을 통해 응답을 생성할 수 있다. 우리는 native memory를 두 가지 핵심 측면에서 정의한다:

- **네이티브 메모리 상태.** 전통적인 대형 기초 모델과 달리, memory foundation models는 여러 추론에 걸쳐 네이티브하게 상태를 유지하며, 이전 추론에서 백본 내부에 메모리 상태를 형성, 유지 및 활용할 수 있다. 이들의 메모리 상태는 백본 파라미터의 일부로 동적으로 표현되며, 그 의미 공간은 사전 훈련 또는 중간 훈련 단계에서 정렬된다.

- **네이티브 메모리 절차.** 메모리 엔지니어링과 달리, memory foundation models는 추론 과정에서 네이티브하게 메모리 절차를 통합한다. 기억, 망각, 업데이트와 같은 특정 메모리 연산은 백본의 순방향 계산과 함께 자율적으로 수행되며, 입력 지시에 따라 네이티브 메모리 상태에 영향을 미친다.

Memory foundation models는 메모리 기능을 모델의 순방향 계산에 내부화하려 한다. 메모리 상태는 백본의 동적 파라미터로 표현될 수 있고, 메모리 절차는 계산을 통해 실행된다. 따라서 일반 기초 모델과 마찬가지로, memory foundation models는 사후 훈련을 통해 데이터 기반으로 특정 도메인에 최적화 및 적응이 가능하다. 이 변환은 대형 기초 모델에서 대형 추론 모델로의 진화와 유사하며, Chain-of-Thought (CoT) [7]가 성능과 효율성을 향상시키기 위해 추론에 네이티브하게 통합된 사례이다. 또한, native memory 절차가 모델 계산에 통합될 수 있기 때문에 메모리 처리의 병렬 효율성을 개선하는 기반을 제공한다.

본 논문에서는 메모리 기반 모델의 최초 프로토타입인 Metis를 구현한다. 우리는 Fast Weight Programming (FWP) [18]에서 영감을 받아 본질적 메모리 상태를 갖는 새로운 모델 아키텍처를 설계하였다. 이 아키텍처는 메모리 어텐션을 통해 백본 연산에 통합될 수 있다. 구체적으로, 우리는 Metis 블록을 본질적 메모리의 기본 단위로 제안한다. 각 블록은 주로 하이퍼 메모리 블록과 로컬 메모리 블록으로 구성된다. 또한, 메모리 재구성 및 메모리 연산 목표를 포함한 특정 최적화 목표를 설계함으로써 Metis에 본질적 메모리 절차를 부여한다. 이 두 목표는 메모리 상태의 압축 상한과 연산 목표에 해당한다. 우리는 또한 복잡한 시나리오에서 견고성을 향상시키기 위해 정규화 목표를 설계한다. 이 학습을 지원하기 위해 공개 데이터셋에서 대규모 메모리 전용 데이터를 합성하여, Metis가 중간 학습을 통해 본질적 메모리 기능을 습득하도록 한다. 마지막으로, 우리는 제안한 프레임워크의 효과를 입증하고 분석을 위한 추가 측면을 탐구하기 위해 광범위한 실험을 수행한다.

일반적인 관점에서 메모리의 근본적인 문제는 온라인 정보의 시간 스트리밍 특성에서 비롯된다. 저장 단계에서 메모리 시스템은 수신된 정보가 미래에 어떻게 사용될지 판단할 수 없다. 추론 단계에서는 원본 정보가 더 이상 접근할 수 없으며, 저장된 정보만 활용된다. 따라서 메모리는 수신된 정보가 미래에 어떻게 활용될지를 모델이 예측하는 예측 문제로 볼 수 있다. 머신러닝의 다른 예측 과제와 마찬가지로, 메모리 역량은 사전 학습 단계에서 획득하고 다른 도메인으로 일반화될 수 있으며, 메모리 기반 모델은 아키텍처와 최적화 기반을 제공할 수 있다.

그들의 유망한 특성에도 불구하고, 메모리 기반 모델을 구현하는 것은 여전히 매우 어려운 과제이다. 이는 최종 목표가 문맥에서 외부 메모리에 대한 의존을 완전히 제거하는 데 있기 때문이다. Metis는 메모리 관련 과제에서 뛰어난 성능을 보이지만, 여전히 몇 가지 한계를 갖는다. 첫째, 고정 크기 파라미터에 압축될 때 정보 손실이 발생해 장기 과제에서 성능이 저하된다. 둘째, 잠재 공간 내에서 의미가 혼합되어 일부 경우에 정보 혼란이 나타난다. 이러한 한계에도 불구하고 Metis는 메모리 기반 모델을 달성하기 위한 잠재적 경로를 제공한다. 연구 커뮤니티와 산업계 모두에게 이익이 되도록, 우리는 프로젝트를 <a href="https://github.com/MemTensor/Metis">https://github.com/MemTensor/Metis</a>에 공개한다.

우리의 기여는 다음과 같이 요약된다:

- 우리는 메모리 기초 모델과 네이티브 메모리를 공식 정의와 함께 도입하며, 네이티브 메모리 상태와 네이티브 메모리 절차의 관점에서 추가 분석을 제공한다.
- 우리는 메모리 기초 모델의 최초 프로토타입인 Metis를 제안하며, 이는 새로운 메모리 아키텍처와 최적화 과제를 구현한다.
- 우리는 모델의 효과를 검증하기 위해 광범위한 실험을 수행하고, 다각적 관점에서 상세한 연구를 진행한다. 또한 연구 커뮤니티와 산업에 이익이 되도록 프로젝트를 공개한다.

본 논문의 나머지 구성은 다음과 같다. 2장은 메모리 기초 모델의 공식 정의를 제공한다. 3장은 Metis의 모델 아키텍처를 상세히 설명한다. 이후 4장에서는 데이터 구축 파이프라인을 소개하고 5장에서는 최적화 과정을 개요한다. 6장에서는 광범위한 실험 결과와 분석을 제시한다. 마지막으로 7장에서는 관련 연구를 검토하고 8장에서는 결론을 제시한다.

## <span id="page-2-0"></span>2 메모리 기초 모델 (Memory Foundation Model)

본 장에서는 메모리 기반 모델의 공식 정의를 제시한다. 이후, 네이티브 메모리를 네이티브 메모리 상태와 절차의 관점에서 소개한다. 그 다음, 메모리 기반 모델을 기존 연구와 비교한다. 마지막으로, 메모리 기반 모델을 평생 학습과 AI 에이전트의 진화 추세의 관점에서 추가적으로 논의한다.

### 2.1 정의 (Definition)

우리는 다단계 시나리오에서 메모리 기반 모델을 정의한다. 연속적인 상호작용 과정을 이산 시간 단계의 시퀀스로 공식화한다, $t \in \{1, 2, ..., T\}$ . 각 단계 t에서, 기반 모델은 입력 지시 시퀀스 $X_t$ 를 받고, 응답 시퀀스 $Y_t$ 를 생성한다.

전통적인 메모리 없는 기반 모델의 경우, 생성은 현재 입력 컨텍스트에 전적으로 의존한다. 응답에서 k번째 토큰의 자기회귀 디코딩은 일반적으로 $y_{t,k} \sim P(y \mid X_t, Y_{t,< k}; \theta)$ 로 표현되며, 여기서 $Y_{t,< k}$ 는 단계 t에서 이전에 생성된 토큰들을 나타내고, $\theta$ 는 백본의 고정 파라미터를 나타낸다. For

외부 메모리를 갖는 기반 모델의 경우, 자기회귀 디코딩 과정은 입력 지시와 함께 컨텍스트 $C_t$ 에 조건화된다. 이는 $y_{t,k} \sim P(y \mid C_t, X_t, Y_{t,< k}; \theta)$ 로 표현될 수 있으며, 여기서 $C_t$ 는 이전 정보 $\{(X_i, Y_t)\}_{i=1}^{t-1}$ 에서 얻을 수 있다. 외부 메모리 프레임워크는 일반적으로 저장 절차 $C_t = C_{t-1} \oplus \{(X_t, Y_t)\}$ 와 검색 절차 $C_t = C_{t-1} \otimes X_t$ 두 가지 명시적 절차를 갖는다. 여기서 $\oplus$ 는 일반적인 쓰기 연산을, $\otimes$ 는 텍스트 메모리 저장소 $C_{t-1}$ 에 대한 일반적인 읽기 연산을 나타낸다. 이 두 절차는 모델 추론 과정 외부에서 실행된다.

**정의 1** (Memory Foundation Model). 메모리 기반 모델은 다단계 상호작용에서 **네이티브 메모리** 로 강화된 자기회귀 기반 모델로 정의된다. 각 단계 t에서, k번째 토큰의 생성은 입력 지시 $X_t$ 와 이전에 생성된 토큰 $Y_{t, < k}$ 에 조건화된다.

$$y_{t,k} \sim P(y \mid X_t, Y_{t, < k}; \theta_t),$$

여기서 모델 파라미터 $\theta_t$ 는 이전 단계의 정보를 네이티브 파라미터 공간(즉, 네이티브 메모리 상태)에 통합한다. 동시에 $\theta_{t+1}$ 은 입력 지시 $X_t$ 와 출력 $Y_t$ 를 기반으로 모델 내부의 순방향 계산 중 자율적으로 변형된다(즉, 네이티브 메모리 절차).

반대로, 메모리 기반 모델은 메모리를 백본의 계산에 내부화하며, 이는 네이티브 메모리로 강화된다. 외부 명시적 저장소 $C_t$ 와 컨텍스트 $C_t$ 에 의존하는 대신, 네이티브 메모리 상태를 유지하며 이는 여러 단계에 걸쳐 동적 파라미터로 작용한다. 또한, 백본 외부에서 메모리 절차를 명시적으로 실행하는 대신, 메모리 기반 모델의 메모리 절차는 모델의 순방향 계산과 함께 자율적으로 발생한다. 예를 들어, 기억, 망각, 업데이트와 같은 연산이 있다.

### 2.2 네이티브 메모리 상태 (Native Memory State)

본 논문에서는 메모리의 출처에 대해 엄격한 정의를 채택한다. 우리는 온라인 상호작용 중에 획득한 정보만을 메모리로 간주하며, 상호작용이 시작되기 전에 이용 가능한 정보는 제외한다. 실제로, 이러한 오프라인 정보는 개인화에 필요한 경로별 특수 정보를 포함하지 않으며 실시간 적응을 요구하지 않으므로, 메모리보다는 지식으로 보는 것이 더 적절하다.

저장된 정보가 단계마다 다르기 때문에 파라미터 $\theta_t$는 완전히 정적일 수 없다. 따라서 파라미터의 일부는 입력에 따라 동적으로 변해야 하며, 이 동적 부분을 메모리 상태 $\mathbf{M}_t$라 부른다. 메모리 기반 모델에서는 저장된 정보의 표현이 백본과 결합되어 순방향 계산에 참여해야 한다. 따라서 네이티브 메모리 상태는 파라미터 형태로 표현되어야 한다. 텍스트 메모리는 해석 가능성과 모델 간 호환성에서 장점을 제공하지만, 이의 이산적 표현은 정보 밀도가 낮고 반복적인 사전 채우기를 필요로 한다. 반면 파라미터 메모리는 사전 정보를 밀집 형태로 표현하여 저장 및 활용 효율을 높인다.

또한, 동적 파라미터 $\mathbf{M}_t$와 정적 파라미터 $\mathbf{\Phi} = \theta_t \setminus \mathbf{M}_t$의 의미 공간은 온라인 추론을 수행하기 전 사전 훈련 또는 중간 훈련 단계에서 정렬되어야 한다. 이 정렬은 서로 다른 단계의 동적 파라미터가 정적 파라미터와 협업하여 계산할 수 있게 한다. 온라인 상호작용 중에는 네이티브 메모리 절차를 통해 네이티브 메모리 상태를 업데이트하고 활용할 수 있어, 메모리 기반 모델이 단계마다 상태를 유지하도록 한다.

### <span id="page-3-0"></span>2.3 네이티브 메모리 절차 (Native Memory Procedure)

메모리 관점에서 저장과 활용은 시간 스트리밍 특성을 가진 온라인 정보를 처리하기 위한 두 가지 핵심 절차이다. 메모리 저장은 과거 정보를 보존하고, 메모리 활용은 이 저장된 정보를 활용해 모델 추론을 지원한다. 이들은 정보 공급과 사용 사이의 시간적 불일치를 해결하려는 목적을 가진다.

메모리 저장 절차는 일반적으로 기억, 망각, 업데이트와 같은 여러 구체적 연산을 포함한다. 기초 모델 관점에서 입력 지시는 정보 처리의 의도와 내용을 모두 담고 있다. 예를 들어, "Alice는 24세이다"는 그녀의 나이를 기억한다는 의미이고, "Bob은 런던에서 보스턴으로 이사했다"는 그의 위치를 업데이트한다는 의미이다. 네이티브 저장 절차는 입력 지시를 메모리 상태의 업데이트 값에 직접 매핑해야 한다. 반대로 외부 메모리는 의도와 내용을 별도로 처리하기 위해 규칙 기반 및 사전 정의된 연산에 의존한다. 대부분의 연산은 삽입, 삭제, 수정으로 분류될 수 있지만, 의미적 의도와 내용은 이산 규칙으로 쉽게 분리될 수 없다. 실제로 저장 절차는

본질적으로 현재 정보가 미래에 어떻게 사용될지를 예측한다. 규칙 기반 절차는 이산 함수 공간에서 작동하기 때문에 최적의 예측 성능을 달성하기 어렵다.

메모리 활용 절차의 주요 목표는 저장된 정보를 활용해 추론을 지원하는 것이다. 기초 모델 관점에서 이는 입력 지시가 요구하는 정보를 순방향 계산에 참여시키는 것으로 볼 수 있다. 예를 들어, *"Bob은 지금 어디에 사는가?"*에 답하려면 이전에 저장된 거주 정보를 활용해야 한다. 따라서 네이티브 메모리 활용 절차는 입력 지시와 메모리 상태를 직접적으로 생성된 출력에 매핑해야 한다. 외부 메모리는 검색, 재정렬, 연결을 트리거하는 규칙을 설계한다. 그러나 정보 요구는 이산적이고 유한한 규칙으로 정의·포착할 수 없다. 예를 들어, 지시는 의미적 유사성, 감정, 혹은 암시적 지표의 복합 조합에 기반한 정보를 요구할 수 있다. 메모리 활용 절차는 정보 요구를 예측하며, 이는 추론 과정과 결합된다. 따라서 이 절차는 이산 함수 공간에 의해 제한된 이산 단계로 나누어져서는 안 된다.

Consequently, 메모리 절차는 연속 함수 공간 내에서 모델링되고 수치 계산을 통해 구현되어야 하며, 이는 백본의 순방향 계산과 밀접하게 결합된다. 메모리 기반 모델에서는 네이티브 메모리 절차가 순방향 계산 중에 메모리 저장과 활용을 자율적으로 수행한다. 이 네이티브 메모리 절차는 사전 훈련 또는 중간 훈련 단계에서 구축되어야 한다. 또한, 이 메모리 절차 패러다임은 효율성과 엔드-투-엔드 최적화 모두에서 상당한 이점을 갖는다.

### 2.4 이전 연구와의 비교 (Comparison with Previous Works)

테스트 타임 트레이닝(Test-time Training, TTT). 메모리 기반 모델은 테스트 타임 트레이닝과 세 가지 핵심 측면에서 차이가 있다. 첫째, TTT는 일반적으로 단일 시퀀스 내에서 모델을 적응시키며, 동적 파라미터가 현재 입력에 더 잘 맞도록 업데이트된다. 반면, 메모리 기반 모델은 다단계 상호작용 하에 정의된다. 그들의 동적 파라미터는 이전 단계에서 정보를 저장하고 향후 추론을 지원하는 지속적인 네이티브 메모리 상태로 기능한다.

둘째, TTT는 명시적으로 네이티브 메모리 절차를 제공하지 않는다. 그 업데이트는 일반적으로 자기 지도 언어 모델링에 의해 주도되며, 이는 모델이 현재 시퀀스 내에서 이전 정보를 흡수하도록 돕는다. 그러나 입력 지침에 따라 모델이 어떻게 의미적으로 기억하고, 잊고, 업데이트하고, 정보를 반영해야 하는지 명시하지 않는다. 반면, 메모리 기반 모델은 메모리 재구성 및 운영 목표를 가지고 훈련되어, 잠재적 파라미터 공간에서 의미적 메모리 연산을 자율적으로 수행하고 네이티브 메모리 상태를 이에 따라 변형시킬 수 있다.

셋째, 많은 TTT 방법은 효율적인 장기 컨텍스트 모델링을 동기로 하며, 종종 전체 어텐션을 대체하기 위해 순환 층을 도입한다. 그러나 메모리 기반 모델은 다른 목표를 추구한다. 그들은 현재 단계 내에서 표준 전체 어텐션 계산을 대체하려는 것이 아니다. 대신, 이전 상호작용 단계의 정보를 네이티브 메모리 상태를 통해 잔차로 도입한다.

요약하면, TTT는 주로 추론 시 적응 메커니즘이며, 메모리 기반 모델은 메모리를 지속적이고, 지시 기반이며, 절차 인식 능력으로 공식화한다.

메모리 증강 신경망(Memory-Augmented Neural Networks, MANNs). 메모리 증강 신경망은 가변 메모리 슬롯과 학습된 읽기-쓰기 연산 등과 같은 추가 메모리 모듈을 신경망 모델에 도입한다 [19](#page-27-7). 이러한 모델은 신경망이 외부 정보를 저장하고 이후 계산에 이를 검색할 수 있음을 보여준다. 그러나 메모리 기반 모델은 메모리가 백본과 통합되는 방식에서 차이가 있다. MANNs에서는 메모리 모듈이 일반적으로 신경 컨트롤러에 의해 제어되는 별도의 저장소 구성요소이다. 연산은 가변적일 수 있지만, 메모리는 여전히 주요 모델 파라미터와는 독립적으로 설계되는 경우가 많아 백본과는 별개이다.

반면, 메모리 기반 모델은 메모리를 백본 계산에 내부화한다. 메모리 상태는 파라미터 형태로 표현되며 순방향 계산에 직접 참여한다. 메모리 절차는 명시적 슬롯 위에 별도의 컨트롤러로 구현되는 대신, 백본과 동일한 연속 함수 공간으로 모델링된다. 따라서 메모리 기반 모델은 외부 증강 메모리에서 메모리 기반 모델 내부의 네이티브 메모리로의 전환 단계로 간주될 수 있다.

기타 방법. In-place TTT[20], MemGen[21] 및 -Mem[22]와 비교하면, 이들은 여전히 문맥에서 텍스트 메모리에 의존하고 추가 잠재 요약을 사용해 추론을 개선한다. 반면 메모리 기반 모델은 문맥에서 텍스트 메모리를 완전히 제거한다. MEMO[23]와 MemFT[24]와 비교하면, 이들은 주로 오프라인 문서를 다루는 반면 메모리 기반 모델은 테스트 시점 정보를 중심으로 한다. Memory<sup>3</sup>[25]와 비교하면, 이 모델은 텍스트 RAG를 넘어 지식을 검색 가능한 명시적 메모리로 인코딩하는 중요한 단계를 거친다. 메모리 기반 모델은 이 방향을 네이티브 메모리로 더욱 확장한다. Memory<sup>3</sup>는 주로 오프라인 코퍼스에서 명시적 메모리를 구축하고 이를 활용해 어텐션 계산을 보강하지만, 메모리 기반 모델은 온라인 상호작용에서 획득한 정보를 백본 내 지속적인 동적 상태로 내부화한다. 또한 이러한 상태를 네이티브 메모리 절차를 통해 여러 상호작용 단계에서 자율적으로 유지·변환할 수 있도록 한다.

### 2.5 논의 (Discussion)

메모리 기반 모델(memory foundation models)에서 상호작용의 시작(onset of interaction)은 정적 지식 획득에서 동적 지식 획득으로의 전환(static to dynamic knowledge acquisition)을 나타낸다. 상호작용 이전에 획득된 지식은 오프라인 사전 훈련(offline pre-training)에서 유래하며 정적 파라미터(static parameters)에 보존된다. 반면 상호작용 중에 수신되는 정보는 테스트 시점(test time)에서 획득되어 동적 메모리 상태(dynamic memory states)에 저장된다. 따라서 $\theta_1$는 사전 훈련(pre-training) 외부에서 초기 보조 정보(initial supplementary information)로도 활용될 수 있다. $\theta_1$가 전이 가능한 도메인 지식(transferable domain knowledge)을 포착하므로, 유사 도메인에 배포된 모델은 동일한 $\theta_1$로 초기화하여 기준 정보(baseline information)를 제공할 수 있다.

또한 네이티브 메모리는 기초 모델의 진화 추세와 부합한다. 대형 추론 모델[8]에서 영감을 받아, 우리는 에이전트의 외부 능력이 최적화를 통해 기초 모델에 네이티브하게 표현될 수 있음을 발견했다. 즉, 목표 행동의 감독 데이터는 내부 능력을 활성화하고 이를 다른 과제에 일반화할 수 있다. 이러한 네이티브 능력은 일반화, 효율성 및 최적화 특성에서 이점을 제공한다. 메모리는 전통적으로 외부 모듈에 의존해온 중요한 에이전트 능력이다. 따라서 메모리 역시 메모리 전용 과제를 통해 네이티브하게 유발될 수 있다고 주장한다. 그러나 추론이 순수한 과정인 반면, 메모리는 저장 엔터티를 포함한다. 이는 모델 아키텍처를 수정하여 저장 엔터티를 메모리 상태로 통합하도록 요구한다. 이후 메모리 상태와 절차는 협업 함수 공간에서 모델링되어야 한다. 이를 통해 최적화 기반 접근법으로 기초 모델에 메모리 능력을 부여할 수 있다.

## <span id="page-5-0"></span>3 메티스 아키텍처 (Metis Architecture)

본 장에서는 먼저 몇 가지 전제 조건을 제시한다. 그 다음, 메티스 블록을 갖는 메모리 기반 모델의 프로토타입으로 메티스를 소개한다. 이후 이 아키텍처가 계산을 통해 네이티브 메모리 저장 및 활용 절차를 어떻게 지원하는지 보여준다. 마지막으로 이론적 통찰, 이론적 오차 분석 및 추가 논의를 제공한다. 메티스 프레임워크의 개요는 그림 2에 제시된다.

### 3.1 전제조건 (Preliminaries)

우리는 메모리 기반 모델의 주요 구현으로 인과적 언어 모델을 채택한다. 이는 현대 기초 모델에서 주로 사용되기 때문이다. 인과적 언어 모델의 표준 아키텍처를 제시하며, 이는 주로 *N*개의 스택된 Transformer 블록과 언어 모델링 헤드로 구성된다.

**Transformer Block.** 핵심 구조를 강조하기 위해, 우리는 causal self-attention과 feed-forward network(FFN)에 집중한다. 이 두 요소는 현대 Transformer의 주요 구성 요소이다. 위치 임베딩, multi-head attention 전략, 하이브리드 attention 메커니즘 등 다른 세부 사항은 생략한다. 이들은 우리 프레임워크에 직접 통합될 수 있다.

l번째 Transformer 블록의 입력을  $\mathbf{H}^{(l-1)} \in \mathbb{R}^{L \times d}$ 으로 표시한다. 여기서 L은 시퀀스 길이, d는 은닉 상태 차원이다. PreNorm 전정규화 함수를 적용한 뒤, causal self-attention의 입력으로  $\tilde{\mathbf{H}}^{(l)} = \operatorname{PreNorm}(\mathbf{H}^{(l-1)})$ 를 얻는다. 이 층의 쿼리, 키, 값 투영 행렬을 각각  $\mathbf{W}_Q^{(l)}, \mathbf{W}_K^{(l)} \in \mathbb{R}^{d \times d_k}, \mathbf{W}_V^{(l)} \in \mathbb{R}^{d \times d_v}$ 로 표시한다. 그러면 l번째 층의 쿼리 상태, 키 상태, 값 상태를 다음과 같이 얻는다.

$$\mathbf{Q}^{(l)} = \tilde{\mathbf{H}}^{(l)} \mathbf{W}_{O}^{(l)}, \quad \mathbf{K}^{(l)} = \tilde{\mathbf{H}}^{(l)} \mathbf{W}_{K}^{(l)}, \quad \mathbf{V}^{(l)} = \tilde{\mathbf{H}}^{(l)} \mathbf{W}_{V}^{(l)}.$$

그 다음, causal self-attention은 다음과 같이 계산된다.

<span id="page-5-1"></span>

$$\mathbf{A}^{(l)} = \operatorname{Softmax} \left( \frac{\mathbf{Q}^{(l)} (\mathbf{K}^{(l)})^{\mathsf{T}}}{\sqrt{d_k}} + \operatorname{Mask}(L) \right) \mathbf{V}^{(l)}, \tag{1}$$

여기서 $d_k$는 attention head 차원이며, $\operatorname{Mask}(L)$는 causal mask이며, $\operatorname{Mask}(L)_{i,j} = -\infty$ (j > i 인 경우)이고, 그렇지 않으면 0이다. 그 다음, 투영된 출력 attention을 residual에 추가한다.

$$\mathbf{H}^{\prime(l)} = \mathbf{H}^{(l-1)} + \mathbf{A}^{(l)} \mathbf{W}_{O}^{(l)},$$

<span id="page-6-0"></span>![](2026-08-01-2607.26760-metis-memory-foundation-model/_page_6_Figure_0.jpeg)

Figure 2 Metis 아키텍처 개요.

여기서 $\mathbf{W}_O^{(l)} \in \mathbb{R}^{d_v \times d}$ 이다. 마지막으로, $\mathbf{H}'^{(l)}$ 를 FFN에 통과시키고 residual 연결을 통해 l번째 층 출력을 얻는다.

$$\mathbf{H}^{(l)} = \mathbf{H}^{\prime(l)} + \text{FFN}(\text{Norm}(\mathbf{H}^{\prime(l)})),$$

여기서 활성화된 $\mathbf{H}^{(l)}$ 는 (l+1)번째 층의 입력이기도 하다.

Causal Language Model. 입력 토큰 시퀀스를 $X = (x_1, x_2, ..., x_L)$ 로 표시한다. causal language model은 먼저 이 이산 토큰들을 연속 벡터 표현으로 매핑한다. 토큰 임베딩 행렬을 $\mathbf{E} \in \mathbb{R}^{|\mathcal{V}| \times d}$ 로 표시하며, 여기서 $|\mathcal{V}|$는 어휘 크기이다. 초기 은닉 상태 $\mathbf{H}^{(0)} \in \mathbb{R}^{L \times d}$ 는 해당 임베딩을 추출하고 위치 임베딩과 결합하여 얻는다. 그 다음, 이 초기 표현은 N개의 Transformer 블록 스택을 순차적으로 처리한다.

$$\mathbf{H}^{(l)} = \text{TransformerBlock}^{(l)}(\mathbf{H}^{(l-1)}), \quad \text{for } l = 1, 2, \dots, N.$$

그 다음, 최종 은닉 상태 $\mathbf{H}^{(N)}$ 는 문맥화된 입력을 나타내며, 언어 모델링 헤드는 이 최종 상태를 어휘 공간으로 다시 매핑하여 다음 토큰의 확률 분포를 예측한다. 이 과정은 일반적으로 정규화 후 선형 투영을 거쳐 softmax 함수를 적용하여 모델링된다.

$$P(\cdot \mid x_{\leq i}) = \text{Softmax}(\text{Norm}(\mathbf{H}_{(i)}^{(N)})\mathbf{W}_{\text{LM}}),$$

여기서 $\mathbf{H}_{(i)}^{(N)} \in \mathbb{R}^d$ 는 위치 i의 최종 은닉 벡터이며, $\mathbf{W}_{\mathrm{LM}} \in \mathbb{R}^{d \times |\mathcal{V}|}$ 는 투영 행렬을 나타낸다. $x_{i+1} \sim P(x_{i+1} \mid x_{\leq i})$ 를 샘플링한 뒤, 이 새로운 토큰을 시퀀스에 추가하고 모델은 end-of-sequence 토큰을 디코딩하거나 최대 길이에 도달할 때까지 과정을 반복한다.

사전 훈련 단계에서, 인과적 언어 모델은 표준 자기회귀 다음 토큰 예측 목표를 사용하여 최적화된다. 이는 훈련 시퀀스의 음의 로그우도(negative log-likelihood)를 다음과 같이 최소화한다.

$$\theta = \arg\min_{\theta} \sum_{X \in \mathcal{D}} \sum_{i=1}^{|X|-1} -\log P(x_{i+1} \mid x_{\leq i}; \theta),$$

여기서  $\mathcal{D}$  는 사전 훈련 코퍼스를 나타내며,  $\theta$  는 모델의 모든 학습 가능한 파라미터를 포함한다.

### 3.2 네이티브 메모리 상태 (Native Memory State)

네이티브 메모리 상태를 구현하기 위해, 우리는 Figure 2(b)에서 Transformer 블록 내부에 Metis 블록을 제안한다. 각 Metis 블록은 Figure 2(c)에서 보듯이 로컬 메모리 블록과 하이퍼 메모리 블록으로 구성된다. 로컬 메모리 블록은 이전 정보의 밀집 표현을 유지하는 역할을 하며, 하이퍼 메모리 블록은 메모리 상태를 변환하기 위한 파라메트릭 함수 공간을 구축한다.

**로컬 메모리 블록.** 로컬 메모리 블록은 현재 단계에서 메모리 상태를 유지하므로, l번째 로컬 메모리 블록 내부에 밀집 메모리 네트워크  $\mathbf{M}^{(l)} \in \mathbb{R}^{d_k \times d_v}$  를 정의한다. 단계 t에서 이를  $\mathbf{M}_t^{(l)}$  로 표시한다. 모델은 또한 쿼리-키 정규화 벡터  $\mathbf{S}_t^{(l)} \in \mathbb{R}^{d_k}$  를 유지한다.  $\mathbf{M}^{(l)}$  과  $\mathbf{S}_t^{(l)}$  는 서로 다른 단계에서 업데이트되는 동적 파라미터이다. 구체적으로, 우리는 기본적으로  $\mathbf{M}_1^{(l)} = \mathbf{0}$  과  $\mathbf{S}_1^{(l)} = \mathbf{0}$  를 설정한다.

**하이퍼 메모리 블록.** 하이퍼 메모리 블록은 현재 입력  $X_t$  과 출력  $Y_t$  의 중간 활성화에 기반해 로컬 메모리 블록의 동적 파라미터를 업데이트하는 역할을 한다. 각각은 중간 훈련을 통해 얻은 정적 파라미터로 구성되며, 상호작용 중에는 변하지 않는다. 이는 네이티브 메모리 저장 절차의 파라메트릭 기반이다. 구체적으로, 각 하이퍼 메모리 블록은 여러 최적화 가능한 파라미터로 매개된다. 첫째, 적응형 집계에 대한 중간 활성화를 점수화하는 학습 가능한 중요도 벡터  $\tilde{\mathbf{w}}_{\text{agg}}^{(l)} \in \mathbb{R}^d$  를 갖는다. 추가로, 메모리 키와 값 투영 행렬  $\tilde{\mathbf{W}}_K^{(l)} \in \mathbb{R}^{d \times d_k}$  과  $\tilde{\mathbf{W}}_V^{(l)} \in \mathbb{R}^{d \times d_v}$  를 설정하여 선택된 은닉 상태를 로컬 메모리의 메모리 키와 값으로 매핑한다. 또한, 네이티브 메모리 활용 절차에서 오류를 줄이기 위해 메모리 쿼리 투영 행렬  $\tilde{\mathbf{W}}_Q^{(l)} \in \mathbb{R}^{d \times d_k}$  를 설정한다.

### 3.3 네이티브 메모리 절차 (Native Memory Procedure)

네이티브 메모리 절차는 메모리 저장 절차와 활용 절차로 구성되며, 우리는 **Section 2.3**에서 이를 논의한다. 본 프레임워크의 네이티브 메모리 저장 절차에서 하이퍼 메모리 블록은 중간 활성화를 기반으로 모델 계산의 일부로 로컬 메모리 블록을 업데이트한다. 네이티브 메모리 활용 절차에서는 로컬 메모리 블록이 현재 메모리 상태를 순방향 계산에 통합한다.

네이티브 메모리 저장 절차. 단계 t를 완료한 후, l번째 층의 입력 은닉 상태를  $\mathbf{H}_t^{(l-1)}$  로 표시한다. 그 다음, 하이퍼 메모리 블록은 학습된 적응형 집계를 통해 이를 압축된 표현으로 집계한다. 구체적으로, 먼저 은닉 상태를  $\tilde{\mathbf{H}}_t^{(l)} = \operatorname{PreNorm}(\mathbf{H}_t^{(l-1)})$  로 사전 정규화하고, L개의 토큰 각각을 학습 가능한 중요도 벡터  $\tilde{\mathbf{w}}_{\text{agg}}^{(l)} \in \mathbb{R}^d$  로 점수화하여 중요도 분포를 얻는다.

$$\mathbf{p}_{t}^{(l)} = \operatorname{Softmax}\left(\frac{\tilde{\mathbf{H}}_{t}^{(l)}\tilde{\w_{\operatorname{agg}}^{(l)}}{\tau}\right) \in \mathbb{R}^{L},$$

여기서 $\tau$는 온도 계수이다. 그 다음, 우리는 top-$\rho$에 기반한 위치의 부분집합을 얻는다. 이 확률들을 내림차순으로 정렬하면 $p_{(1)} \ge p_{(2)} \ge \cdots \ge p_{(L)}$가 되고, 누적값이 임계값 $\rho$에 도달하는 가장 짧은 접두사를 유지한다. 선택된 위치의 수는 다음과 같이 표현할 수 있다.

$$L_t' = \operatorname{clip}\left(\min\left\{k: \sum
olimits_{r=1}^k p_{(r)} \geq \rho\right\}, \ K_{\min}, \ L\right),$$

여기서 $K_{\min}$ 은 선택된 위치의 최소 개수를 나타낸다. 이 $L'_t$ 개의 최고 점수를 가진 위치들은 선택된 집합 $\mathcal{S}_t^{(l)}$ 를 형성하며, 우리는 해당 숨겨진 상태들을 수집한다.

$$\tilde{\mathbf{H}}_t^{(l)} = \mathbf{\Pi}_t^{(l)} \tilde{\mathbf{H}}_t^{(l)} \in \mathbb{R}^{L_t' \times d}, \quad \text{with } L_t' \ll L,$$

여기서 $\Pi_t^{(l)} \in \{0,1\}^{L_t' \times L}$ 은 $S_t^{(l)}$ 의 원-핫 인디케이터인 행들로 구성된다. top-$\rho$ 선택은 미분 불가능하므로, 우리는 밀집 분포 $\mathbf{p}_t^{(l)}$ 를 통해 기울기를 전달하는 직통 추정기를 채택하여 스코어러 $\tilde{\mathbf{w}}_{\text{agg}}^{(l)}$ 를 엔드투엔드 학습 가능하게 만든다. 이후에는 투영된 메모리 키 상태와 메모리 값 상태를 다음과 같이 계산한다

$$\tilde{\mathbf{K}}_t^{(l)} = \bar{\mathbf{H}}_t^{(l)} \tilde{\mathbf{W}}_K^{(l)}, \quad \tilde{\mathbf{V}}_t^{(l)} = \bar{\mathbf{H}}_t^{(l)} \tilde{\mathbf{W}}_V^{(l)}.$$

Finally, the dense memory network is updated based on  $\tilde{\mathbf{K}}_{t}^{(l)}$  and  $\tilde{\mathbf{V}}_{t}^{(l)}$  by

$$\mathbf{M}_{t+1}^{(l)} = \lambda \mathbf{M}_{t}^{(l)} + \frac{(1-\lambda)}{L_{t}'} \cdot \frac{\tilde{\mathbf{K}}_{t}^{(l)\top}}{\sqrt{d_{k}}} \tilde{\mathbf{V}}_{t}^{(l)}, \tag{2}$$

여기서 $\lambda$는 할인 계수(discount factor)를 나타낸다. 또한, 쿼리-키 정규화 벡터는 업데이트될 수 있다.

$$\mathbf{S}_{t+1}^{(l)} = \lambda \mathbf{S}_{t}^{(l)} + \frac{(1-\lambda)}{L_{t}'} \cdot \frac{\tilde{\mathbf{K}}_{t}^{(l)\top} \mathbf{1}}{\sqrt{d_{k}}}.$$

(3)

이 네이티브 저장 프로시저는 그림 2(c)에 제시된다. 구축된 함수 공간을 기반으로 우리는 최적화를 통해 다양한 메모리 연산을 모델의 계산에 내재화하려 한다. 구체적으로, 선택과 투영은 모델에 압축 기능을 제공한다. 한편, 의미 기반 계산은 메모리 명령을 잠재 공간 내에서 이해하고 적용할 수 있게 한다. 실제로 우리는 선형 업데이트를 Gated Delta Network (GDN)-기반 [26] 업데이트로 대체하면 성능이 향상됨을 발견했으므로 Metis는 최종적으로 GDN 기반 업데이트(GDU) 전략을 채택한다. 섹션 6.3 및 부록 C는 두 구현을 제거 실험을 통해 비교한다.

Native Memory Utilization Procedure. We define the memory attention as

$$\tilde{\mathbf{A}}_{t}^{(l)} = \operatorname{diag}\left(\tilde{\mathbf{Q}}_{t}^{(l)}\mathbf{S}_{t}^{(l)}\right)^{-1}\tilde{\mathbf{Q}}_{t}^{(l)}\mathbf{M}_{t}^{(l)},\tag{4}$$

여기서  $\tilde{\mathbf{Q}}_t^{(l)} = \tilde{\mathbf{H}}_t^{(l)} \tilde{\mathbf{W}}_Q^{(l)}$  은 최적화 가능한 파라미터  $\tilde{\mathbf{W}}_Q^{(l)} \in \mathbb{R}^{d \times d_k}$ 를 갖는 메모리 쿼리 상태를 나타낸다. 실제로는 정규화 분모에 항등 벡터를 추가하여 수치 오버플로우를 방지하고 수치 안정성을 향상시킨다. 이후 메모리 어텐션을 어텐션의 메인 브랜치에 통합하고, 식 (1)을 ...으로 대체한다.

$$\mathbf{A}_{t}^{(l)} = \gamma \cdot \operatorname{Softmax} \left( \frac{\mathbf{Q}_{t}^{(l)} (\mathbf{K}_{t}^{(l)})^{\mathsf{T}}}{\sqrt{d_{k}}} + \operatorname{Mask}(L) \right) \mathbf{V}_{t}^{(l)} + (1 - \gamma) \cdot \operatorname{Norm} \left( \tilde{\mathbf{A}}_{t}^{(l)} \right), \tag{5}$$

where Norm(·)은 메모리 읽기 결과에 적용되어 원래의 어텐션 분기와 스케일을 맞추며, $\mathbf{K}_t^{(l)}$, $\mathbf{V}_t^{(l)}$는 현재 단계에서 입력 키 상태와 값 상태이며, $\gamma \in [0,1]$는 두 분기를 균형시킨다.


### 3.4 Native Memory Procedures의 이론적 통찰 (Theoretical Insight of Native Memory Procedures)


우리는 Metis 블록을 통해 이전 단계의 정보가 이후 추론에 어떻게 영향을 미치는지에 대한 이론적 통찰을 제공한다. 단계 t에서 우리는 가상 메모리 프리픽스 $\mathbf{P}_t^{(l)} \in \mathbb{R}^{L_p \times d}$를 l번째 어텐션 레이어의 입력 $\tilde{\mathbf{H}}_t^{(l)}$ 앞에 붙여, 증강된 입력을 생성한다.

$$\hat{\mathbf{H}}_t^{(l)} = \begin{bmatrix} \mathbf{P}_t^{(l)} \\ \tilde{\mathbf{H}}_t^{(l)} \end{bmatrix}.$$

그 다음, 대응되는 쿼리 상태 $\hat{\mathbf{Q}}_{t}^{(l)}$를 다음과 같이 계산한다.

$$\hat{\mathbf{Q}}_t^{(l)} = \hat{\mathbf{H}}_t^{(l)} \mathbf{W}_Q^{(l)} = \begin{bmatrix} \mathbf{P}_t^{(l)} \mathbf{W}_Q^{(l)} \\ \mathbf{Q}_t^{(l)} \end{bmatrix}.$$

마찬가지로, 키 상태와 값 상태는 다음과 같다.

$$\hat{\mathbf{K}}_t^{(l)} = \begin{bmatrix} \mathbf{P}_t^{(l)} \mathbf{W}_K^{(l)} \\ \mathbf{K}_t^{(l)} \end{bmatrix}, \quad \hat{\mathbf{V}}_t^{(l)} = \begin{bmatrix} \mathbf{P}_t^{(l)} \mathbf{W}_V^{(l)} \\ \mathbf{V}_t^{(l)} \end{bmatrix}.$$

그 다음, 수정된 인과 마스크 $\operatorname{Mask}(L_p + L) \in \mathbb{R}^{(L_p + L) \times (L_p + L)}$를 사용하여 어텐션 출력 $\hat{\mathbf{A}}_t$를 계산한다.

$$\hat{\mathbf{A}}_t = \operatorname{Softmax} \left( \frac{\hat{\mathbf{Q}}_t^{(l)} \hat{\mathbf{K}}_t^{(l) \top}}{\sqrt{d_k}} + \operatorname{Mask}(L_p + L) \right) \hat{\mathbf{V}}_t^{(l)}.$$

구체적으로, 인과 마스크를 다음과 같이 네 부분으로 나눈다.

$$\operatorname{Mask}(L_p + L) = \begin{bmatrix} \mathbf{0}_{L_p \times L_p} & -\infty_{L_p \times L} \\ \mathbf{0}_{L \times L_p} & \operatorname{Mask}(L) \end{bmatrix},$$

$\mathbf{0}_{L \times L_p}$는 가상 메모리 프리픽스 토큰이 입력 토큰에 보이도록 허용한다. 이후, 어텐션 계산을 다음과 같이 분해한다.

$$\hat{\mathbf{A}}_{t} = \begin{bmatrix} \operatorname{Softmax} \left( \frac{\left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{Q}^{(l)}\right) \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}} \right) & \mathbf{0}_{L_{p} \times L} \\ \operatorname{Softmax}^{*} \left( \frac{\mathbf{Q}_{t}^{(l)} \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}} \right) & \operatorname{Softmax}^{*} \left( \frac{\mathbf{Q}_{t}^{(l)} \mathbf{K}_{t}^{(l) \top}}{\sqrt{d_{k}}} + \operatorname{Mask}(L) \right) \end{bmatrix} \begin{bmatrix} \mathbf{P}_{t}^{(l)} \mathbf{W}_{V}^{(l)} \\ \mathbf{V}_{t}^{(l)} \end{bmatrix},$$

Softmax $^*$ (·)는 전체 행에 적용되는 전역 소프트맥스 함수를 의미한다. 이후, 비가상 토큰에 해당하는 어텐션 출력을 다음과 같이 유지한다.

<span id="page-9-0"></span>

$$\mathbf{A}_{t}^{(l)} = \underbrace{\operatorname{Softmax}^{*} \left( \frac{\mathbf{Q}_{t}^{(l)} \mathbf{K}_{t}^{(l) \top}}{\sqrt{d_{k}}} + \operatorname{Mask}(L) \right) \mathbf{V}_{t}^{(l)}}_{\text{원본 어텐션}} + \underbrace{\operatorname{Softmax}^{*} \left( \frac{\mathbf{Q}_{t}^{(l)} \left( \mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)} \right)^{\top}}{\sqrt{d_{k}}} \right) \left( \mathbf{P}_{t}^{(l)} \mathbf{W}_{V}^{(l)} \right)}_{\text{메모리 어텐션}}.$$

(6)

$\mathbf{z}_{\text{orig}}$와 $\mathbf{z}_{\text{mem}}$는 원본 어텐션과 메모리 어텐션의 분할 항목을 나타낸다.

$$\mathbf{z}_{\text{orig}} = \exp\left(\frac{\mathbf{Q}_{t}^{(l)} \mathbf{K}_{t}^{(l)^{\top}}}{\sqrt{d_{k}}} + \text{Mask}(L)\right) \mathbf{1}_{L}, \quad \mathbf{z}_{\text{mem}} = \exp\left(\frac{\mathbf{Q}_{t}^{(l)} \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}}\right) \mathbf{1}_{L_{p}}.$$

(7)

그 다음, 원소별 합으로 나누어 가중치 행렬을 얻는다

$$\Lambda_{\text{orig}} = \text{diag}\left(z_{\text{orig}} \oslash \left(z_{\text{orig}} + z_{\text{mem}}\right)\right), \quad \Lambda_{\text{mem}} = \text{diag}\left(z_{\text{mem}} \oslash \left(z_{\text{orig}} + z_{\text{mem}}\right)\right) = I - \Lambda_{\text{orig}}.$$

그 다음, 방정식 (6)은 각 부분에 대해 일반 Softmax 함수를 적용한 식과 동일하다:

$$\mathbf{A}_{t}^{(l)} = \mathbf{\Lambda}_{\text{orig}} \cdot \operatorname{Softmax} \left( \frac{\mathbf{Q}_{t}^{(l)} \mathbf{K}_{t}^{(l) \top}}{\sqrt{d_{k}}} + \operatorname{Mask}(L) \right) \mathbf{V}_{t}^{(l)} + \left( \mathbf{I} - \mathbf{\Lambda}_{\text{orig}} \right) \cdot \operatorname{Softmax} \left( \frac{\mathbf{Q}_{t}^{(l)} \left( \mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)} \right)^{\top}}{\sqrt{d_{k}}} \right) \left( \mathbf{P}_{t}^{(l)} \mathbf{W}_{V}^{(l)} \right).$$

두 주의(attention) 구성요소의 영향을 제어하기 위해, 전역 가중치 파라미터 $\gamma \in [0, 1]$ 를 도입하여 원래 가중치 행렬을 근사한다

$$\mathbf{A}_{t}^{(l)} = \gamma \cdot \operatorname{Softmax}\left(\frac{\mathbf{Q}_{t}^{(l)}\mathbf{K}_{t}^{(l)^{\top}}}{\sqrt{d_{k}}} + \operatorname{Mask}(L)\right)\mathbf{V}_{t}^{(l)} + (1 - \gamma) \cdot \operatorname{Softmax}\left(\frac{\mathbf{Q}_{t}^{(l)}\left(\mathbf{P}_{t}^{(l)}\mathbf{W}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}}\right)\left(\mathbf{P}_{t}^{(l)}\mathbf{W}_{V}^{(l)}\right).$$

그 다음, $\mathbf{P}_t^{(l)}$ 에 대한 이 특정 메모리 주의 부분을 다음과 같이 표기한다

$$\check{\mathbf{A}}_{t}^{(l)} = \operatorname{Softmax}\left(\frac{\mathbf{Q}_{t}^{(l)} \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}}\right) \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{V}^{(l)}\right).$$

우리는 $\mathbf{Q}_t^{(l)}$ 와 $\mathbf{P}_t^{(l)}\mathbf{W}_K^{(l)}$ 사이의 유사성 함수를 다음과 같이 정의한다

$$\operatorname{Sim}\left(\mathbf{Q}_{t}^{(l)}, \mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right) = \exp\left(\frac{\mathbf{Q}_{t}^{(l)} \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}}\right).$$

그 다음, 메모리 주의는 다음과 같이 다시 쓸 수 있다

$$\check{\mathbf{A}}_{t}^{(l)} = \operatorname{diag}\left(\operatorname{Sim}\left(\mathbf{Q}_{t}^{(l)}, \mathbf{P}_{t}^{(l)}\mathbf{W}_{K}^{(l)}\right) \cdot \mathbf{1}\right)^{-1}\operatorname{Sim}\left(\mathbf{Q}_{t}^{(l)}, \mathbf{P}_{t}^{(l)}\mathbf{W}_{K}^{(l)}\right)\left(\mathbf{P}_{t}^{(l)}\mathbf{W}_{V}^{(l)}\right).$$

$\mathbf{Q}_t^{(l)}$ 부분과 $\mathbf{P}_t^{(l)}\mathbf{W}_K^{(l)}$ 부분을 분해하기 위해, 유사성을 다음과 같이 근사한다

$$\operatorname{Sim}\left(\mathbf{Q}_{t}^{(l)}, \mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right) = \frac{\mathbf{Q}_{t}^{(l)} \left(\mathbf{P}_{t}^{(l)} \mathbf{W}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}}.$$

따라서 메모리 주의는 다음과 같이 다시 쓸 수 있다

$$\check{\mathbf{A}}_{t}^{(I)} = \operatorname{diag}\left(\mathbf{Q}_{t}^{(I)} \frac{\left(\mathbf{P}_{t}^{(I)} \mathbf{W}_{K}^{(I)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \cdot \mathbf{1}\right)^{-1} \mathbf{Q}_{t}^{(I)} \left[\frac{\left(\mathbf{P}_{t}^{(I)} \mathbf{W}_{K}^{(I)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \left(\mathbf{P}_{t}^{(I)} \mathbf{W}_{V}^{(I)}\right)\right].$$

(8)

마지막으로, 프리픽스 토큰 $\mathbf{P}_t^{(l)}$ 를 c번째(c < t) 단계에서 집계된 결과 $\bar{\mathbf{H}}_c^{(l)}$ 로 간주하면 다음과 같다

<span id="page-10-0"></span>

$$\check{\mathbf{A}}_{t}^{(l)} = \operatorname{diag}\left(\mathbf{Q}_{t}^{(l)} \frac{\left(\bar{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \cdot \mathbf{1}\right)^{-1} \mathbf{Q}_{t}^{(l)} \left[\frac{\left(\bar{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \left(\bar{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{V}^{(l)}\right)\right],\tag{9}$$

여기서  $\tilde{\mathbf{W}}_K^{(l)}$ ,  $\tilde{\mathbf{W}}_V^{(l)}$  는 하이퍼 메모리 블록의 파라미터이다.  
실제로는 참조 단계 c가 사전에 접근 가능하지 않으며, 단계 t에서 요구되는 증거가 단일 단계보다 더 넓게 걸쳐 있을 수 있다는 점을 주목할 필요가 있다.  
한편, 서로 다른 단계의 메모리 키 상태와 메모리 값 상태는 고정 크기 메모리 네트워크  $\mathbf{M}_t^{(l)}$  및 정규화 벡터  $\mathbf{S}_t^{(l)}$  내에서 결합되어, 비참조 단계 $(j 
eq c)$ 가 읽기 결과에 노이즈로 누출되는 것을 불가피하게 만든다.  
이러한 노이즈의 영향을 완화하기 위해, 방정식 (9)에서 일반적인 어텐션 쿼리  $\mathbf{Q}_t^{(l)}$  를 직접 재사용하는 대신, 학습 가능한 메모리 쿼리  $\tilde{\mathbf{Q}}_t^{(l)} = \tilde{\mathbf{H}}_t^{(l)} \tilde{\mathbf{W}}_O^{(l)}$  를 활용한다.

<span id="page-10-2"></span>

$$\check{\mathbf{A}}_{t}^{(l)} = \operatorname{diag}\left(\tilde{\mathbf{Q}}_{t}^{(l)} \frac{\left(\tilde{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \cdot \mathbf{1}\right)^{-1} \tilde{\mathbf{Q}}_{t}^{(l)} \left[\frac{\left(\tilde{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{K}^{(l)}\right)^{\mathsf{T}}}{\sqrt{d_{k}}} \left(\tilde{\mathbf{H}}_{c}^{(l)} \tilde{\mathbf{W}}_{V}^{(l)}\right)\right],\tag{10}$$

여기서  $\tilde{\mathbf{W}}_Q^{(l)} \in \mathbb{R}^{d \times d_k}$  은 최적화 가능한 프로젝션이다. 이는 메모리 쿼리를 원래의 어텐션에서 분리하고, 교차 단계 유사성  $\tilde{\mathbf{Q}}_t^{(l)} \tilde{\mathbf{K}}_j^{(l) \top}$  를 재구성할 자유를 제공한다. 따라서 관련 단계는 강조하고 무관한 단계는 억제하여, 메모리 쿼리 상태를 사용할 때 노이즈의 영향을 줄일 수 있다. 우리는 섹션 3.5에서 자세한 이론적 오류 분석을 제공한다.

### 3.5 이론적 오류 분석 (Theoretical Error Analysis)

전통적인 Transformer가 모든 과거 KV 쌍을 증가하는 캐시에 저장하는 것과 달리, 하이퍼 메모리 블록은 정보를 고정 크기 행렬에 압축한다. 모델이 c번째 단계에서 정보를 추출해야 한다고 가정한다. 밀집 메모리 네트워크는 다음과 같이 표현될 수 있다.

$$\mathbf{M}_t^{(l)} = \sum_{j=1}^{t-1} \lambda^{t-(j+1)} \cdot \frac{(1-\lambda)}{L_j'} \cdot \frac{\tilde{\mathbf{K}}_j^{(l)\top}}{\sqrt{d_k}} \tilde{\mathbf{V}}_j^{(l)}.$$

그 다음, 우리는 메모리 쿼리 $\tilde{\mathbf{Q}}_t^{(l)} = \tilde{\mathbf{H}}_t^{(l)} \tilde{\mathbf{W}}_Q^{(l)}$ 를 사용하여 밀집 메모리 네트워크에서 정보를 추출하고 쿼리-키 정규화 벡터를 다음과 같이 정의한다.

$$\begin{split} \tilde{\mathbf{A}}_{t}^{(l)} = & \operatorname{diag}\left(\tilde{\mathbf{Q}}_{t}^{(l)}\mathbf{S}_{t}^{(l)}\right)^{-1}\tilde{\mathbf{Q}}_{t}^{(l)}\mathbf{M}_{t}^{(l)} \\ = & \operatorname{diag}\left(\sum_{j=1}^{t-1}\lambda^{t-(j+1)}\frac{(1-\lambda)}{L_{j}'}\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\tilde{\mathbf{K}}_{j}^{(l)\top}}{\sqrt{d_{k}}}\mathbf{1}\right)^{-1} \\ \cdot \left(\sum_{j=1}^{t-1}\lambda^{t-(j+1)}\cdot\frac{(1-\lambda)}{L_{j}'}\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\tilde{\mathbf{K}}_{j}^{(l)\top}}{\sqrt{d_{k}}}\tilde{\mathbf{V}}_{j}^{(l)}\right). \end{split}$$

위 합산에서 개별 항을 다음과 같이 정의한다.

$$\mathbf{U}_j = \lambda^{t-(j+1)} \frac{(1-\lambda)}{L_j'} \tilde{\mathbf{Q}}_t^{(l)} \frac{\tilde{\mathbf{K}}_j^{(l)\top}}{\sqrt{d_k}} \mathbf{1},$$

$$\mathbf{R}_{j'} = \lambda^{t-(j'+1)} \cdot \frac{(1-\lambda)}{L'_{j'}} \tilde{\mathbf{Q}}_t^{(l)} \frac{\tilde{\mathbf{K}}_{j'}^{(l)\top}}{\sqrt{d_k}} \tilde{\mathbf{V}}_{j'}^{(l)},$$

그리고 $\tilde{\mathbf{A}}_{t}^{(l)}$는 다음과 같이 다시 쓸 수 있다

$$\tilde{\mathbf{A}}_t^{(l)} = \operatorname{diag}\left(\sum_{j=1}^{t-1} \mathbf{U}_j\right)^{-1} \left(\sum_{j'=1}^{t-1} \mathbf{R}_{j'}\right).$$

우리의 목표 정보가 *c*-단계에 저장되어 있다고 가정한다(즉, 유사도 $\tilde{\mathbf{Q}}_t^{(l)}\tilde{\mathbf{K}}_c^{(l)}$가 다른 단계보다 현저히 높다). 그러면 방정식을 다음과 같이 더 재작성할 수 있다

$$\begin{split} \tilde{\mathbf{A}}_{t}^{(I)} = & \operatorname{diag}\left(\mathbf{U}_{c} + \sum_{j=1, j 
eq c}^{t-1} \mathbf{U}_{j}\right)^{-1} \left(\mathbf{R}_{c} + \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'}\right). \\ = & \left(\operatorname{diag}\left(\mathbf{U}_{c}\right) \left(\mathbf{I} + \operatorname{diag}\left(\mathbf{U}_{c}\right)^{-1} \cdot \operatorname{diag}\left(\sum_{j=1, j 
eq c}^{t-1} \mathbf{U}_{j}\right)\right)\right)^{-1} \left(\mathbf{R}_{c} + \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'}\right). \end{split}$$

1차 테일러 전개에 따라 다음과 같다

$$\begin{split} \tilde{\mathbf{A}}_{t}^{(l)} \approx & \left( \mathbf{I} - \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \cdot \operatorname{diag} \left( \sum_{j=1, j 
eq c}^{t-1} \mathbf{U}_{j} \right) \right) \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \left( \mathbf{R}_{c} + \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'} \right), \\ = & \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \mathbf{R}_{c} + \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'} - \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \cdot \operatorname{diag} \left( \sum_{j=1, j 
eq c}^{t-1} \mathbf{U}_{j} \right) \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \mathbf{R}_{c} \\ - & \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \cdot \operatorname{diag} \left( \sum_{j=1, j 
eq c}^{t-1} \mathbf{U}_{j} \right) \operatorname{diag} \left( \mathbf{U}_{c} \right)^{-1} \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'}, \\ & \underbrace{ \left( \mathbf{R}_{c} + \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'} + \sum_{j'=1, j' 
eq c}^{t-1} \mathbf{R}_{j'} \right)}_{\boldsymbol{\epsilon}_{3}} \end{split}$$

첫 번째 항은 방정식 (10)의 $\check{\mathbf{A}}_t^{(l)}$와 동일하며, $\tilde{\mathbf{K}}_c^{(l)} = \bar{\mathbf{H}}_c^{(l)} \tilde{\mathbf{W}}_K^{(l)}$ 및 $\tilde{\mathbf{V}}_c^{(l)} = \bar{\mathbf{H}}_c^{(l)} \tilde{\mathbf{W}}_V^{(l)}$에 의해

$$\begin{split} \operatorname{diag}\left(\mathbf{U}_{c}\right)^{-1}\mathbf{R}_{c} = &\operatorname{diag}\left(\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\tilde{\mathbf{K}}_{c}^{(l)\top}}{\sqrt{d_{k}}}\mathbf{1}\right)^{-1}\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\tilde{\mathbf{K}}_{c}^{(l)\top}}{\sqrt{d_{k}}}\tilde{\mathbf{V}}_{c}^{(l)} \\ = &\operatorname{diag}\left(\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\left(\bar{\mathbf{H}}_{c}^{(l)}\tilde{\mathbf{W}}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}}\mathbf{1}\right)^{-1}\tilde{\mathbf{Q}}_{t}^{(l)}\frac{\left(\bar{\mathbf{H}}_{c}^{(l)}\tilde{\mathbf{W}}_{K}^{(l)}\right)^{\top}}{\sqrt{d_{k}}}\left(\bar{\mathbf{H}}_{c}^{(l)}\tilde{\mathbf{W}}_{V}^{(l)}\right) \\ = &\tilde{\mathbf{A}_{t}^{(l)}}. \end{split}$$

따라서, $||\tilde{\mathbf{A}}_t^{(l)} - \check{\mathbf{A}}_t^{(l)}||_2$ 에 대한 세 가지 오차 항이 존재한다. $\epsilon_2$와 $\epsilon_3$는 전역 정규화에 의해 발생하는 구조적 오차이며, 반면 $\epsilon_1$은 무관한 정보에 의해 도입된 어텐션 오차이다. 이 세 항 중 항상 적어도 하나의 항이 $\tilde{\mathbf{Q}}_t^{(l)} \tilde{\mathbf{K}}_j^{(l)\top}$ (여기서 $j 
eq c$) 를 포함한다. 따라서 이 유사도가 낮을 때는 결과 오차가 작을 것으로 예상된다.

### 3.6 효율성 분석 (Efficiency Analysis)

Metis는 외부 메모리와 비교해 추가 추론 오버헤드가 제한적인 네이티브 메모리를 도입한다. 핵심 이유는 원래 어텐션, 메모리 어텐션, 메모리 저장 절차가 크게 병렬로 실행될 수 있기 때문이다. l번째 레이어의 t 단계에서 원래 어텐션 분기는 현재 입력에 대해 토큰-토큰 어텐션을 계산하고, 메모리 활용 분기는 네이티브 메모리 상태 $\mathbf{M}_t^{(l)}$와 $\mathbf{S}_t^{(l)}$ 에 대해 메모리 어텐션을 수행한다. 이 두 분기는 동일한 입력 은닉 상태에 의존하지만 서로에 대한 순차적 의존성이 없다. 따라서 메모리 어텐션은 원래 어텐션의 출력을 기다릴 필요가 없으며, 두 분기가 모두 끝난 뒤에만 결과를 융합할 수 있다.

메모리 저장 절차도 현재 추론 경로와 분리될 수 있다. 이는 미래 단계에 대한 메모리 상태를 업데이트하고, 현재 단계에서는 기존 메모리 상태만 읽는다. 따라서 필요한 은닉 상태가 준비되면 저장 분기는 원래 어텐션과 메모리 활용과 병렬로 실행될 수 있으며, 추가적인 순차 단계가 되지 않는다. 결과적으로 레이어 수준 지연은 다음과 같이 표현될 수 있다.

$$T_{\text{parallel}}^{(l)} = \max \left( T_{\text{orig}}^{(l)}, T_{\text{util}}^{(l)}, T_{\text{store}}^{(l)} \right) + T_{\text{fuse}}^{(l)}. \tag{11}$$

또한 Metis는 과거 정보를 고정 크기의 네이티브 메모리 상태에 저장하고, 검색된 텍스트 메모리를 입력 컨텍스트에 추가하지 않는다. 따라서 메모리 활용 비용은 주로 메모리 상태 크기에 의존하며, 과거 상호작용 수에 따라 선형적으로 증가하지 않는다. 이는 Metis가 네이티브 메모리 기능을 제공하면서 외부 메모리 시스템이 일반적으로 도입하는 검색, 연결, 사전 채우기 오버헤드를 피할 수 있게 한다.

## 4 데이터 구성 (Data Construction)

일반 기반 모델을 중간 훈련 단계에서 Metis를 구축하기 위해, 기존 공개 데이터셋을 기반으로 종합적인 훈련 데이터셋을 합성한다. 이 데이터셋은 기본 데이터와 보조 데이터로 구성되며, 네이티브 메모리 절차를 훈련하고 복잡한 시나리오에서 일반화를 향상시키는 데 사용된다.

### 4.1 기본 데이터 (Primary Data)

기본 데이터는 네이티브 메모리 절차를 훈련하기 위한 핵심 감독 역할을 한다. 이는 최적화를 통해 메모리 기반 모델이 순방향 계산에서 다양한 메모리 연산을 수행하도록 가르치도록 설계되었으며, 이를 통해 다양한 시나리오에 일반화된다. 네이티브 메모리 절차는 수동 규칙이 아니라 최적화를 통해 획득되므로, 기본 데이터는 원하는 메모리 연산에 대한 명시적 감독을 제공해야 한다.

**데이터 원칙.** 우리는 두 가지 데이터 원칙을 강조한다. 첫째, 데이터는 온라인 정보의 시간 흐름 특성을 반영하는 시계열 순서의 상호작용 단계로 구조화되어야 한다. 둘째, 데이터는 상태 일관성을 가져야 한다. 이후 질의에 대한 응답은 이전 연산에 의해 형성된 메모리 상태와 일치해야 한다. 이 두 특성은 모델이 정보를 저장하고 적절한 이후 단계에서 활용하도록 가르친다.

데이터 요약. 우리는 Table [1](#page-13-0)에 표시된 것처럼, 네 가지 메모리 연산에 걸쳐 27개의 공개 벤치마크를 선택한다. 우리는 기본 데이터를 세 가지 직교 차원으로 구성한다:  
(1) 메모리 연산은 *기억*(*remember*), *잊기*(*forget*), *갱신*(*update*), 그리고 *반영*(*reflect*)를 포함하며, 이들은 모두 네이티브 메모리의 핵심 행동을 포괄한다.  
(2) 지시의 중요성은 명시적 메모리 명령에서 자연스러운 서사에 정보를 삽입하는 암시적 진술까지 다양하다.  
(3) 잡음 수준은 정제된 시퀀스가 기본 사례를 형성하고, 잡음이 있는 시퀀스는 무관한 턴을 삽입하여 생성된다.  
이 세 차원은 메모리 절차가 연산, 지시 스타일, 잡음 수준 전반에 걸쳐 일반화하도록 장려한다.  
*기억*(*remember*) 샘플은 사실을 진술한 뒤 그 사실을 묻는다. 반면 *반영*(*reflect*) 샘플은 여러 개의 단일 홉 사실을 도입한 뒤 그들의 다중 홉 조합을 묻는다.  
*갱신*(*update*) 샘플은 이전에 진술한 사실을 수정한 뒤 질문하고, *잊기*(*forget*) 샘플은 이전에 진술한 사실을 취소한 뒤 질문한다.

구성 파이프라인. 우리의 데이터 합성 파이프라인은 시드 추출, 정적 합성, 품질 검증이라는 세 가지 주요 단계로 구성된다.

*1단계: 시드 추출.* 각 소스 데이터셋에서 소스 참조, 질문, 답변을 추출하여 기본 대화를 만든다. 그 다음, 기본 사실을 구조화된 시드로 요약한다. 이 시드는 주제, 관계, 대상과 함께 업데이트된 대상이나 다중 홉 체인과 같은 연산별 필드를 기록한다. 또한, 각 질문과 논리적으로 직교하는 방해 대화 풀을 수집하여 시퀀스 길이를 늘리는 데 사용한다.

*2단계: 정적 합성.* 구조화된 시드를 기반으로 강력한 지시 따르기 언어 모델이 각 기본 대화를 두 가지 중요도 스타일로 재작성한다. 명시적 스타일은 참조를 명확한 메모리 지시로 표현하고, 암시적 스타일은 같은 사실을 명시적 지시 없이 서술한다…

*3단계: 품질 검증.* 언어 모델은 자동 심사자로서 여러 품질 기준에 따라 샘플을 필터링한다. 일관성 검사는 최종 답변이 의도한 메모리 상태를 충실히 반영하는지 확인한다. 직교성 검사는 삽입된 방해가 핵심 사실을 유출하지 않는지 보장하고, 지름길 검사는 참조 없이 답변 가능한 질문을 제거한다. 또한, 템플릿 붕괴를 방지하기 위해 질문의 의미적 다양성을 모니터링한다. 어느 검사를 통과하지 못한 샘플은 폐기되어, 신뢰할 수 있는 샘플만 최종 코퍼스에 포함된다.

### 4.2 보조 데이터 (Auxiliary Data)

보조 데이터는 모델의 일반화 가능성을 향상시키는 데 사용된다. 또한 다중 엔터티 작업 및 혼합 대화와 같은 복잡한 시나리오에서 메모리 기반 기초 모델의 기능을 더욱 강화한다.

구성 원칙. 기본 데이터(primary data)는 단일 사실 연산부터 다중 사실 추론 사례(multi-fact reasoning cases)까지 기본 메모리 연산 상호작용으로 구성된다. 그러나 실제 상호작용은 훨씬 복잡하다. 유사한 사실이 여러 개 공존할 수 있고, 일부 사실은 폐지되고 다른 사실은 지속될 수 있으며, 메모리 턴(memory turns)은 일반 대화와 자주 교차한다.

첫 번째는 간섭(interference)으로, 모델이 유사한 사실을 혼동하거나 망각 연산이 파라메트릭 공간(parametric spaces)에서 보존된 사실을 손상시키는 경우이다. 두 번째는 메모리 오염(memory pollution)으로, 모델이 필요하지 않은 질문에 저장된 값을 적용하는 경우이다. 보조 데이터(auxiliary data)는 이러한 시나리오를 정확히 겨냥하여 기본 데이터를 보완한다. 보조 데이터는 동일한 사실 수준 구조를 유지하면서 사실과 대화를 보다 도전적인 상호작용 패턴으로 구성하여 원시 메모리(native memory)의 일반화와 견고성을 향상시킨다.

데이터 요약. 보조 데이터를 네 가지 하위 유형으로 구성하며, 이는 표 [3](#page-14-1)에 표시된다.  
첫 번째 두 하위 유형은 다중 사실 시나리오를 다룬다.  
(1) 다중 엔티티 바인딩은 두 개의 혼동 가능한 사실을 동시에 저장하고 둘 다를 질의하여, 모델이 각 값을 자신의 사실에 바인딩하도록 훈련한다.  
(2) 선택적 망각은 한 사실을 폐지하고 다른 사실은 유지함으로써, 모델이 부수적인 손실 없이 한 사실만 선택적으로 잊도록 훈련한다.  
나머지 두 하위 유형은 메모리 오염을 다룬다.  
(3) 메모리 이후 대화는 메모리 질의 직후 일반 대화를 이어가므로, 모델이 저장된 값을 관련 없는 답변에 반영하지 않도록 한다.  
(4) 메모리 무관 대화는 메모리 상태가 존재해도 메모리가 필요 없는 질문에 답함으로써, 모델이 메모리가 반응에 영향을 주어서는 안 되는 시점을 학습하도록 한다.  
따라서 이 네 가지 하위 유형은 기본 데이터를 현실적인 혼합 상호작용으로 확장한다.

구성 파이프라인. 보조 데이터는 합성된 쌍 사실과 준비된 일반 대화를 포함한 두 가지 공통 재료로부터 구축되며, 이후 네 가지 하위 유형으로 구성된다.

*쌍 사실 합성.* 다중 엔티티 바인딩과 선택적 망각 하위 유형은 유사한 사실 쌍을 필요로 한다. 각 소스 사실은 주어, 관계, 값으로 표현되며, 우리는 하나의 혼동 가능한 대조 사실을 합성한다. 각 대조 사실은 소스 사실에 대해 네 가지 변환 중 하나를 사용해 생성된다. 주어는 유지하되 관계를 바꾸거나, 관계는 유지하되 주어를 바꾸거나, 값 형식을 모방하거나, 의미적으로 인접한 상태를 유지한다. 언어 모델이 각 대조 사실을 생성하고, 검증자는 모순되거나 재진술되거나 소스에 의존하는 사실을 제외한다. 이후 검증된 사실을 자연스러운 문장, 질의, 폐지 스니펫으로 재작성하여 유창성과 다양성을 확보한다.

하위 유형 공식화. 다중 엔티티 바인딩 하위 유형은 순차적으로 쌍으로 된 사실을 제시한 뒤 두 사실을 모두 질의하여 모델이 각 값을 올바른 사실에 바인딩하도록 강제한다. 선택적 망각 하위 유형은 두 사실을 제시하고 하나를 철회한 뒤 두 사실을 모두 질의한다. 따라서 철회된 사실은 사용 불가능해지고 보존된 사실은 올바른 상태를 유지한다. 포스트-메모리 대화 하위 유형은 메모리 질의 뒤에 무관한 일반 턴을 추가하여 모델이 저장된 값을 유출하지 않고 정상 대화로 복귀하도록 한다. 메모리-무관 대화 하위 유형은 메모리 상태를 유지하지만 일반 턴 전에 그 질의를 삭제하고, 메모리를 전혀 포함하지 않는 독립 대화도 포함한다.

## <span id="page-15-0"></span>5 모델 최적화 (Model Optimization)

Metis를 네이티브 메모리 절차로 강화하기 위해, 우리는 중간 훈련 단계에서 여러 훈련 목표를 설계한다. 이 목표들은 주로 메모리 재구성, 메모리 연산, 정규화로 구성된다. 세 목표는 공통적인 우도 형태를 공유하지만 서로 다른 데이터에서 작동한다. 이들은 함께 네이티브 메모리 상태와 절차를 형성한다.

### 5.1 개요 (Overview)

우리는 각 훈련 샘플을 다단계 상호작용 $s = \{(X_t, Y_t)\}_{t=1}^{T_s}$ 으로 구성한다. 이는 섹션 2의 정의를 따른다. 단계 t에서 모델은 입력 지시문 $X_t$ 를 읽고 어시스턴트 응답 $Y_t = (y_{t,1}, \ldots, y_{t,|Y_t|})$ 를 생성한다. 모든 단계는 순차적으로 전달되며, 네이티브 메모리 절차는 다음 단계가 시작되기 전에 각 단계의 정보를 메모리 상태에 저장한다. 따라서 단계 t의 파라미터 $\theta_t$ 는 앞선 모든 단계 $\{(X_t, Y_t)\}_{t < t}$ 의 메모리 상태를 이미 통합한다. 우리는 쿼리 단계의 부분 집합 $Q_s \subseteq \{1, \ldots, T_s\}$ 만 감독한다. 이 단계에서 어시스턴트 응답이 라벨링되며, 참조 및 연산 단계는 라벨이 없다. 그러나 참조 및 연산 단계의 응답은 여전히 메모리 상태 업데이트를 위해 생성되거나 제공된다. 또한 세 목표는 아래의 단계별 손실을 공유하며, 감독 대상 $Y_t$ 가 훈련 데이터에서 어떻게 구성되는지에 따라 차이가 있다. 감독 단계 $t \in Q_s$ 에 대해 단계별 손실은 토큰 평균 음의 로그우도이다.

<span id="page-15-2"></span>

$$\ell(s,t) = -\frac{1}{|Y_t|} \sum_{k=1}^{|Y_t|} \log P(y_{t,k} \mid X_t, Y_{t,< k}; \theta_t), \tag{12}$$

여기서 $Y_{t, < k}$ 는 단계 t에서 이전에 생성된 토큰을 나타내며, $\theta_t$ 는 이전 단계에 의해 형성된 메모리 상태에 조건부이다. 샘플의 손실은 감독 단계에 걸쳐 $\sum_{t \in Q_s} \ell(s, t)$ 로 집계되며, 이는 단일 궤적을 허용한다.

여러 응답을 감독한다. 중간 훈련 단계에서 백본 파라미터를 고정하고 네이티브 메모리 파라미터만 최적화한다.

세 가지 목표는 다섯 개의 데이터 하위 집합에 해당하며, 우리는 명시적 손실 계수(loss coefficients) 대신 작업 가중 샘플러(task-weighted sampler)를 통해 그 기여도를 제어한다. 훈련 에포크(epoch) e에서 하위 집합 $\tau$ 의 샘플링 확률은

$$\pi_{\tau}(e) = \frac{w_{\tau}(e)}{\sum_{\tau' \in \mathcal{T}} w_{\tau'}(e)}, \qquad w_{\tau}(e) = w_{\tau}^{s} + \left(w_{\tau}^{e} - w_{\tau}^{s}\right) \cdot \min\left(\frac{e}{E - 1}, 1\right), \tag{13}$$

여기서 $\mathcal{T}$는 부분집합들의 집합이며, E는 총 epoch 수, 그리고 $w_{\tau}^{s}$, $w_{\tau}^{e}$는 부분집합 $\tau$의 시작 및 끝 가중치이다. 이 선형 annealing은 저장 지향 데이터에서 더 어려운 장거리 및 정규화 데이터로 샘플링 질량을 점진적으로 이동시키는 커리큘럼을 형성한다. 가중치가 샘플링 빈도만 조절하기 때문에, 중간 훈련 목표의 기대값은 다음과 같이 쓸 수 있다.

$$\mathcal{L} = \sum_{\tau \in \mathcal{T}} \pi_{\tau}(e) \cdot \mathbb{E}_{s \sim \mathcal{D}_{\tau}} \left[ \sum_{t \in \mathcal{Q}_{s}} \ell(s, t) \right], \tag{14}$$

여기서 $\mathcal{D}_{\tau}$는 부분집합 $\tau$의 데이터이며, 샘플링된 각 단계는 방정식 (12)에서 가중치가 없는 손실을 기여한다.

### 5.2 메모리 재구성 목표 (Memory Reconstruction Objective)

메모리 재구성 목표는 Metis가 정보를 저장하고 재구성할 수 있게 한다. 이는 초기화된 모델이 일반적으로 갖지 못하는 기능을 제공함으로써 모델의 워밍업 단계에서 중요한 학습 신호를 제공한다. 또한, 완전 무손실 압축 및 재구성을 통해 정보 저장의 상한을 목표로 한다. 그러나 이 목표와 네이티브 메모리 절차 사이에는 트레이드오프가 존재한다. 첫째, 재구성과 지시 따르기는 각각 특수성 및 일반화를 요구하므로 모순된다. 둘째, 예측 과제 관점에서 네이티브 메모리 절차는 입력 지시에 의해 안내되는 손실 압축을 필요로 한다. 반대로 메모리 재구성은 손실 압축에 반대된다.

이 목표는 Section 4.1의 기본 데이터에서 파생된 재구성 서브셋  $\mathcal{D}_{rec}$  를 기반으로 한다. 각 샘플에서 참조 문단이 제시되고 초기 단계에서 메모리 상태에 저장되며, 이후 쿼리 단계에서는 모델이 그 내용을 재생성해야 한다. 감독된 응답  $Y_t$  가 저장된 참조를 재현하므로 메모리 상태는 최소 손실로 소스를 보존해야 한다. 우리는 이 서브셋에 대한 단계별 손실을 다음과 같이 정의한다

$$\mathcal{L}_{\text{rec}} = \pi_{\text{rec}}(e) \mathbb{E}_{s \sim \mathcal{D}_{\text{rec}}} \left[ \sum_{t \in Q_s} \ell(s, t) \right], \tag{15}$$

여기서 기대값은  $\mathcal{D}_{rec}$  에서 추출된 샘플을 평균화하며,  $\ell(s,t)$  는 쿼리 단계 t에서 저장된 내용을 재구성하는 부정 로그 가능도를 측정한다. 단계 t까지는 참조 문단이 이미  $\theta_t$  로 표현된 네이티브 메모리 상태에 저장되어 있다.  $\mathcal{L}_{rec}$  를 최소화하면 하이퍼 메모리 블록이 참조를 재구성 가능한 상태에 인코딩하도록 유도한다.

### 5.3 메모리 운영 목표 (Memory Operation Objective)

재구성이 무손실 저장을 확립하는 반면, 네이티브 메모리는 입력 주도형 연산을 추가로 지원해야 한다. 메모리 운영 목표는 Metis가 기억, 망각, 업데이트, 반영을 학습하도록 하여 메모리 상태가 각 단계에서 지시에 따라 진화하도록 한다. 이는 제어된 지시 강조와 잡음 하에서 이러한 연산을 나타내는 기본 데이터에 기반한다.

우리는 기본 데이터의 두 가지 상호 보완적인 하위 집합을 사용한다. 첫 번째 하위 집합은  $\mathcal{D}_{op}^{e/i}$  로 표시되며, 명시적 및 암시적 샘플을 포함한다. 명시적 샘플은 작업을 명확한 명령으로 표현하고, 암시적 샘플은 동일한 정보를 자연스러운 서술 안에 삽입한다. 이러한 대비는 모델이 표면 키워드가 아니라 의도에서 작업을 추론하도록 강제한다. 두 번째 하위 집합은  $\mathcal{D}_{op}^d$  로 표시되며, 참조와 질의 사이에 무관한 턴이 삽입된 방해 샘플을 포함한다. 이는 장기 보존과 중간 잡음에 대한 견고성을 촉진한다.

모든 작업 샘플에서, 감독된 응답은 이전 단계의 정보와 일관성을 유지한다. *업데이트* 샘플의 경우, 답변은 새 값을 반영하고 이전 값을 반영하지 않는다. *잊기* 샘플의 경우, 답변은 더 이상

잊혀진 값을 드러낸다. *reflect* 샘플의 경우, 답변은 여러 저장된 사실을 다중 홉 추론으로 구성한다. 따라서 단일 가능성 목표만으로 모든 연산을 감독할 수 있다, 다음과 같이

$$\mathcal{L}_{op} = \pi_{e/i}(e) \mathbb{E}_{s \sim \mathcal{D}_{op}^{e/i}} \left[ \sum_{t \in Q_s} \ell(s, t) \right] + \pi_{d}(e) \mathbb{E}_{s \sim \mathcal{D}_{op}^{d}} \left[ \sum_{t \in Q_s} \ell(s, t) \right], \tag{16}$$

여기서 $\theta_t$는 이제 이전 연산 시퀀스가 메모리 상태에 미친 순수한 효과를 인코딩한다. 재구성과 달리, 목표는 더 이상 저장된 내용의 복사본이 아니므로, 모델은 지침에 따라 메모리 상태를 변환하고 읽는 방법을 학습한다.

### 5.4 정규화 목표 (Regularization Objective)

재구성 및 운영 목표는 주로 단순 상호작용 패턴에 기반하며, 이는 복잡한 시나리오에서 모델을 취약하게 만든다. 정규화 목표는 현실적인 상호작용에서 메모리가 작동할 때 발생하는 두 가지 실패 모드를 완화한다. 첫 번째는 유사한 사실이 혼동되거나 망각 연산이 보존된 사실을 손상시키는 간섭이다. 두 번째는 저장된 값이 필요하지 않은 응답에 유출되는 메모리 오염이다 [54]. 이 목표는 Section 4.2의 보조 데이터에 기반하며, 이는 사실과 대화를 보다 복잡하고 현실적인 상호작용 패턴으로 구성한다.

우리는 보조 데이터의 두 하위 집합을 사용한다. 다중 사실(subset) $\mathcal{D}_{mf}$는 간섭을 목표로 한다. 이 집합의 다중 엔티티 바인딩 샘플은 두 개의 혼동 가능한 사실을 동시에 제시하고 모델에게 두 사실 모두에 대해 질문함으로써, 메모리 활용 절차가 각 값을 자신의 키에 바인딩하도록 제한한다. 선택적 망각 샘플은 한 사실을 취소하면서 다른 사실을 보존하는 지시를 포함하여, 망각 연산이 국소적으로 작동하도록 제한한다. 메모리 오염 $\mathcal{D}_{mp}$는 유출을 목표로 한다. 그 후 메모리 대화 샘플은 메모리 쿼리 직후 일반 대화를 이어가며, 메모리와 무관한 샘플은 메모리 상태가 존재해도 메모리가 필요 없는 질문에 답한다. 두 경우 모두 모델이 관련 없는 응답에 메모리를 주입하는 것을 억제한다.

이러한 하위 집합은 보다 현실적이고 다양한 상호작용 시나리오에서 메모리 동작을 제한함으로써 정규화 역할을 한다. 감독 대상은 교차 사실 간섭, 부수적 망각, 값 유출을 벌점으로 부여하여 항상 메모리 상태를 읽거나 덮어쓰는 퇴화된 해법을 억제한다. 우리는 목표를 다음과 같이 정의한다

$$\mathcal{L}_{\text{reg}} = \pi_{\text{mf}}(e) \mathbb{E}_{s \sim \mathcal{D}_{\text{mf}}} \left[ \sum_{t \in Q_s} \ell(s, t) \right] + \pi_{\text{mp}}(e) \mathbb{E}_{s \sim \mathcal{D}_{\text{mp}}} \left[ \sum_{t \in Q_s} \ell(s, t) \right], \tag{17}$$

여러 샘플이 다중 감독 단계를 노출하므로 $|Q_s| > 1$이 한 상호작용 내에서 보존된 사실과 취소된 사실을 동시에 제한한다. 메모리와 무관한 경우에는 감독 단계가 메모리 상태와 무관한 일반 턴이며, 그 목표는 메모리 상태와 독립적이다.

기준선. 우리는 네 가지 범주의 기준선을 대상으로 우리 접근법을 종합적으로 평가한다. 전체 정보를 문맥에 첨부하여 평가되는 백본 모델의 경우, 4B, 9B, 27B 규모의 Qwen3.5 [59]를 사용한다. 부분 문맥 기준선의 경우, 이 백본 모델에 RAG [60]를 적용한다. Temp-LoRA는 추론 시 이전 텍스트 청크에 대해 임시 LoRA 모듈을 훈련시켜 정보를 모델에 융합하며, 역사적 문맥을 일시적 파라미터 업데이트로 인코딩한다. 구체적으로, 우리는 Qwen3.5 백본의 해당 규모에 맞춰 Temp-LoRA를 구현한다. 파라메트릭 메모리 모델에 관해서는, 저차원 보정으로 주의를 조정하는 $\delta$-Mem [22]와 비교한다. 자세한 내용은 부록 E에 제공된다.

훈련 구성. 보고된 Metis 모델은 Qwen3.5 백본을 기반으로 하며 $8\times H100$ GPU에서 훈련된다. 백본은 훈련 중 고정되고, 학습 가능한 메모리 파라미터는 해당 백본 층의 키 및 값 투영 행렬을 사용해 초기화된다. 우리는 AdamW를 사용하며 학습률은 $2\times 10^{-4}$, 200 warmup 단계 이후 일정 스케줄, 가중치 감쇠 0.01, $\beta = (0.9, 0.999)$, $\epsilon = 10^{-8}$, 그리고 기울기 클리핑 1.0을 적용한다. 훈련은 BF16과 seed 42를 사용하며 2,000 스텝마다 체크포인트를 저장한다. Metis-4B의 경우 14,000 스텝(1 epoch) 동안 훈련한다. Metis-27B는 동일한 훈련 스텝 수를 사용하며 약 0.4 epoch에 해당한다. Metis-9B는 8,000 스텝(약 0.5728 epoch)을 사용하며, 이는 검증 세트 성능에 대한 조기 종료에 의해 선택된다.

평가 파이프라인. 메모리 연산 및 메모리 기반 QA 과제에 대해 우리는 정적 평가 패러다임을 채택한다. 각 테스트 경로는 두 개의 순차 단계로 나뉜다. 첫 번째 단계는 모델에 필요한 문맥을 제공하는 정보 단계이며, 두 번째 단계는 모델이 이전 정보를 바탕으로 질문에 답해야 하는 질의 단계이다. 마지막으로 평가에서는 질의 단계에서 모델의 출력과 정답을 비교해 성능 지표를 계산한다. 정보 단계와 질의 단계의 프롬프트는 부록 F.2에, LLM-as-a-Judge의 프롬프트는 부록 F.3에 제공된다.

### 6.2 전반적 성능 (Overall Performance)

메모리 연산 작업. 금속 설정(*즉*, MemOps (Gold))과 Metis 테스트 세트의 MemOps 결과가 표 5에 제시되어 있다. 페이지 제한으로 인해 MemOps의 전체 설정(*즉*, MemOps (Full)) 실험 결과와 분석은 부록 B에 넣었다. 예상대로, 전체 컨텍스트 모델이 가장 강력한 전반적 성능을 달성하며, 컨텍스트를 제거하면 표준 백본에서 상당한 성능 저하가 발생한다. 부분 컨텍스트는 Metis 테스트 세트에서 일부 정보를 보존하지만 MemOps (Gold)에서는 성능이 저하되어 불완전한 이력이 메모리 연산을 신뢰할 수 있게 지원하지 못함을 보여준다. Temp‑LoRA와 $\delta$‑Mem은 손실된 성능의 일부를 회복하지만 이들의 이득은 제한적이다. 동일한 무컨텍스트 설정에서 Metis는 MemOps (Gold)와 Metis 테스트 세트 모두에서 가장 높은 평균 결과를 달성한다. 이 결과는 Metis가 자체 네이티브 메모리 상태에서 정보를 보존하고 원래 컨텍스트를 재생하지 않고도 이후 단계에서 이를 사용할 수 있음을 시사한다.

Metis‑27B는 무컨텍스트 설정에서 두 벤치마크 모두에서 가장 높은 평균 성능을 달성한다. Metis‑4B 및 Metis‑9B와 비교하면 기억, 업데이트, 반성 및 전반적 성능에서 명확한 이득을 보인다. 특히 Metis 테스트 세트에서 망각에 대한 개선이 크게 나타난다. 이 결과는 충분히 큰 백본이 네이티브 메모리 상태를 더 잘 형성하고 활용할 수 있음을 시사한다. 또한, 망각은 외부 MemOps (Gold) 벤치마크에서 여전히 가장 어려운 연산이며, Metis‑27B에서도 마찬가지이다. 이는 공유 잠재 상태에서 정보를 제거하거나 억제하는 것이 저장하거나 업데이트하는 것보다 일반화하기 더 어렵다는 것을 시사한다…

Metis‑27B는 무컨텍스트 설정에서 두 벤치마크 모두에서 가장 높은 평균 성능을 달성한다. Metis‑4B 및 Metis‑9B와 비교하면 기억, 업데이트, 반성 및 전반적 성능에서 명확한 이득을 보인다. 특히 Metis 테스트 세트에서 망각에 대한 개선이 크게 나타난다. 이 결과는 충분히 큰 백본이 네이티브 메모리 상태를 더 잘 형성하고 활용할 수 있음을 시사한다. 또한, 망각은 외부 MemOps (Gold) 벤치마크에서 여전히 가장 어려운 연산이며, Metis‑27B에서도 마찬가지이다. 이는 공유 잠재 상태에서 정보를 제거하거나 억제하는 것이 저장하거나 업데이트하는 것보다 일반화하기 더 어렵다는 것을 시사한다. 전반적으로 Metis는 단기 시나리오에서 메모리 연산 작업에서 강력한 성능을 보인다.

메모리 기반 QA 작업. 메모리 기반 QA 작업의 결과가 표 6에 제시되어 있다. 전체 컨텍스트 모델은 원본 증거에 직접 주의를 기울일 수 있기 때문에 강력한 상한을 제공한다. 부분 컨텍스트만 사용될 때 성능이 급격히 감소한다. 컨텍스트가 없으면 원본 Qwen3.5 모델은 LoCoMo (Gold)에서 거의 0점에 가까운 점수를 얻으며, 답변이 백본 지식만으로 신뢰할 수 있게 복구될 수 없음을 확인한다. 반면 Metis는 무컨텍스트 설정에서 두 벤치마크 모두에서 가장 높은 평균 성능을 달성한다. Metis‑27B는 모든 작업 범주에서 가장 높은 점수를 얻어 다른 기준선보다 우수하다. 이 결과는 네이티브 메모리 상태가 유용한 정보를 보존하고 원본 컨텍스트를 재생하지 않고도 질문 응답을 지원할 수 있음을 보여준다.

Metis의 이점은 복잡하거나 장거리 메모리 요구가 있는 작업에서 특히 명확하다. NextMem (Contextual Generation)에서 Metis는 HotpotQA, LongMemEval, LoCoMo 하위 집합에서 큰 이득을 달성한다. 또한 LoCoMo (Gold)에서 다중 홉 및 시계열 질문 응답을 크게 개선한다. 이는 네이티브 메모리가 상대적으로 단순한 사실 질문에 대해 여전히 효과적이면서, 더 까다로운 작업에서 더 큰 이득을 제공함을 나타낸다. 시계열 질문에서의 강력한 개선은 더 큰 Metis 모델이 서로 다른 상호작용 단계에서 관계를 더 잘 보존하고 활용할 수 있음을 시사한다. 그러나 개방형 LoCoMo (Gold) 질문에서의 이득은 상대적으로 제한적이며, 이는 일부 작업 유형이 모델 용량이 증가해도 여전히 어려운 상태임을 나타낸다.

또한 Metis‑4B와 Metis‑9B 사이의 개선은 적당하지만 Metis‑27B는 평균 점수를 크게 향상시킨다. 이 패턴은 백본 스케일링이 모델 용량이 도달한 후 네이티브 메모리 기능을 향상시킬 수 있음을 시사하지만, 이득은 작업마다 균일하지 않다. 이 결과는 Metis가 단기 QA 작업과 상대적으로 긴 LoCoMo (Gold) 설정 모두에서 강력한 메모리 기반 QA 성능을 제공함을 나타낸다.

### 6.3 Ablation Studies (Ablation Studies)

우리는 훈련 데이터와 모델 구조의 관점에서 Metis-4B에 대한 ablation 연구를 수행한다. 주요 실험 설정을 따르며, 메모리 기반 QA 과제에서 LoCoMo (Gold)와 NextMem을 평가한다. 또한 메모리 연산 과제에서 Metis 테스트 세트와 MemOps (Gold)를 사용한다. 모든 ablation 모델은 Metis-4B와 동일한 훈련 구성 및 평가 파이프라인을 사용한다.

데이터 Ablation. 두 가지 변형을 통해 서로 다른 훈련 데이터의 기여도를 평가한다. w/o MS에서는 Multi-fact Scenario 데이터를 제거한다. w/o MS+MP에서는 Multi-fact와 Memory Pollution 데이터를 포함한 전체 보조 데이터 세트를 제거하여 메모리 학습과 일반화에 대한 전체적인 기여도를 살펴본다.

표 [7](#page-21-1)에 나타난 바와 같이, Multi-fact Scenario 데이터를 제거하면 두 종류의 과제 모두에서 성능이 일관되게 감소한다. 이 결과는 다중 사실 감독이 Metis가 관련 정보를 통합하고 일관된 메모리 상태를 유지하도록 돕는다는 것을 시사한다. 감소 현상은 MemOps (Gold)와 Metis 테스트 세트에서 더 뚜렷하며, 이러한 데이터가 신뢰할 수 있는 메모리 연산을 학습하는 데 특히 중요함을 암시한다. 전체 보조 데이터 세트를 제거하면 훨씬 더 큰 전반적 저하가 발생한다. 감소는 특히 Metis 테스트 세트에서 명확하며, LoCoMo (Gold)와 NextMem의 성능도 일관되게 감소한다. 이는 보조 데이터가 다양한 시나리오에서 원시 메모리 절차의 견고성과 일반화를 향상시킨다는 것을 보여준다.

구조 Ablation. 우리는 원시 메모리 절차의 주요 구성 요소를 추가로 ablate한다. w/o GDU에서는 GDU를 선형 업데이트(LU)로 교체한다. w/o SA에서는 적응형 집계 메커니즘을 제거하고 메모리 저장에 마지막 토큰의 은닉 상태를 직접 사용한다. w/o OQ에서는 최적화 가능한 메모리 쿼리 투영을 제거하고 원래 어텐션의 쿼리를 재사용한다. w/o QKN에서는 메모리 어텐션에서 쿼리-키 정규화를 제거한다.

이러한 변형 중에서 적응형 집계 제거가 가장 큰 성능 저하를 일으킨다. 마지막 토큰을 직접 사용하는 것은 입력 시퀀스에 분산된 정보를 효과적으로 포착하지 못한다. 결과적으로 모델은 유익한 메모리 상태를 구축하지 못한다. 또한 쿼리-키 정규화를 제거하면 특히 LoCoMo (Gold)와 NextMem에서 상당한 저하가 발생한다. 이 정규화가 없으면 무관한 정보가 더 강한 간섭을 유발할 수 있다. 더불어 원래 어텐션 쿼리를 재사용하는 것도 모든 벤치마크에서 성능을 감소시킨다. 감소는 메모리 기반 QA 과제에서 더 크며, 이는 별도의 메모리 쿼리가 관련 과거 정보를 잡음에서 구분하는 데 중요함을 시사한다. 이 관찰은 추가 쿼리 투영이 교차 단계 유사성을 재구성하고 무관한 메모리로부터의 간섭을 억제한다는 우리의 이론적 분석과 일치한다.

또한 GDU를 선형 업데이트로 교체하면 전체 평균에 미미한 영향을 미친다. 선형 업데이트는 MemOps (Gold)와 Metis 테스트 세트에서 약간 더 나은 성능을 보이지만, LoCoMo (Gold)에서는 명백히 약하다. 이는 선형 업데이트가 단순하고 단기 메모리 연산을 처리할 수 있는 반면, GDU는 장기 시나리오에서 더 나은 균형을 제공한다는 것을 시사한다. 이 결과는 GDU가 보다 안정적인 모델 동작을 유도할 수 있다는 우리의 엔지니어링 관찰과 일치하며, Metis에서의 사용을 동기화한다. Appendix [C](#page-33-0)에서는 9B와 27B 규모에서 LU와 GDU의 과제별 성능을 추가로 비교한다.

표 8에 나타난 바와 같이, Metis는 ATM-Bench에서 강력한 OOD 전이를 보여 주며, 모델 규모와 대부분의 질문 유형에서 메모리 기반선보다 일관되게 우수하다. 이 이점은 결정론적으로 채점된 숫자 질문에서도 유지되며, 이는 개방형 질문에 사용된 LLM 판정의 단순한 효과가 아니라는 것을 시사한다. ATM-Bench는 모델이 개인 아카이브에서 추출한 이질적 증거를 보존하고 통합하도록 요구하므로, 이러한 결과는 Metis가 학습한 본래 메모리 절차가 훈련 중 관찰된 패턴을 넘어 전이된다는 것을 암시한다. MemDaily에 대한 결과는 보다 혼재적이며, Metis는 경쟁력을 유지하지만 메모리 기반선을 지속적으로 앞서지 못한다. 두 벤치마크를 함께 보면, Metis의 본래 메모리 능력이 훈련 데이터 구축에 사용되지 않은 벤치마크에도 일반화된다는 증거를 제공한다.

### <span id="page-21-0"></span>6.5 메모리 용량 연구 (Memory Capacity Studies)

이 부분에서는 Metis의 장기 메모리 능력을 추가로 탐구한다. 우리는 메모리 용량을 모델링함으로써 이 능력을 평가한다. 메모리 용량은 단계 수준(step-level)과 궤적 수준(trajectory-level)으로 구성된다. 구체적으로, 단계 수준 용량은 단일 업데이트 내에 수용 가능한 최대 토큰 수를 의미한다. 반면, 궤적 수준 용량은 상호작용 궤적 내에서 최대 업데이트 단계 수를 나타낸다.

우리는 40개의 독립적이고 원자적인 페르소나 도메인으로 정의된 공유 스키마 위에 20개의 가상 사용자를 포함하는 테스트 데이터셋을 구축한다. 먼저, 모델은 인구통계, 교육, 관계 등과 같은 40개의 세분화된 도메인을 생성한다. 그 다음, 각 사용자에 대해 도메인들을 고정된 시드로 섞어 순차적으로 인스턴스화한다. 이전에 생성된 속성들은 각 페르소나 내에서 논리적 일관성을 보장하기 위해 불변의 컨텍스트로 제공된다. 각 속성은 처음에 전체 페르소나를 조건으로 한 전기 스타일 문장으로 확장된다. 이후, 각 도메인마다 하나의 직접적인 질문이 생성되어 모든 사용자에게 재사용된다. 마지막으로, 각 전기 스타일 메시지는 해당 사실만을 표현하는 간결한 1인칭 진술문으로 다시 작성된다. 평가 과정에서 각 사용자의 40개 기록은 순차적 궤적을 형성한다. 진술문은 순차적으로 메모리에 저장되고, 쿼리는 모델을 탐지하는 데 사용된다. 또한, 사용자 속성은 LLM 기반 판단의 정답(gold answer) 역할을 한다. 이 데이터셋을 바탕으로 우리는 두 가지 평가 설정에서 Qwen3.5-4B(전체 컨텍스트 사용)와 Metis-4B의 성능을 비교한다.

단계별 용량. 이 설정은 모델이 단일 메모리 안에 얼마나 많은 정보를 인코딩할 수 있는지를 평가한다.

단계 수준 설정에서는 Metis가 단일 업데이트에 소량의 정보만 포함될 때 잘 동작하지만, 입력이 길어질수록 정확도가 급격히 감소한다. 첫 번째 사실에 대한 성능은 가장 뚜렷한 하향 추세를 보이며, 중간 및 마지막 사실은 더 큰 변동성을 나타낸다. 입력이 수백 단어를 초과하면 세 위치 모두 성능이 낮아진다. 반면, 전체 컨텍스트 기반 기준은 특히 첫 번째 사실에서 훨씬 강력한 성능을 유지한다.

트레젝터리 수준 용량. 이 설정은 모델이 메모리 업데이트 시퀀스에서 얼마나 많은 정보를 보존할 수 있는지를 평가한다. 각 사용자마다 메모리 상태는 한 번만 초기화되고 이후 트레젝터리 전체에 걸쳐 누적된다. 40개의 진술은 기본적으로 5개씩 연속 그룹으로 나뉘며, 각 그룹은 Metis에 순차적으로 연결·업데이트된다. 그룹 수준 업데이트마다 모델은 첫 번째, 중간, 현재 업데이트된 사실에 대해 질의된다. 이 설정은 반복 업데이트 하에서 진화하는 메모리 상태의 용량을 측정하며, 성능은 업데이트된 트레젝터리 단계 수에 따라 보고된다. 결과는 Figure [3](#page-22-0) (오른쪽)에 제시된다.

트레젝터리 수준 설정에서도 업데이트 단계 수가 증가함에 따라 성능이 감소한다. 첫 번째 사실의 정확도는 거의 연속적으로 감소하여 초기 정보가 이후 업데이트에 의해 점진적으로 약화되는 것을 보여준다. 중간 및 최신 사실 역시 불안정하게 유지되며, 이는 새로운 업데이트가 가장 오래된 정보만 덮어쓰는 것이 아니라 전체 메모리 상태에 걸쳐 간섭을 일으킨다는 것을 시사한다. 각 업데이트의 정보량이 고정되어 있음에도 불구하고, 트레젝터리가 길어질수록 성능이 명확히 떨어진다. 이는 반복적인 상태 전이와 누적된 압축 오류가 네이티브 메모리의 또 다른 주요 한계를 형성함을 확인시켜 준다.

### 6.6 일반 역량 연구 (General Capability Studies)

이전 실험에서는 메모리 관련 과제에서 Metis의 효과가 입증되었다. 그러나 네이티브 메모리를 순방향 계산에 통합하면 백본의 원래 동작에 영향을 미칠 수 있어 일반적인 성능이 감소할 가능성이 있다. 본 절에서는 Metis가 원래 백본과 비교해 일반 과제에서 어떻게 수행되는지 추가로 탐구한다. Metis-4B와 Qwen3.5-4B를 비교하고 두 모델 간의 성능 차이를 보고한다. 구체적으로, Metis의 일반 역량을 서로 다른 단계에서 평가하기 위해 두 가지 설정을 설계하였다. 첫 번째는 초기 단계(Initial Stage)로, 메모리에 어떠한 정보도 저장되기 전, 즉 step = 1에 해당하는 일반 과제에서의 성능을 측정한다. 이 설정에서 Metis는 벤치마크에서 원래 프롬프트를 받기 전에 빈 메모리 상태로 초기화되고, 백본은 동일한 프롬프트를 받는다. 두 번째는 활성 단계(Active Stage)로, 이전 상호작용 단계에서 무관한 정보를 축적한 후 Metis를 평가한다. 여기서 step > 1이다. Metis의 경우, 메모리 상태를 초기화하고 벤치마크 프롬프트를 제공하기 전에 작업과 무관한 메시지를 저장한다. 백본의 경우, 동일한 메시지를 프롬프트 앞에 덧붙인다. 우리의 실험은 MMLU-Pro [&#91;64&#93;](#page-29-13), IFEval [&#91;65&#93;](#page-29-14), GSM8K [&#91;66&#93;](#page-29-15), 그리고 MMMLU [&#91;67&#93;](#page-29-16)에서 수행된다.

### 6.7 저차원 분해 (Low-rank Decomposition)

저장 오버헤드는 메모리 효율성의 핵심 지표이다. 제한된 정보를 가진 단기 과제에서는 파라메트릭 메모리 표현을 추가로 압축할 수 있다. 따라서 Metis의 저장 최적화 잠재력을 탐색하기 위해, 우리는 메모리 상태에 저차원 분해를 적용하여 효율적으로 저장하고 메모리 활용 전에 재구성한다. 구체적으로, 메모리 상태 $\mathbf{M}_t^{(l)}$를 FP32로 캐스팅하고 마지막 두 차원에 대해 SVD를 계산한다. 따라서 보존된 랭크 k에 대해 분해 과정은 다음과 같이 표현될 수 있다

$$\mathbf{M}_t^{(l)} = \mathbf{U}_t^{(l)} \boldsymbol{\Sigma}_t^{(l)} \mathbf{V}_t^{(l) \top}.$$

우리는 원래 전체 랭크 인자를 대신하여 저차원 근사 $\hat{\mathbf{U}}_t^{(l)} = \mathbf{U}_{t,:,1:k}^{(l)}, \hat{\boldsymbol{\Sigma}}_t^{(l)} = \boldsymbol{\Sigma}_{t,1:k,1:k}^{(l)}$, 그리고 $\hat{\mathbf{V}}_t^{(l)} = \mathbf{V}_{t,:,1:k}^{(l)}$를 유지한다. 여기서 $\mathbf{U}_{t,:,1:k}^{(l)$와 $\mathbf{V}_{t,:,1:k}^{(l)}$는 각각 $\mathbf{U}_t^{(l)}$와 $\mathbf{V}_t^{(l)}$의 처음 k 열을 나타내며, $\boldsymbol{\Sigma}_{t,1:k,1:k}^{(l)}$는 $\boldsymbol{\Sigma}_t^{(l)}$의 선두 $k \times k$ 대각 하위 행렬을 의미한다. 그 다음 재구성은 다음과 같이 표현된다

$$\hat{\mathbf{M}}_{t}^{(l)} = \hat{\mathbf{U}}_{t}^{(l)} \hat{\boldsymbol{\Sigma}}_{t}^{(l)} \hat{\mathbf{V}}_{t}^{(l)\top}.$$

우리는 $k \in \{1, 4, 16, 64, 128, 256\}$를 Metis-4B와 Section 6.2에 맞춰 네 가지 벤치마크에서 평가한다. 이 모델들을 저차원 메모리 상태를 가진 원래 Metis 모델과 비교하여 성능 저하 추세를 특성화한다. 전체 메모리 상태 차원은 1024이다. 결과는 Figure 4에 제시되며, 보존된 랭크가 증가함에 따라 명확한 추세가 나타난다. 1과 4와 같은 극히 낮은 랭크는 상당한 성능 저하를 초래한다. 이는 소수의 특이 방향이 메모리 상태에 저장된 의미 정보를 보존하기에 충분하지 않음을 시사한다. 랭크가 16으로 증가하면 성능이 급격히 향상되고, 랭크 64에서는 전체 랭크 모델에 근접한다. 랭크를 64에서 256으로 더 증가시켜도 거의 추가 개선이 없다. 이러한 결과는 메모리 상태에 유용한 정보가 주로 상대적으로 낮은 차원 서브스페이스에 집중되어 있음을 시사한다.

Table 10은 서로 다른 데이터셋에서 낮은 랭크 분해에 대한 민감도를 추가로 보여준다. 결과는 서로 다른 벤치마크가 공격적인 낮은 랭크 압축에 대해 서로 다른 수준의 민감도를 보인다는 것을 나타낸다. 매우 작은 랭크에서는 모든 데이터셋에서 성능이 명확히 감소한다. 감소는 Metis 테스트 세트와 MemOps(Gold)에서 특히 크며, 이는 메모리 연산 작업이 연산 관련 정보를 보존하기 위해 충분한 표현 용량을 필요로 함을 시사한다. MemOps(Gold)는 k=16에서 전체 랭크 성능을 회복하고 더 큰 랭크에서도 안정적이다. 반면 Metis 테스트 세트는 계속해서 개선된다.

### 6.8 사례 연구 (Case Studies)

우리는 다양한 시나리오에서 Metis-4B의 동작을 보여주기 위해 정성적 사례 연구를 수행한다. 각 턴에서 모델은 먼저 현재 입력과 기존 메모리를 기반으로 응답을 생성한 뒤, 사용자 입력을 메모리 상태에 업데이트한다. 우리는 Figure [5](#page-25-0)에 몇 가지 대표 사례를 제시하여 Metis-4B의 네이티브 메모리 동작을 정성적으로 검토한다. 각 사례는 빈 네이티브 메모리 상태에서 시작하며, 모델은 이전 상호작용 단계에서 저장된 정보를 사용해야 한다. 기억 사례에서 Metis는 Alice의 음식 선호도를 정확히 저장하고 이후 쿼리에서 이를 검색한다. 다중 사실 사례에서 모델은 Alice에 관한 여러 속성을 보존하고 다른 속성이 도입된 후 그녀의 나이를 올바르게 선택한다. 이 결과는 Metis가 서로 다른 값을 해당 속성에 바인딩하고 관련 사실 간의 간섭을 줄일 수 있음을 시사한다. 방해 사례는 무관한 대화 턴이 저장된 선호도를 덮어쓰지 않음을 추가로 보여준다. 따라서 Metis는 유용한 메모리를 일반 대화 내용과 구분할 수 있다.

망각 사례는 네이티브 메모리 상태가 단순히 추가만 되는 것이 아님을 보여준다. 망각 지시를 받은 후 Metis는 이후 쿼리에서 제거된 선호도를 더 이상 제공하지 않는다. 이는 모델이 지시의 의미적 의도에 따라 잠재 메모리 상태를 수정할 수 있음을 시사한다. 그러나 망각 지시에 대한 즉각적인 응답은 여전히 이전 사실을 반복하며 제거를 명시적으로 확인하지 않는다. 최종 메모리 상태는 정확하지만, 동작 단계에서의 응답은 의도된 메모리 동작과 완전히 일치하지 않는다. 이 행동은 현재 단계가 이전 메모리 상태를 과도하게 강조하기 때문일 수 있다. 전반적으로 이러한 사례는 Metis의 효과를 보여주지만, 일관성 측면에서 개선의 여지가 있음을 드러낸다.

### 7.1 LLM 및 에이전트의 메모리 (Memory of LLMs and Agents)

최근 몇 년간, 대규모 기초 모델과 에이전트는 개인 비서[&#91;60,](#page-29-9) [63&#93;](#page-29-12), 심층 연구[&#91;68–](#page-29-17)[70&#93;](#page-29-18), 그리고 코딩 에이전트[&#91;3–](#page-26-2)[5&#93;](#page-26-3)와 같은 분야에 널리 적용되고 있다. 이러한 시스템의 핵심 역량은 메모리이며, 이는 과거 정보를 저장해 향후 추론을 지원한다[&#91;9&#93;](#page-26-6). 그들의 표현 형태를 기반으로, 대규모

기초 모델과 에이전트는 일반적으로 텍스트 메모리, 잠재 메모리, 파라메트릭 메모리의 세 가지 유형으로 분류된다 [9, 10]. 텍스트 메모리는 일반적으로 정보를 텍스트로 표현하며, 저장 및 검색을 위해 RAG를 활용한다. 이러한 방법들은 In-Context Learning (ICL) [71]에 의해 백본이 추론을 지원하도록 정보를 제공한다. 예를 들어, MemoryBank [11]은 사용자와의 과거 대화를 유지하기 위해 듀얼 타워 밀집 검색을 갖춘 계층적 저장 접근 방식을 제안한다. MemTree [72]는 정보의 추상화 수준을 모델링하기 위해 트리 구조의 메모리 메커니즘을 설계하며, 이는 의미적 임베딩에 따라 동적으로 업데이트된다. 반대로, 잠재 메모리는 모델의 중간 활성화를 통해 메모리를 포착한다. 예를 들어, NextMem [56]은 자기회귀 오토인코더를 통해 사실적 메모리를 잠재 표현으로 압축하고, MemGen [21]은 추론 과정에 엮이는 잠재 메모리 토큰을 생성한다. 또한, 파라메트릭 메모리는 내부 모델 파라미터에 지식을 주입한다. 예를 들어, Locas [73]은 FFN을 소프트 룩업 테이블로 보고, 우회 FFN을 추가함으로써 키-값 관점에서 테스트 시점 정보를 저장한다. 또한, 지식 편집은 파라메트릭 메모리 방법으로 간주될 수 있다 [9]. ROME [50]은 투영 행렬을 연관 메모리로 간주하고, 랭크-원 업데이트를 통해 새로운 사실적 연관을 삽입한다. 산업계에서는 텍스트 메모리가 여전히 가장 효과적인 접근 방식이지만, 잠재 메모리와 파라메트릭 메모리는 유망한 연구 방향으로 부상하고 있다.

### 7.2 빠른 가중치 프로그래밍 (Fast Weight Programming)

최근, FWP는 광범위한 관심을 끌고 있다. 이 패러다임은 훈련 중에 학습된 파라미터(즉, 느린 가중치)를 사용함과 동시에 추론 시에 시퀀스에 종속적인 정보를 포착하기 위해 동적 파라미터(즉, 빠른 가중치)를 유지한다 [18]. 이 분야의 기존 방법들은 일반적으로 몇 가지 주요 방향을 따른다. 선형 어텐션은 소프트맥스 커널을 피처 맵으로 대체하여 선형 복잡도와 재귀 상태를 달성한다 [74]. 또한, 선형 트랜스포머는 비밀리에 빠른 가중치 프로그래머임이 입증되었다 [75]. 이후 연구들은 업데이트 규칙을 풍부하게 하며, 예를 들어 RetNet [76]과 RWKV [77]가 있다. 또한, 상태 공간 모델은 선형 시간 계산으로 시퀀스를 고정 크기의 재귀 상태로 압축한다. 예를 들어 S4 [78]와 Mamba [79]가 있으며, Mamba-2 [80]는 상태 공간 모델과 어텐션 사이의 이중성을 더욱 드러낸다. TTT는 또한 재귀 상태를 추론 중에 자기 지도 경사 하강법으로 최적화되는 빠른 가중치로 간주한다. 예를 들어 TTT 레이어 [81]와 Titans [82]가 있다.

### 7.3 메모리 증강 신경망 (Memory-Augmented Neural Networks)

MANNs는 추론 시 모델이 작업별 정보를 저장하고 검색하는 능력을 향상시키기 위해 명시적 메모리 모듈을 도입한다. 초기 연구로는 Memory Networks [&#91;83&#93;](#page-30-12)와 Neural Turing Machines [&#91;19&#93;](#page-27-7)가 있으며, 이들은 외부 메모리를 신경 컨트롤러에 추가하고 메모리 슬롯에 대한 미분 가능한 읽기 및 쓰기 연산을 학습한다. 이러한 방법은 신경 모델이 비모수적 메모리를 사용하여 연관 회상, 알고리즘적 추론, 소수 샷 적응을 지원할 수 있음을 보여준다. 그러나 그들의 메모리는 보통 별도의 저장 모듈로 유지되며, 메모리 절차는 종종 백본 계산과 독립적으로 설계된다. 최근 모델은 재귀 메모리 [&#91;84&#93;](#page-30-13)와 같은 추론 중에 동적 상태를 유지한다. 훈련 중에 학습된 정적 모델 파라미터와 달리, 이러한 동적 상태는 현재 입력 시퀀스에 따라 업데이트되며 시간에 따라 변하는 정보를 포착한다. 우리의 연구는 이 일반적인 방향을 따르지만, 메모리 저장 및 활용을 모델 계산에 직접 통합하는 데 초점을 맞추어, 모델이 시퀀스에 따라 의존하는 정보를 보다 자연스럽게 유지할 수 있도록 한다.

## <span id="page-26-9"></span>8 결론 (Conclusion)

본 논문에서는 메모리 기반 모델을 소개하고, 메모리 상태와 메모리 절차를 기반으로 한 네이티브 메모리의 공식 정의를 제시한다. 이 정의를 바탕으로 메모리 기반 모델의 최초 프로토타입인 Metis를 제안한다. Metis 블록은 로컬 메모리 블록과 하이퍼 메모리 블록으로 구성되어, 모델이 상호작용 단계 전반에 걸쳐 압축된 조밀 메모리 상태를 유지하고 현재 입력 및 생성된 응답에 따라 이를 업데이트할 수 있도록 한다. 또한 공개 벤치마크에서 메모리 전용 데이터셋을 구축하고, 메모리 재구성, 메모리 연산, 정규화 목표를 포함한 중간 훈련 프레임워크를 설계한다. 우리의 실험은 Metis의 효과를 검증하고, 다각적인 관점에서 그 동작을 분석한다.

이러한 유망한 결과에도 불구하고, Metis는 여전히 메모리 기반 모델로 가는 초기 단계이다. 현재의 네이티브 메모리 상태는 정보를 고정 크기의 잠재 파라미터에 압축하므로, 극히 장기 시나리오에서 성능이 저하될 수 있으며, 의미적으로 유사한 사실이 잠재 공간에서 때때로 혼동될 수 있다. 따라서 네이티브 메모리는 외부 메모리를 완전히 대체하는 것으로 볼 수 없다. 대신, 우리는 이것이 보다 효율적이고 최적화 가능하며 깊이 통합된 메모리 기능을 갖춘 미래의 기반 모델을 구축하기 위한 보완적 방향을 열어준다고 믿는다. 향후 연구는 메모리 용량, 제어 가능성, 해석 가능성을 더욱 향상시키고, 네이티브와 외부 메모리를 결합한 하이브리드 시스템을 탐색하며, 네이티브 메모리 훈련을 더 넓은 도메인과 더 긴 상호작용으로 확장할 수 있다.

우리는 메모리 기반 모델의 초기 탐구를 제시한다. 메모리를 외부 정보 관리 모듈에서 지속적인 내부 상태로 변환하여, 메모리 저장 및 활용을 모델의 순방향 계산에 직접 통합한다. 네이티브 메모리의 중요성은 정보 보존 능력 향상을 넘어선다. 장기적으로는 계산 패러다임, 학습 과정, 인지 구조, 그리고 기반 모델의 능력 개발을 재구성할 수 있다. 그림 6(Figure [6](#page-31-0))에 나타난 바와 같이, 우리는 메모리 기반 모델 개발에서 다섯 단계의 진보적 능력 수준을 상상한다: 상태 기반 기능(stateful capability), 자기 관리 기능(self-managing capability), 경험 학습 기능(experience-learning capability), 지속적 인지 기능(persistent cognitive capability), 그리고 자기 진화 기능(self-evolving capability). 이 능력들은 메모리가 지속적 상태에서 자율적 메모리 조직, 경험 기반 학습, 지속적 인지, 그리고 지속적인 능력 진화로 점진적으로 통합되는 방식을 특징짓는다.

<span id="page-31-0"></span>![](2026-08-01-2607.26760-metis-memory-foundation-model/_page_31_Figure_2.jpeg)

그림 6 메모리 기반 모델의 로드맵. 네이티브 메모리는 기반 모델을 무상태 예측기에서 상태 기반 학습자(stateful learner)로, 궁극적으로는 지속적인 자기 진화가 가능한 모델로 점진적으로 변환시키는 것을 목표로 한다. 다섯 가지 능력은 모델의 계산, 메모리 조직, 학습 과정, 인지 표현, 그리고 능력 형성에 점점 더 깊은 변화를 나타낸다. 이들의 개발은 메모리 아키텍처, 학습 목표, 확장 가능한 훈련, 해석 가능성 및 제어, 그리고 장기 평가의 진보에 의해 지원된다.

레벨 I: 상태 기반 기능. 대부분의 기존 기반 모델은 본질적으로 무상태 조건부 예측기이다. 각 추론 단계에서 그들의 출력은 고정된 모델 파라미터와 현재 컨텍스트에 의해 결정되며, 상호작용 간 연속성은 주로 과거 정보를 외부 컨텍스트로 반복 제공함으로써 유지된다. 따라서 첫 번째 수준은 정적 함수에서 지속적 상태로의 전환이다. 메모리 기반 모델은 추론 단계마다 동적 내부 상태를 유지한다. 그 출력은 현재 입력과 이전 상태에 의해 공동으로 결정되며, 각 상호작용은 이후 계산에 사용되는 상태를 업데이트한다:

$$(Y_t, \mathbf{M}_{t+1}) = f_{\Phi}(X_t, \mathbf{M}_t),$$

여기서 Φ는 정적 모델 파라미터를, **M**은 단계에서의 네이티브 메모리 상태를 나타낸다. 외부에서 제공되는 텍스트 컨텍스트와 달리 **M**은 모델 내부 계산과 직접 결합되어 상호작용 중에 지속적으로 진화한다. 이 전환은 기반 모델의 기본 계산 단위를 변화시킨다. 모델은 더 이상 입력과 출력을 단순히 정적 매핑하는 것이 아니라, 시간이 지남에 따라 진화하는 상태 기반 계산 시스템이 된다.

레벨 II: 자기 관리 기능. 지속적 상태를 보유하는 것만으로는 완전한 메모리 기능이 성립되지 않는다. 실제 환경에서 관측되는 정보는 중요성, 유효성, 추상화 수준, 시간 규모, 보안 요구사항 등에서 차이가 있다. 따라서 모델은 내부 상태를 자율적으로 조직하고 유지하는 방법을 학습해야 한다. 두 번째 수준은 지속적 상태에서 학습된 메모리 수명 주기로 전환된다. 모델은 입력되는 정보의 의미, 예상되는 미래 활용도, 적용 가능한 프라이버시 및 안전 제약에 따라 기억할 것, 업데이트할 것, 통합할 것, 잊을 것을 결정해야 한다. 이 수준에서 메모리 연산은 더 이상 주로 외부 규칙이나 이산 워크플로우를 통해 구현되지 않는다. 대신 메모리 상태와 이를 변형하는 절차가 모두 네이티브, 학습 가능한 구성 요소가 되어 기반 모델 내에서 메모리를 선택, 조직, 진화시킬 수 있게 된다.

레벨 III: 경험-학습 능력.  
모델이 자율적으로 메모리를 유지할 수 있게 되면, 메모리의 역할은 정보 지원에서 능력 적응으로 확장될 수 있다.  
모델은 일어난 일을 기억할 뿐 아니라, 그 경험의 결과로 변해야 한다.  
세 번째 수준은 메모리 활용에서 경험 기반 학습으로의 전환을 의미한다.  
상호작용 기록은 모델이 표현, 지식, 행동 규칙을 정제하는 데 활용할 수 있는 보상 신호가 된다.  
성공, 실패, 피드백, 환경 변화와 관련된 경험은 고립된 기록이 아니라 재사용 가능한 내부 능력으로 변환될 수 있다.  
이 방향은 사전 학습, 인컨텍스트 학습, 테스트 시점 적응, 지속적 학습을 통합된 프레임워크 안에서 점진적으로 연결할 수 있다.  
훈련 후 완전히 고정되는 대신, 기초 모델은 이전에 획득한 능력을 보존하면서 새로운 사용자, 작업, 환경에 지속적으로 적응할 수 있다.

레벨 IV: 지속적인 인지 능력.  
경험 학습은 모델이 상호작용을 통해 적응하는 방식을 설명하지만, 보다 고급 인공지능은 구조화되고 지속적으로 업데이트되는 내부 인지를 형성해야 한다.  
다음 단계는 축적된 경험에서 지속적인 내부 모델로 전환된다.  
기초 모델은 세계, 사용자, 작업, 시간, 그리고 자신에 대한 진화하는 표현을 유지해야 한다.  
이러한 표현은 시간적 변화, 인과 관계, 불확실성, 새로운 증거와 기존 신념 사이의 충돌을 포착해야 한다.  
환경이 변할 때, 모델은 전역 일관성을 유지하면서 내부 표현을 수정할 수 있어야 한다.  
이 단계에서 메모리는 더 이상 단절된 과거 정보 조각으로 구성되지 않는다.  
메모리는 모델이 장기간에 걸쳐 인지 연속성을 유지하는 기반이 된다.  
계획, 개인화, 복잡한 의사결정은 이 능력의 하위 표현으로 나타날 수 있지만, 정의적인 변환은 외부 에이전트 워크플로우가 아니라 기초 모델 내부 인지 표현 안에서 일어난다.

레벨 V: 자가 진화 능력.  
메모리 기반 기초 모델의 장기 목표는 축적된 경험을 모델 자체의 지속적인 능력 개발로 전환하는 것이다.  
모델은 현재 상태를 적응시키는 것뿐 아니라, 과거 경험을 반성하고 추상화하며 재구성하여 새로운 지식 구조와 학습 전략을 발견해야 한다.  
최종 단계는 지역적 적응에서 개방형 능력 진화로의 전환을 의미한다.  
모델은 장기적 가치를 지닌 경험을 식별하고, 특정 상호작용에서 전이 가능한 지식을 추상화하며, 그 결과 인사이트를 향후 학습에 통합한다.  
그 후, 탐색과 활용은 메모리 기반 기초 모델과 환경 사이의 지속적인 피드백 루프를 형성한다.

전망. 메모리 기반 기초 모델은 더 강력한 저장 모듈이 장착된 기존 기초 모델로 보아서는 안 된다.  
이들은 기초 모델 패러다임의 보다 근본적인 변화를 가리킨다.  
이 관점에서 메모리는 계산, 학습, 인지, 지속적 자기 진화를 연결하는 기초 메커니즘이 될 수 있다.

### **가능한 패러다임 전환**

기초 모델은 무상태 예측기에서 상태를 가진 학습자로 진화하고, 궁극적으로는 메모리를 자율적으로 조직하고 지속적인 인지를 유지하며, 축적된 경험을 통해 새로운 능력을 개발하는 학습 시스템이 될 수 있다.

# <span id="page-33-0"></span>C 업데이트 설계(모델 규모별) (C Update Designs across Model Scales)

섹션 [6.3](#page-20-0)에서 논의한 바와 같이, GDN 기반 업데이트를 선형 업데이트로 대체하면 4B 규모에서 경쟁력 있는 성능을 얻는다. 본 부분에서는 9B와 27B 규모에서의 성능을 추가로 탐구한다. 훈련 단계에서 Metis-9B LU는 검증 곡선에서 급격한 변동을 보이지 않아 조기 중단 없이 14k 스텝까지 훈련되었다. 보고된 Metis-9B GDU 결과는 8k 체크포인트를 기준으로 한다.

# D Llama Backbone로의 전이 (D Transfer to a Llama Backbone)

구조적으로 Metis는 네이티브 메모리 컴포넌트를 해당 Transformer 층에 통합함으로써 다양한 호환 가능한 causal decoder‑only Transformer 백본에 원칙적으로 적용될 수 있다. 주요 실험이 Qwen3.5 백본을 사용하므로, 우리는 Metis를 Llama‑3.1‑8B에 적용하여 이 구조적 유연성을 테스트한다.

설정. 우리는 Llama‑3.1‑8B를 백본으로 사용하고, 주요 실험과 동일한 훈련 및 평가 설정을 따르며 모델을 14,000 스텝 동안 훈련한다. 평가는 주요 실험과 동일한 벤치마크 데이터셋을 사용한다. 우리는 결과 모델을 동일한 Llama 백본을 사용한 no‑context 및 full‑context 조건과, 주요 평가에서의 Qwen3.5 기반 Metis‑4B 및 Metis‑9B 결과와 비교한다.

결과. 표 [13](#page-34-1)에 나타난 바와 같이 Metis (Llama‑3.1‑8B)는 주요 실험과 동일한 전반적 패턴을 보인다: 네 개의 벤치마크에서 Llama no‑context 제어를 능가하지만 여전히 full‑context 제어를 따라간다. 또한 두 Qwen 기반 Metis 변형보다 약간 높은 Overall 점수를 달성한다. 그러나 이 이점은 작업마다 일관되지 않는다: Llama 기반 변형은 LoCoMo (Gold)와 Metis 테스트 세트에서 두 Qwen 기반 변형을 능가하지만 NextMem 및 MemOps (Gold)에서는 두 변형보다 성능이 떨어진다. 이러한 작업‑종속적 분기점은 프레임워크가 성공적으로 전이되더라도 백본 선택이 작업 수준의 성능 프로필을 형성함을 시사하며, 백본 독립적 행동이나 보편적 우월성을 암시하지 않으면서 모델 계통 전반에 걸친 적용 가능성을 지원한다.

# <span id="page-34-0"></span>E 평가 구현 세부사항 (E Evaluation Implementation Details)

DenseRAG. 우리는 현재 테스트 인스턴스에 보이는 컨텍스트만으로 검색 코퍼스를 구성한다. 컨텍스트는 문장 경계에서 분할되며, 256 임베딩‑모델 토큰을 초과하는 문장은 연속적인 청크로 추가 분할된다. 검색은 코사인 유사도를 통해 수행되며, 상위 5개의 청크가 해당 Qwen3.5‑4B, 9B, 또는 27B 생성기에 제공된다. 골드 답변, 증거 식별자, 미래 턴은 검색 코퍼스에 포함되지 않는다.

Temp‑LoRA. 공식 저장소의 raw‑text 적응 설계를 따라, 우리는 Qwen3.5‑4B, 9B, 27B용 Temp‑LoRA의 공식‑유사 메모리‑작업 적응을 구현한다. 각 테스트 인스턴스마다 LoRA와 옵티마이저를 재설정하고, 각 메모리 스텝을 4,096 토큰(보고된 벤치마크에 충분)으로 제한하고 1,024 토큰 청크로 분할한다. 우리는 BF16에서 배치 크기 1, AdamW(학습률 5 × 10−<sup>5</sup>, 가중치 감쇠 0, 스케줄러 없음)으로 청크당 두 번 업데이트를 수행한다. LoRA는 rank 64, 스케일링 팩터 64, 드롭아웃 0.05를 사용하며, 어텐션 및 피드‑포워드 프로젝션에 적용된다. 그 매개변수와 옵티마이저 상태는 인스턴스 내에서 지속되며, 다음 인스턴스 전에 폐기된다.

-Mem. 우리는 공식적으로 공개된 delta‑mem_qwen3_4b‑instruct 어댑터와 Qwen3‑4B‑Instruct‑2507 백본, 공식 -Mem 런타임을 사용한다. 각 원시 메모리 스텝은 별도의 사용자 메시지로 입력된다. 질문‑전용 쿼리를 발행하기 전에 온라인 -Mem 상태만 보유하고 채팅 기록, 처리된 입력 ID, KV 캐시를 비운다. 각 인스턴스 전에 -Mem을 재설정한다.

Metis. 우리는 각 인스턴스 전에 Metis를 빈 LocalMemory 상태로 재설정한다. 쿼리 단계에서는 Metis가 질문 프롬프트만 받는다.

### 사용자 지침 (User Instruction)



질문에 대해 model_output을 gold_answer와 비교하여 평가한다. JSON 형태로 반환하며, 키는 다음과 같다: score(0~1), pass(불리언), matched_points(문자열 배열), missed_points(문자열 배열), rationale(짧은 문자열). 엄격한 평가 기준을 사용한다: 답변이 요청된 핵심 개체/값/날짜/관계(동의어 및 의미상 동등 표현 허용)를 포함할 때만 1.0을 부여한다. 핵심 답변은 포함하지만 약간의 부가 문구, 사소한 부정확성, 혹은 한 가지 부수적 누락이 있을 경우 0.5~0.75를 부여한다. 다른 인물, 조직, 장소, 숫자, 날짜, 제목, 관계, 혹은 답변 선택지가 다르거나, gold answer이 특정 개체인 경우 일반 범주를 제시하거나, gold과 단순히 공통어를 공유하거나, 정확한 답을 뒷받침하지 않는 그럴듯한 추측, 또는 모델이 답이 없다고 말하면서 gold이 답변 가능한 경우에는 0을 부여한다. 최종 답변이 틀렸다면 설명의 질을 보상하지 않는다. 질문이 국가/주/형태를 묻고 모델이 정확히 그 국가/주/형태를 제시하면, 세계 지식으로 추측 가능하더라도 정답으로 간주한다.

# <span id="page-38-0"></span>일반 능력 연구에서의 프롬프트 (Prompts in General Capability Study)

# G 효율성 (Efficiency)

본 부록은 4B 규모에서 Metis의 추론 효율성을 평가하며, 네이티브 메모리의 이점과 도입되는 비용을 모두 파악한다. 먼저 LoCoMo (Gold)에서 애플리케이션 수준의 종단 간 및 쿼리 지연 시간을 측정한다. 또한 512에서 128K 컨텍스트 토큰에 걸친 제어된 스윕을 통해 히스토리 효과를 분리하고, 지연 시간을 세분화된 단계별 구성 요소로 분해한다. 마지막으로 지연 시간 외에, 고정 크기 메모리 상태를 유지하는 저장 효율성을 조사하며, 히스토리가 증가함에 따라 각 방법이 세션당 유지해야 하는 저장량을 측정한다.

### G.1 LoCoMo (Gold)에서의 종단 간 지연 시간

평가 프로토콜. 우리는 Section 6에 서술된 기준 구성을 따라 LoCoMo (Gold) 증거 세션 설정에서 1,527개의 예제를 대상으로 모든 방법을 평가한다. 각 예제는 콜드 스타트 프로토콜 하에서 독립적으로 평가된다: 방법별 상태가 초기화되고, 증거 세션이 처리되며, 이후 질문에 답변하지만 예제 간에 상태를 재사용하지 않는다. 모든 방법은 최대 96개의 토큰을 생성하는 그리디 디코딩을 사용한다. 각 실행은 측정되지 않은 워밍업 예제를 하나 포함하며, CUDA 동기화는 모든 타이밍 경계에서 적용된다. 종단 간 지연 시간은 검색, 테스트 시 적응, 필요 시 메모리 기록을 포함하고, 그 뒤에 쿼리 생성을 따른다. 쿼리 지연 시간은 이러한 준비 작업이 완료된 후 시작된다. 모델 로딩 및 답변 평가는 제외된다. 생성이 자연스러운 정지 동작을 사용하므로, 결과는 제어된 디코드 전용 지연 시간 대신 애플리케이션 수준 지연 시간을 측정한다.

결과. Partial Context는 과거 정보를 사용하는 방법 중에서 가장 낮은 종단 간 지연 시간을 보이며, 평균 0.268초, P95는 0.456초이다. Metis는 평균 지연 시간을 0.562초로 달성하며, 이는 Full Context의 0.607초보다 약간 낮으며, P95 지연 시간을 3.012초에서 0.926초로 감소시켜 69.3%를 절감한다. $\delta$-Mem과 비교할 때 Metis는 평균 및 P95 종단 간 지연 시간을 각각 36.4%와 42.2% 감소시킨다; Temp-LoRA와 비교하면 해당 감소율은 64.1%와 71.9%이다. ### G.2 컨텍스트 길이에 따른 지연 시간 스케일링 (Latency Scaling with Context Length)

평가 프로토콜. 우리는 4B 규모에서 단일 NVIDIA A800 GPU를 사용해 512에서 128K 토큰까지의 통제된 이력을 이용해 여섯 가지 방법을 평가한다. 각 최종 쿼리는 메서드별 템플릿을 제외하고 512개의 내용 토큰을 포함하며, 배치 크기 1로 32개 또는 128개의 토큰을 생성한다. 각 방법, 컨텍스트 길이, 출력 길이에 대해, 커널 초기화를 제거하기 위해 한 번의 워밍업 실행 후 5개의 측정 실행에서 평균과 표준편차를 보고한다. Metis는 이력을 최대 2K 토큰 단위로 처리하므로 커밋 수가 컨텍스트 길이에 따라 자연스럽게 증가한다. Partial Context는 매 실행마다 전체 이력에 대한 인덱스를 재구성하고 상위 다섯 개 문장 청크를 검색한다. 이는 답변 점수 없이 생성 전용 실험이다. 엔드-투-엔드 지연은 모든 메서드별 이력 준비 또는 작성과 이후 쿼리를 포함하며, 쿼리 지연은 이력 준비가 완료된 후 측정된다.

결과. 컨텍스트 길이가 32K 이하일 때 Metis는 Full Context보다 약간 높은 엔드-투-엔드 지연을 보인다. 두 출력 길이 모두에서 첫 번째 측정된 64K 지점에서 순서가 반전된다: 32개의 생성 토큰에 대해 Full Context와 Metis는 각각 5.909초와 5.390초를 소요하며 1.096배의 속도 향상을 제공한다; 128개의 생성 토큰에 대해 각각 10.228초와 9.522초를 소요해 1.074배의 속도 향상을 제공한다. 128K에서는 이러한 E2E 속도 향상이 각각 1.497배(14.254초 대 9.521초)와 1.595배(21.404초 대 13.423초)로 증가한다(그림 7).

그림 8은 순수 메모리 커밋이 Metis 지연의 작은 비율임을 추가로 보여준다. 64K와 128K에서 커밋은 각각 약 0.203초와 0.406초를 차지하며, 두 출력 길이에서 Metis E2E 지연의 2.1–4.3%에 불과하다; 대부분의 수집 시간은 역사 인코딩 백본 포워드에서 발생하며, 이는 약 3.86초에서 7.65초로 증가한다. Metis는 측정된 모든 컨텍스트 및 출력 길이에서 두 상태 기반 기준선보다 낮은 E2E 지연을 보인다. 128K에서는 δ-Mem보다 2.40–2.67배, Temp-LoRA보다 6.46–8.71배 빠르다. 이 격차와 일치하게, 상태 작성은 128K에서 δ-Mem E2E 지연의 71.7–90.8%를 차지하고, 임시 적응은 Temp-LoRA에서 92.2–97.7%를 차지한다.

그림 8은 32토큰(상단) 및 128토큰(하단) 출력에 대한 컨텍스트 길이별 정규화된 엔드-투-엔드 지연 분해를 보여준다. Metis의 경우, 모델 포워드/쿼리 프리필은 역사 인코딩 포워드와 최종 쿼리 프리필을 포함하며, 쓰기/커밋/적응은 순수 메모리 업데이트만을 포함한다. δ-Mem과 Temp-LoRA의 경우, 후자는 각각 상태 작성과 임시 적응을 나타내며; 인덱싱 및 검색은 Partial Context에 대해 별도로 보고된다. 기타에는 재설정, 토크나이징, 프롬프트 구성, 동기화, 텍스트 디코딩, 그리고 분리되지 않은 호스트 측 작업이 포함된다.

분석. E2E 결과는 두 가지 상호 보완적인 효율성 이점을 드러낸다. Full Context에 비해, Metis는 장기 컨텍스트 영역에서 히스토리가 증가함에 따라 점점 더 유리해진다. 교차점은 64K에서만 처음 관찰된다. 이는 Qwen3.5-4B가 이미 32개의 레이어 중 24개에서 선형 어텐션을 사용하기 때문이며, 이는 Full Context의 컨텍스트 의존 KV 트래픽을 크게 줄여 Metis에 유리하게 E2E 교차점을 지연시킨다. 나머지 8개의 풀 어텐션 레이어의 KV 캐시가 계속 증가함에 따라 Metis의 이점은 더욱 두드러진다: 컨텍스트가 64K에서 128K로 두 배가 되면 Full Context의 프리필(prefill)은 약 2.67배(4.34초에서 11.60초) 증가하고 디코드(decode)는 약 1.65배(32-토큰 출력의 1.40초에서 2.31초, 128-토큰 출력의 5.74초에서 9.45초) 증가하여 E2E 지연 시간 차이를 확대한다. 두 상태 기반 기준선에 비해, Metis는 히스토리 재생에 필요한 점점 더 비싼 상태 기록이나 임시 적응을 피하기 때문에 전체 컨텍스트 길이 스윕 동안 낮은 E2E 지연 시간을 유지한다. 우리는 메모리 읽기 비용을 분리하기 위해 쿼리 지연 시간만 사용한다. 이는 Metis 쿼리 지연 시간에서 No Context 지연 시간을 뺀 값으로 추정된다. 32-토큰 출력의 경우, 추정 읽기 비용은 64K에서 0.091초, 128K에서 0.106초이며, 128-토큰 출력의 경우는 각각 0.770초와 0.559초이다. 이 값들은 Metis 쿼리 지연 시간의 7.2–14.4%에 불과하며 히스토리가 두 배가 되어도 증가하지 않는다. Figure 8은 유사하게 순수 메모리 커밋이 64K와 128K에서 Metis E2E 지연 시간의 2.1–4.3%만을 차지하며, 대부분의 인게스션 시간은 히스토리 인코딩 백본 포워드에 소요된다는 것을 보여준다. 따라서 메모리 읽기나 순수 메모리 커밋은 주요 지연 병목이 아니다. 원칙적으로 두 단계는 백본 어텐션과 별도의 CUDA 스트림에서 동시에 실행될 수 있다. 그러나 이러한 비동기 겹침은 더 세밀한 커널 실행과 스트림 간 동기화가 필요하며, 이는 실행 및 스케줄링 오버헤드를 도입해 이 규모에서 숨겨진 지연을 상쇄할 수 있다. 따라서 최종 구현에서는 이 최적화를 활성화하지 않는다.

### G.3 Per-Session Storage across Context Lengths (Per-Session Storage across Context Lengths)

**평가 프로토콜.** 우리는 또한 512에서 32K 토큰까지 다양한 컨텍스트 길이에서 4B 방법들의 지속적인 세션당 저장량을 측정한다. 모든 값은 파라미터 수를 분석적으로 추정하는 대신 런타임 객체에서 얻어진다. Full Context의 경우, 세션을 재개하기 위해 히스토리를 재생하지 않고 필요한 KV 캐시를 보존한다; 측정에는 제어된 컨텍스트, 고정된 512-토큰 쿼리 프롬프트, 그리고 32개의 생성 토큰이 포함된다. KV 캐시와 모델 상태는 BF16으로 저장된다. RAG 저장소는 FP32 BGE-M3 임베딩과 해당 청크 텍스트를 포함한다. 상태 기반 방법의 경우, 각 세션마다 별도로 보존해야 하는 상태만 계산한다.

결과. 전체 컨텍스트(Full Context) 저장소는 512 컨텍스트 토큰에서 87.06 MB에서 32K에서 1,118.86 MB로 증가한다. 8개의 전체‑주의(full‑attention) 레이어는 토큰당 32.8 KB의 KV 캐시를 추가하고, 24개의 선형‑주의(linear‑attention) 레이어는 51.90 MB의 상수 상태를 기여한다. 반면 Metis Full은 16.79 MB를 유지하고 Metis k = 64는 2.11 MB를 유지한다. 32K에서 전체 컨텍스트는 Metis Full 상태의 $67\times$와 Metis k = 64 상태의 $529\times$를 차지한다; 측정된 선형 추세를 128K로 외삽하면 각각 약 $256\times$와 $2,000\times$가 된다. 다른 상수 크기 상태는 4.6 KB는  $\delta$‑Mem에 대해, 190.3 MB.

분석. Metis는 컨텍스트에 따라 달라지는 저장소 증가를 제거한다: Full Context KV 캐시는 32K에서 1,066.96 MB에 도달하지만, 두 Metis 상태는 일정하게 유지된다. 저랭크 지속성은 특히 효율적인 운영점을 제공한다: Metis(k = 64)는 Metis Full 상태의 1/8만 사용하면서 평균적으로 전체 상태 성능의 99.9 %를 유지한다.  $\delta$-Mem은 4.6 KB만 차지한다. 이는 공식 랭크-8 구성에서 36개의 어텐션 모듈 각각에 8 × 8 BF16 온라인 행렬을 저장하여 각 세션을 저차원 상태로 압축하기 때문이다; 이 제한된 용량은 낮은 LoCoMo 점수(Table 6)와 일치한다. 작은 상태에도 불구하고, 모든 쿼리 토큰은 36개의 어텐션 모듈에서 이를 읽고 추가적인 q/k/v/o 델타 프로젝션을 적용하여 백본 어텐션 위에 층별 행렬 연산과 커널 실행을 도입한다. RAG Store 역시 히스토리와 함께 성장하며 별도의 검색 및 인덱싱 파이프라인에 의존한다; Metis k = 64는 약 11K 토큰에서 더 작아지고, 측정된 16K 및 32K 포인트에서도 더 작게 유지된다. Temp-LoRA는 세션당 190.3 MB 어댑터를 필요로 하며, 이는 Metis Full 상태의 11.3배이다. 전체적으로 Metis는 긴 텍스트에 대해 높은 저장 효율을 제공한다: Metis Full과 k = 64 모두 일정하게 유지되며 Full Context보다 현저히 작고, k = 64는 히스토리가 증가함에 따라 RAG Store보다도 더 작아진다. 4B 모델 가중치 이후 약 72 GB가 남은 80 GB GPU에서 저장 전용 상한선으로서, 32K Full Context 캐시는 약 64개의 재현 세션을 수용할 수 있는 반면, 약 4,000개의 전체 상태 Metis 세션을 수용한다; 전자는 히스토리 길이에 따라 감소하지만 후자는 독립적이다.
