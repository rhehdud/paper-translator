## **ABSTRACT**

시각-언어 모델(VLM) 에이전트는 점점 더 도구와 코드를 활용해 3D 장면에서 행동하도록 사용되고 있다 (Wang et al., 2024a; Hu et al., 2024; Sun et al., 2025; Doris et al., 2026; Huang et al., 2023). 장면을 설명하는 대신 실제로 행동하는 것은 에이전트의 3D 이해도를 더 강력하게 테스트한다. 기존의 3D 벤치마크는 텍스트 응답이나 단일 객체 조작을 평가하여, 완전한 다중 객체 3D 장면에서의 에이전트 행동을 충분히 평가하지 못한다. 우리는 **SceneActBench**를 제시한다. 이는 통합된 에이전트—환경 루프 하에서 5개의 3D 과제에 대해 시각적으로 조건화된 행동을 평가하는 벤치마크이다. PNG 이미지 또는 샘플링된 비디오 프레임과, 해당되는 경우 제공된 3D 자산을 주어 에이전트가 3D 환경에서 행동한다. 우리는 각 최종 출력을 숨겨진 정답과 과제별 기하학적 지표를 사용해 평가한다. SceneActBench는 210개의 소스 인스턴스에서 구축된 5개의 과제로 구성되어 520개의 과제 사례(쌍 입력 조건 포함)를 제공한다. 모든 과제는 비교를 공정하게 유지하기 위해 하나의 고정된 에이전트 루프를 거친다. 11개의 독점 VLM 구성에서 Overall 점수는 38.6–50.2 범위이며, 어떤 구성도 과제마다 일관되게 우수한 성능을 보이지 않는다. 우리는 실패가 어디서, 어떻게 나타나는지 추가로 분석한다.

우리는 **SceneActBench**를 사용하여 이 질문에 접근한다. **SceneActBench**는 시각적으로 조건화된 3D 행동을 위한 실행 가능한 벤치마크이다. 에이전트는 이미지 또는 샘플링된 비디오 프레임을 관찰하고 3D 장면에서 참조와 일치하도록 행동한다. **SceneActBench**는 210개의 소스 인스턴스를 기반으로 한다: 100개의 가구가 배치된 방, 100개의 관절이 있는 물체, 그리고 10개의 다중 물체 동적 장면. 방은 27개 가구 카테고리 중 3–7개의 물체를 포함하고, 동적 세트는 9가지 동작 유형을 포괄한다 (Table 2). 그 다섯 가지 과제는 **Layout**, **Camera**, **Articulated**, **Reconstruction**, 그리고 **Dynamic**이다. 공정한 비교를 위해 우리는 고정된 에이전트 루프를 갖춘 표준화된 평가 하네스를 개발하였다 (Figure 2).

우리는 11개의 독점 VLM 구성을 평가한다. 전체 점수는 38.6에서 50.2 사이이며, 스택된 작업 기여도는 선도 구성 요소들 간의 다양한 강점을 드러낸다 (그림 1). 본 논문은 세 가지 기여를 한다. 첫째, 시각적으로 조건화된 3D 행동을 실행 가능한 평가 문제로 공식화하고 최종 출력을 숨겨진 3D 기준값과 비교하여 점수를 매긴다. 둘째, 210개의 소스 인스턴스로부터 구축된 다섯 가지 작업을 도입하여 공간 기반화, 자아중심 공간 추론, 동역학 추론, 형태 상상, 그리고 하나의 고정 에이전트 루프 하에서의 동적 추론을 테스트한다. 셋째, 11개의 구성을 벤치마크하고 사례 수준 진단을 사용하여 집계 점수 외에 실패가 어디서 어떻게 나타나는지를 특성화한다. 나머지는 벤치마크, 평가, 그리고 실패 분석을 제시한다.

## 2 관련 연구 (RELATED WORK)

**3D 이해 벤치마크.** Many 3D benchmarks pose questions over a scan or rendered image and score a text answer, including ScanQA (Azuma et al., 2022), SQA3D (Ma et al., 2023), and Spatial457 (Wang et al., 2025), with probes such as SpatialVLM (Chen et al., 2024) and BLINK (Fu et al., 2024) reporting that fluent descriptions still miss spatial judgments. Others evaluate agents acting in 3D environments, including BlenderGym (Gu et al., 2025), 3DCodeBench (Gao et al., 2026), GameDevBench (Chi et al., 2026), and EmbodiedBench (Yang et al., 2025), yet each covers a single part such as one object, a static edit, or plain task success. None asks one agent to handle a full scene of many objects (Table 1).

**3D 환경에서 행동하는 에이전트.** Prior work shows that language agents can act in 3D environments or create 3D content. Voyager (Wang et al., 2024a) acts in an interactive world, while VoxPoser (Huang et al., 2023) grounds robot manipulation in 3D. SceneCraft (Hu et al., 2024), 3D-GPT (Sun et al., 2025), and CAD-Coder (Doris et al., 2026) instead generate scenes or shapes. ## <span id="page-2-2"></span>3 벤치마크

SceneActBench는 에이전트가 시각적 증거를 실행 가능한 3D 출력으로 변환할 수 있는지를 평가한다. 에이전트는 **PNG** 이미지 또는 샘플링된 비디오 프레임을 받고, 그래픽 인터페이스 대신 공유 도구 인터페이스를 통해 헤드리스 모드에서 Blender를 제어한다. 작업에 따라 출력은 **JSON** 또는 하나 이상의 **GLB** 파일에 저장되며, 이는 이진 glTF 형식을 사용해 3D 기하학, 재질, 객체 변환 및 애니메이션을 패키징한다. 각 출력은 숨겨진 3D 정답과 비교해 평가된다. 다섯 개의 작업과 짝지어진 입력 조건을 통해 210개의 소스 인스턴스는 520개의 작업 사례를 생성한다. *asset*은 제공되거나 가져올 수 있는 3D 리소스이며, *object*는 장면에 인스턴스화된 항목이다. 부록 A.1은 벤치마크 전반에 걸쳐 사용되는 3D 전용 용어를 정의하고, 부록 A.3은 정확한 평가자 규칙과 모든 진단 지표를 제시한다.

### 3.1 데이터 수집

우리는 세 개의 공개 소스를 사용해 벤치마크를 구성하며, 각각을 자체 형식으로 표준화한다.

• Indoor Scenes Dataset. 우리는 3D-FRONT (Fu et al., 2021)에서 100개의 가구가 배치된 방을 추출하며, 다중 뷰 렌더링과 포즈 주석이 신뢰할 수 있는 M3DLayout (Zhang et al., 2026) 교차점만을 보존한다. 방은 27개 카테고리에서 3~7개의 가구 객체를 포함하며, 각각은 GLB 자산으로 제공된다. 우리는 다양한 카메라 위치에서 각 장면에 대해 11개의 PNG 뷰를 렌더링하고, 각 뷰의 카메라 행렬과 시야각을 **JSON**으로 기록한다. 이 이미지들은 5개 작업 중 3개에서 참조로 사용된다.

• Articulated Objects Dataset. S2O Articulated Containers Dataset (ACD) (Iliash et al., 2026)에서 100개의 관절형 객체를 선택하며, 각각은 GLB 자산으로 제공된다. 각 객체는 고정된 시점에서 16fps, 32프레임의 오픈-클로즈 MP4 비디오와 프레임마다 하나의 GLB 메쉬를 정답으로 갖는다.

• **Dynamics Dataset.** 10개의 장면은 CC0 라이선스의 저폴리 아셋 키트(Kenney<sup>1</sup>)에서 구축되며, 각각은 여러 개의 독립적으로 움직이는 객체를 포함한다. 움직임 유형은 고의적으로 다양하다. 하나의 휴리스틱으로는 모두를 포괄할 수 없으므로 평가가 작업-불특정화된다. 각 장면은 가져올 수 있는 **GLB** 자산 라이브러리와 24fps, 144프레임의 **MP4** 참조 비디오를 제공한다. 정답은 애니메이션된 **GLB** 장면이며, 프레임마다 움직이는 객체 좌표, 정적 레이아웃 주석, 그리고 **JSON** 형식의 카메라를 포함한다.

**Post-processing.** 원시 자산은 좌표와 이름에 정답을 포함한다. 모든 자산을 표준화하면 이 누수를 제거하고 에이전트가 참조 이미지만으로 장면을 재구성하도록 강제한다. 실내 자산은 중앙에 배치되고 중립 yaw로 설정되며, 미터 단위로 주석된 크기로 스케일된다. 관절형 자산은 공유 프레임으로 재배치되며, 그 조인트 파라미터는 에이전트에게 제공되지 않는다. 익명 식별자가 모든 파일 및 노드 이름을 대체한다. 라벨은 객체가 무엇인지 드러내지 않는다. 동적 장면의 경우, 우리는 각 저폴리 렌더를 NVIDIA Cosmos (Agarwal et al., 2026)를 통해 전달하여 동일한 레이아웃과 움직임을 갖는 사진 실사 참조를 생성한다. 관절형 및 동적 참조는 **MP4** 비디오로 저장된다. 구성 간 일관된 비교를 위해 공유 인터페이스는 이 비디오를 샘플링된 **PNG** 프레임으로만 노출한다.

### 3.2 레이아웃

**Task.** 원점에 있는 표준화된 가구 객체와 방 이미지가 주어지면, 에이전트는 각 객체의 세계 좌표와 수직축(요) 주위 회전을 설정한다 (Figure 3에 표시된 대로). 테스트되는 능력은 공간적 근거화이다. 에이전트는 이미지에서 레이아웃이 어떻게 보이는지를 3D에서 각 객체가 어디에 놓여 있고 어느 방향을 향하는지에 매핑한다. 우리는 같은 100개의 장면을 한 뷰와 약 $\sim$ 11개의 모든 뷰로 평가한다.

**Metric.** 주요 점수는 **ADD-S** (Wen et al., 2024)이다. 예측 객체 i와 후보 실제 객체 j에 대해, $\hat{V}_i \subset \mathbb{R}^3$는 최종 세계 변환을 적용한 후 예측 메쉬의 샘플링된 정점 집합을 나타내고, $V_j \subset \mathbb{R}^3$는 주석된 포즈를 적용한 후 해당 후보 실제 메쉬의 샘플링된 정점 집합을 나타낸다. 이들의 방향성 최단거리 표면 거리는

$$d_{\text{surf}}(\hat{V}_i, V_j) = \frac{1}{|\hat{V}_i|} \sum_{\hat{\mathbf{v}} \in \hat{V}_i} \min_{\mathbf{v} \in V_j} \|\hat{\mathbf{v}} - \mathbf{v}\|_2.$$

Hungarian 할당을 사용하여 쌍별 비용 $C_{ij} = d_{\text{surf}}(\hat{V}_i, V_j)$를 이용하면 매칭된 예측 객체와 실제 객체의 집합 $\mathcal{M}$이 생성된다. 장면 수준 점수는

<span id="page-3-1"></span>

$$ADD-S_{\text{scene}} = \frac{1}{|\mathcal{M}|} \sum_{(i,j) \in \mathcal{M}} d_{\text{surf}}(\hat{V}_i, V_j). \tag{1}$$

낮은 점수는 예측 객체 표면이 목표 위치와 방향에 더 가까워졌음을 나타낸다. 주요 점수는 매칭된 객체를 평균하고, 별도의 개수 민감한 감사는 누락된 객체를 고려한다. 부록 A.3은 점 샘플링 절차와 무효 출력 처리 방식을 명시한다.

### 3.3 카메라 (CAMERA)

**작업.** 에이전트는 정리된 장면과 시야각을 보지만, 카메라의 외부좌표(카메라의 3D 위치와 방향)를 알지 못한다. 테스트되는 능력은 자기 중심적 공간 추론이다. 에이전트는 장면이 어떻게 보이는지로 관찰자가 어디에 있었는지 추론한다. 가상 카메라를 배치하고, 렌더링하며, 참조(그림 4)에 대해 포즈를 정제한다.

<span id="page-3-0"></span><sup>&</sup>lt;sup>1</sup>www.kenney.nl, Creative Commons Zero 라이선스로 배포됨.

<span id="page-4-0"></span>![](2026-07-27-2607.22393-sceneactbench-can-agents-act-on-the-3d-scenes-they-see/_page_4_Figure_1.jpeg)

Figure 3: **Layout.** 주어진 한 개 또는 $\sim$ 11개의 보정된 참조 뷰와 원점에 있는 표준화된 가구 객체를 사용하여, 에이전트는 2D 증거를 각 객체의 메트릭 세계 위치와 수직 축(요크)에 대한 회전으로 매핑한다. 알려진 참조 카메라에서 렌더링하고, 시각적 잔차를 사용해 최대 30 단계까지 이 3D 포즈 가설을 업데이트한다. 최종 레이아웃은 숨겨진 실제값과 **ADD-S** 표면 거리(미터 단위)를 사용해 한 번 평가된다.

<span id="page-4-1"></span>![](2026-07-27-2607.22393-sceneactbench-can-agents-act-on-the-3d-scenes-they-see/_page_4_Figure_3.jpeg)

그림 4: **카메라.** 이미 정리된 장면의 하나의 참조 이미지와 알려진 시야각을 주고, 카메라 외부좌표는 숨겨진 상태에서, 에이전트는 6-자유도 포즈 가설을 유지하고, 그로부터 렌더링하며, 이미지 잔차를 통해 최대 30 단계 동안 카메라 위치와 방향을 업데이트한다. 최종 JSON 포즈는 숨겨진 실제값에 대해 위치 오차(미터)와 **AE**(도)를 사용해 한 번 평가된다.

**지표.** 주요 지표는 **위치 오차(PE)**와 **각도 오차(AE)**이다. $\hat{\mathbf{c}}, \mathbf{c} \in \mathbb{R}^3$ 를 예측된 카메라 중심과 실제 카메라 중심으로, $\hat{\mathbf{d}}, \mathbf{d} \in \mathbb{R}^3$ 를 각각의 단위 시야 방향으로 두고, $\|\hat{\mathbf{d}}\|_2 = \|\mathbf{d}\|_2 = 1$ 이라 하자. 우리는 다음과 같이 정의한다.

<span id="page-4-2"></span>

$$PE = \|\hat{\mathbf{c}} - \mathbf{c}\|_{2}, \qquad AE = \frac{180^{\circ}}{\pi} \arccos(\hat{\mathbf{d}}^{\top}\mathbf{d}). \tag{2}$$

PE는 두 카메라 중심 사이의 유클리드 거리를 미터 단위로 측정하고, AE는 그들의 시야 방향 사이의 각도를 도 단위로 측정하며 $[0^{\circ}, 180^{\circ}]$ 범위에 있다. 우리는 이들을 별도로 보고한다. 왜냐하면 추정된 카메라가 정확한 위치에 가까우면서도 잘못된 방향을 향할 수 있기 때문이다. AE는 시야 방향만 비교하므로 시야 축에 대한 롤을 벌하지 않는다.

### 3.4 관절형 (ARTICULATED)

**작업.** 에이전트는 관절로 연결된 움직이는 부품이 있는 닫힌 객체와 개폐 비디오에서 32개의 순서가 지정된 프레임을 받는다. 에이전트는 움직이는 부품을 찾고, 그 부품들의 관절을 추론하며, 움직임을 재현한다 (그림 5). 테스트 대상 능력은 동역학적 추론이다. 에이전트는 샘플링된 프레임에서 각 부품이 어떻게 움직이는지 복구하고 그 움직임을 재현한다.

**측정항목.** 주요 측정항목은 **최대 부품 오류** (Maximum Part Error, MPE) 이다. 이는 모든 실제 움직이는 부품에 대해 개방 정렬된 기하학적 오류 또는 재현되지 않은 움직임 범위 중 가장 큰 값이다. $\mathcal{P}_{mov}$ 를 실제 움직이는 부품 집합이라고 하자. 각 부품 $i \in \mathcal{P}_{mov}$ 에 대해, $\epsilon_i$ 를 그 부품의 가장 큰 기하학적 오류로 정의한다.

<span id="page-5-0"></span>![](2026-07-27-2607.22393-sceneactbench-can-agents-act-on-the-3d-scenes-they-see/_page_5_Figure_1.jpeg)

그림 5: **관절형.** 하나의 닫힌, 라벨이 없는 GLB와 고정된 시점에서 32개의 순서가 지정된 개폐 참조 프레임이 주어지면, 에이전트는 움직이는 메쉬를 선택하고, 각 관절의 종류, 축, 피벗, 범위를 추론하며, 전체 객체 변환을 적용하면서 최대 60 단계 동안 움직임을 렌더-체크한다. 에이전트는 32개의 전체 장면 GLB 상태를 내보낸다. 평가자는 개방 각도로 내보낸 상태를 숨겨진 실제와 매칭하고, **MPE** 를 사용해 움직이는 부품 전체에서 최대 오류를 보고한다.

예측 프레임과 실제 프레임을 개방 각도로 정렬한다. $\kappa_i \in [0, 1]$ 를 예측이 재현한 전체 움직임 비율로 정의하고, $g_i$ 를 전체 실제 움직임 거리로 정의한다:

<span id="page-5-1"></span>

$$MPE = \max \{ \epsilon_i, (1 - \kappa_i) g_i \mid i \in \mathcal{P}_{mov} \}.$$

(3)

여기서 $\epsilon_i$ 와 $g_i$ 는 모두 미터 단위로 측정된다. 항목 $(1 - \kappa_i)g_i$ 는 불완전한 움직임을 벌한다; 특히 움직이지 않은 부품은 $\kappa_i = 0$ 이며 전체 실제 움직임 거리를 부과받는다. 프레임은 프레임 인덱스 대신 개방 각도로 정렬된다. 따라서 MPE는 움직이는 부품 전체에서 최대 오류를 미터 단위로 직접 보고하며, 객체 대각선 항목이나 크기 정규화 없이 수행된다.

### 3.5 재구성 (RECONSTRUCTION)

**작업.** 여러 방 뷰와 빈 장면이 주어지면, 에이전트는 각 가구 객체를 메쉬(정점과 면으로 표현되는 3D 표면)으로 구축, 배치 및 텍스처링한다 (그림 6). 테스트 대상 능력은 형태 상상력이다. 에이전트는 몇 개의 부분 뷰에서 완전한 3D 기하학을 추론한다.

**측정항목.** 주요 F@5% 점수 (Tatarchenko et al., 2019)는 고정 스케일 ICP 정렬 (Besl & McKay, 1992), DBSCAN 클러스터링 (Ester et al., 1996), 그리고 Hungarian 매칭 (Kuhn, 1955) 이후에 계산된다. N 을 실제 객체 수라고 하자. 각 실제 객체 j 에 대해, $V_j \subset \mathbb{R}^3$ 를 그 객체의 표면 샘플 포인트 집합으로 정의한다. 객체 j 가 매칭되면, $\hat{V}_j \subset \mathbb{R}^3$ 를 매칭된 예측 클러스터의 재중심화된 표면 포인트 집합으로 정의한다; 매칭되지 않은 객체는 예측 클러스터가 없다. 객체별 거리 임계값을 $\tau_j = 0.05\delta_j$ 로 설정한다. 여기서 $\delta_j$ 는 객체 j 의 바운딩 박스 대각선 길이이다. 매칭된 객체 j 에 대해, $\mathrm{Prec}_j$ 를 $\hat{V}_j$ 에 있는 포인트 중 가장 가까운 포인트가 $V_j$ 에서 $\tau_j$ 이내에 있는 비율로 정의하고, $\mathrm{Rec}_j$ 를 $V_j$ 에 있는 포인트 중 가장 가까운 포인트가 $\hat{V}_j$ 에서 $\tau_j$ 이내에 있는 비율로 정의한다. 매칭되지 않은 객체 j 에 대해, $\mathrm{Prec}_j = \mathrm{Rec}_j = 0$ 으로 설정한다. 장면 수준 점수는

<span id="page-5-2"></span>

$$F@5\% = \frac{1}{N} \sum_{j=1}^{N} \frac{2\operatorname{Prec}_{j} \cdot \operatorname{Rec}_{j}}{\operatorname{Prec}_{j} + \operatorname{Rec}_{j}}.$$

(4)

합산 항은 $\operatorname{Prec}_j + \operatorname{Rec}_j = 0$ 일 때, 즉 매칭되지 않은 객체를 포함해, 0으로 정의됩니다. 따라서 객체는 예측된 표면과 실제 표면이 서로를 완전히 덮어쌓을 때만 높은 점수를 기여합니다. Appendix A.3에서는 점 집합, 매칭 임계값, 재중심화 등 전체 사양을 제공합니다.

### 3.6 동적 (DYNAMIC)

**작업.** 샘플링된 비디오 프레임과 자산 라이브러리를 주어지면, 에이전트는 정적 레이아웃, 시작 위치, 그리고 키프레임 트래젝터리를 재구성합니다 (Figure 7). 테스트 대상 능력은 동적 추론입니다. 에이전트는 여러 객체의 동시 움직임을 복원하고 3D에서 재생합니다. 또한 동일한 장면과 실제 데이터를 사용해 사진‑현실적 참조 변형을 테스트합니다.

<span id="page-6-0"></span>![](2026-07-27-2607.22393-sceneactbench-can-agents-act-on-the-3d-scenes-they-see/_page_6_Figure_1.jpeg)

Figure 6: **Reconstruction.** 대략 $\sim 11$개의 보정된 방 뷰와 빈 Blender 장면이 주어지면, 에이전트는 가구 객체를 식별하고 개수를 세며, 각 객체의 기하학, 미터 단위 크기, 포즈, Base Color를 가정하고 Blender 코드를 사용해 메쉬를 구축합니다. 이미 알려진 카메라에서 렌더링하고 시각적 잔차를 통해 최대 35단계까지 기하학, 배치, 색상을 수정합니다. 최종 가구가 배치된 장면은 숨겨진 정답과 한 번 비교하여 객체별 대각선 상대 임계값에서 $\mathbf{F@5\%}$를 사용해 점수를 매깁니다.

**지표.** 우리는 각 움직이는 객체를 mover라고 부르며, $N_{\text{mov}}$ 를 실제 mover 수로 둡니다. 평가자는 mover‑중심 트랙을 매칭하고 단일 전역 변환을 보정합니다. 매칭된 실제 mover $i \in \{1, \dots, N_{\text{mov}}\}$ 에 대해, $m_i$ 를 짧은 매칭 트랙 길이로 둡니다. 우리는 이 $m_i$ 프레임에 걸친 중심점 오차를 평균하고, 장면 스케일 S 로 나누어 $e_i$ 를 얻습니다. 스케일 S 는 실제 장면의 수평 범위이며, 최소값은 S m 입니다. 매칭되지 않은 실제 mover는 S0 를 할당하고, S1 움직임은 S2 로 간주됩니다.

같은 전역 변환을 적용한 뒤, $\hat{\mathcal{X}}_{stat} \subset \mathbb{R}^3$ 과 $\mathcal{X}_{stat} \subset \mathbb{R}^3$ 를 각각 예측된 정적 객체 중심점 집합과 실제 중심점 집합으로 둡니다. 우리는 $d_{stat}(\hat{\mathcal{X}}_{stat}, \mathcal{X}_{stat})$ 를 두 개의 방향성 평균 최근접 이웃 거리 합으로 정의합니다: 각 예측 중심점에서 가장 가까운 실제 중심점까지의 평균 거리와, 각 실제 중심점에서 가장 가까운 예측 중심점까지의 평균 거리. 두 주요 오류, **최대 이동자 오류 (MME)** 와 **레이아웃 오류 (LE)** 는

<span id="page-6-1"></span>

$$MME = \max_{1 \le i \le N_{mov}} e_i, \qquad LE = \frac{d_{stat}(\hat{\mathcal{X}}_{stat}, \mathcal{X}_{stat})}{2S}.$$

(5)

MME는 모든 실제 mover를 대상으로 최대값을 취하며, 매칭되지 않은 mover는 $e_i=1$ 을 할당받습니다. LE는 예측된 정적 객체 중심점과 실제 중심점 사이의 두 방향성 최근접 이웃 거리를 평균하고, 결과를 장면 스케일로 정규화합니다. 두 지표 모두 차원less이며 값이 낮을수록 좋습니다. 회전과 스케일은 보정되지 않으며, 추가 예측 mover는 MME에 포함되지 않습니다. Appendix A.3에서는 정확한 트랙 길이, 매칭, 빈 출력 규칙을 명시합니다.

## 집중된 결손이 순위를 형성한다

전체 순위는 작업 결손의 크기와 집중도에 따라 달라지며, 작업 승리 수에 따라 달라지지 않는다. GPT 5.4 High는 세 개의 작업에서 승리하지만 Dynamic 때문에 네 번째로 순위가 매겨진다. 반면 Doubao가 Claude Opus에 비해 두 개의 Dynamic 장면에서 집중적으로 앞서 있다.

#### 4.3.2 입력 조건이 성능에 어떤 영향을 미치는가?

우리는 장면, 목표 출력 및 평가자를 고정한 채 시각 입력만 변경했다 (Figure [9)](#page-9-0)). 다중 시점 Layout은 11개 구성 중 9개에서 개선되었으며, Sonnet은 12.1점, Gemini는 9.4점, Claude Opus는 8.5점을 획득했다. 반면 Step과 MiMo는 각각 1.4점과 0.6점을 잃어 추가 시점이 도움이 되었지만 일관되지는 않음을 보여준다.

Photo-realistic Dynamic는 혼합된 효과를 보였다: 네 개의 구성은 개선되었고, 여섯 개는 감소했으며, Claude Opus는 한 자리 소수점 정밀도에서 변하지 않았다. GPT 5.4 High는 17.3점을 획득했지만 Step과 Sonnet은 각각 10.3점과 10.2점을 잃었다. 목표 레이아웃과 움직임이 고정되어 있기 때문에 이러한 차이는 요구되는 출력의 변화를 측정하기보다 참조 외형에 대한 민감도를 측정한다. 각 구성–사례 쌍은 한 번 실행되었으므로 이러한 차이는 반복 실행 변동성을 추정하지 않는다.

#### 4.3.3 에이전트는 어디에서 실패하는가?

유사한 기본 점수는 서로 다른 실패 단계(그림 [10)](#page-10-0)를 숨긴다. Articulated에서는 상위 세 개의 MPE 값이 0.375–0.404로 가깝지만, Doubao는 391개의 실제 부품 중 13개만 움직이며, Claude Opus는 255/391, GPT 5.4 Medium은 132/391을 움직인다. 이어서 조인트 유형과 방향은 측정 가능한 강체 움직임이 있는 부품에 대해서만 평가된다: Doubao는 12개 중 8개에서 유형과 방향이 모두 정확하며, Claude Opus는 251개 중 248/251과 238/251을, GPT 5.4 Medium은 127개 중 124/127과 105/127을 달성한다. Reconstruction에서는 세 구성 모두 515개의 목표 중 425–432를 일치시키지만, 24–44만을 커버하며, 객체 수준 F@5%는 0.088–0.104로 남는다. Camera에서는 케이스 수준 PE와 AE가 Spearman 상관계수 0.76–0.93을 가지며, 두 지표 모두 18개의 Doubao, 16개의 Claude Opus, 24개의 GPT 5.4 Medium 케이스에서 제로 크레딧 한도에 도달한다. Dynamic에서는 Doubao가 28/29개의 움직임을 일치시키지만, 16개의 자격 있는 트랙 중 7개에서만 방향을 회복하며, Claude Opus는 14개 중 11개, GPT 5.4 Medium은 15개 중 11개를 달성한다. 따라서 기본 기하학, 목표 선택, 표면 완성 및 동작 의미는 서로 다른 단계에서 실패한다.

진단은 실패 단계를 찾는다

기본 지표는 순위의 기초를 제공하지만, 보다 광범위한 진단 세트는 실패를 찾고 모델 개선을 안내하기 위한 세밀한 신호를 제공한다. 기본 점수만으로는 고정된 출력, 잘못된 행동, 불완전한 표면, 방향 실패가 혼합된다.

#### 4.3.4 상호작용이 얼마나 사용되는가? (HOW MUCH INTERACTION IS USED?)

## 5 제한 사항 (LIMITATIONS)

SceneActBench는 다중 객체 3D 동작에 대한 기하학적 스트레스 테스트로 설계되었지만, 몇 가지 한계가 있다. 주요 연구는 독점 VLM 구성을 평가하고 구성–사례 쌍당 하나의 완료된 실행만 사용하므로, 보고된 Overall 점수는 반복 실행 추정치로 해석되어서는 안 된다. Dynamic 작업은 열 개의 장면을 포함하며, 동적 장면 성능의 광범위한 추정치라기보다는 목표 지향적 스트레스 테스트로 보는 것이 가장 좋다. Overall 점수는 고정 정규화 상수에 의존하며 이는 설계 선택이다; 따라서 우리는 집계와 함께 네이티브 메트릭 및 작업 수준 점수를 보고한다. 작업 전문 3D 파이프라인과의 비교는 향후 연구에서 중요한 방향이다.

## 6 결론 (CONCLUSION)

SceneActBench는 3D 이해를 실행 가능한 테스트로 만든다. 에이전트는 3D 환경에서 행동하고 숨겨진 실제 지오메트리를 일치시켜야 한다. 다섯 개의 작업과 열한 개의 구성에서 어느 구성도 일관되게 우수한 성능을 보이지 않는다. 유사한 Overall 점수를 가진 구성은 서로 다른 작업에서 성공한다. 이러한 결과는 3D 장면에서 행동하기 위해서는 단일 해결된 기술이 아니라 여러 개의 별도 역량이 필요함을 시사한다. SceneActBench는 향후 연구가 더 넓은 장면, 오픈-웨이트 모델 및 풍부한 상호작용으로 확장됨에 따라 이를 측정할 공통 기반을 제공한다.

## <span id="page-16-1"></span>A.3 과제 평가자 (TASK EVALUATORS)

주요 텍스트는 기본 지표를 소개합니다. 이 섹션은 일치, 임계값, 누락 출력 규칙을 포함한 전체 케이스별 평가자를 지정하기 위해 동일한 표기법을 사용합니다. 모자는 예측을 나타내며, 해당되지 않은 기호는 정답을 나타냅니다. 점 집합 V에 대해, b(V)와 δ(V)는 각각 그 경계 상자 중심과 대각선을 나타냅니다. 두 개의 표본화된 표면 집합에 대해

$$A, B \subset \mathbb{R}^3$$

, 우리는 사용합니다

$$d_{\text{surf}}^{\leftrightarrow}(A,B) = d_{\text{surf}}(A,B) + d_{\text{surf}}(B,A)$$

감사 지표에서 사용되는 양방향 표면 거리입니다. 별개의 기호 $d_{\rm stat}$는 Dynamic에서 정적 객체 중심 집합에 예약됩니다. 점 샘플링은 결정론적 시드 0을 사용합니다. 구성 수준 진단은 정의된 값이 있는 경우의 산술 평균입니다. 필수 필드는 부록 B.2의 무효-사례 규칙을 따릅니다.

## A.3.1 레이아웃 (LAYOUT)

객체 매칭 및 기본 지표. 평가자는 object_*라는 이름의 예측 메쉬에서 세계 공간 정점을 읽습니다. 각 정답 기준 메쉬를 주석된 포즈로 변환합니다. 각 메쉬당 최대 4,000개의 예측 정점을 보존하고, 각 쌍을 최대 2,000개의 점으로 샘플링합니다. 예측 객체 $\hat{V}_i$와 후보 정답 객체 $V_j$에 대해 매칭 비용은 $C_{ij} = d_{\text{surf}}(\hat{V}_i, V_j)$입니다. C에 대한 헝가리안 할당은 직사각형 매칭 $\mathcal{M}$을 반환하며, 식 1은 장면 점수를 제공합니다. 추가 예측과 일치하지 않는 대상은 이 평균에 포함되지 않습니다. 예측 객체가 없는 장면은 유효한 ADD-S가 없으며 부록 B.2에 따라 작업 점수가 0이 됩니다.

**위치 및 장면 기하학.** 평균 위치 오류는 일치된 경계 상자 중심을 비교하여 변환을 분리합니다:

$$PosErr_{layout} = \frac{1}{|\mathcal{M}|} \sum_{(i,j) \in \mathcal{M}} ||b(\hat{V}_i) - b(V_j)||_2.$$

(6)

이것은 미터 단위로 측정되며, 변환과 정면을 구분합니다. 각 최대 20,000개의 포인트로 샘플링된 예측된 표면 집합 $\hat{V}_{\text{scene}}$와 실제 표면 집합 $V_{\text{scene}}$를 합친 것을 가정합니다. 장면 수준의 대칭 표면 감사는 $d_{\text{surf}}^{\leftrightarrow}(\hat{V}_{\text{scene}},V_{\text{scene}})$ (Wu et al., 2021)입니다. 이는 미터 단위의 정규화되지 않은 오차이며, 객체 매칭을 사용하지 않으므로 누락된 기하학과 추가된 기하학을 포함합니다.

개수에 민감한 감사. N을 실제 객체 수라고 하고, $\delta_j = \delta(V_j)$ 라고 둡니다. 객체 j가 예측 i(j)와 매칭되면 $\xi_j = C_{i(j)j}$, 그렇지 않으면 $\xi_j = +\infty$ 로 둡니다. 배치 정확도(PA)는 목표 크기의 10% 이내에 배치된 비율입니다:

$$PA = \frac{1}{N} \sum_{j=1}^{N} \mathbf{1}[\xi_j < 0.1\delta_j].$$

(7)

Binary scene success (SS)는 예측된 객체 수가 정확하고 PA가 1일 때만 1이며, 그렇지 않으면 0입니다. 보고된 장면 성공률은 장면별 SS의 평균입니다. ADD-S는 Layout 작업 점수의 구성 요소입니다. PosErr<sub>layout</sub>, $d_{\text{surf}}^{\leftrightarrow}$, PA, 그리고 SS는 감사 지표이며 Overall에 포함되지 않습니다.

#### A.3.2 CAMERA (카메라)

**Pose 오류.** 최종 활성 카메라는 예측 중심 $\hat{\mathbf{c}}$와 단위 시야 방향 $\hat{\mathbf{d}}$를 제공합니다. 시야 방향은 월드 행렬의 음수 로컬 Z축입니다. 실제 값은 $\mathbf{c}$, $\mathbf{d}$이며, 방정식 2가 PE와 AE를 제공합니다. PE는 미터 단위, AE는 도 단위로 측정됩니다. AE는 광축 방향을 측정하며 롤을 벌점으로 삼지 않습니다. 이들은 작업 점수와 Overall에 사용되는 유일한 카메라 구성 요소입니다.

**시야각.** 평가자는 활성 카메라에서 최종 수평 시야각 $\hat{f}_x$를 도 단위로 기록합니다. 프롬프트는 목표 시야각 $f_x$를 제공하지만, 평가자는 $|\hat{f}_x - f_x|$를 계산하지 않습니다. 보고된 FOV는 따라서 감사 값이며, 오차 지표가 아닙니다. 이는 PE, AE, 카메라 점수, 또는 Overall에 영향을 주지 않습니다.

**Render-based audits.** 최종 점수 매기기 동안, 평가자는 최종 장면을 $384 \times 384$ 픽셀에서 두 번 렌더링한다. 하나의 렌더링은 예측된 카메라 행렬을 사용한다. 다른 하나는 실제 행렬을 사용한다. 두 렌더링 모두 예측된 FOV, 동일한 EEVEE 렌더러, 그리고 동일한 세계 설정을 사용한다. 이 쌍은 최종 장면 내에서 카메라 외부 파라미터의 효과를 고립시킨다.

평가자는 두 렌더를 $256 \times 256$ 크기로 리사이즈한 뒤 SSIM과 PSNR을 보고합니다. 두 이미지 모두 RGB 값이 [0,1] 범위이며 데이터 범위는 1입니다. 또한 OpenCLIP ViT-B/32 이미지 임베딩 간의 코사인 유사도 $s_{\rm CLIP}$, 그 거리 $1-s_{\rm CLIP}$, 그리고 AlexNet LPIPS를 보고합니다. LPIPS 역시 $256 \times 256$ 이미지를 사용합니다. 이러한 외관 의존적 수량은 감사 전용입니다. 시각적 렌더링 실패가 유한한 PE와 AE를 무효화하지는 않습니다. 그들은 두 평가자 렌더를 비교하며, 제공된 참조 이미지는 비교 대상이 아닙니다.

#### A.3.3 ARTICULATED (관절형)

**프레임 및 부품 라벨.** 평가자는 표준화된 객체 프레임에서 32개의 실제 프레임을 사용합니다. 프레임 0은 닫힌 상태이며 프레임 16은 완전히 열린 상태입니다. 예측된 열림 및 닫힘 키프레임은 첫 번째 프레임으로부터 전체 객체 변위가 가장 큰 및 가장 작은 프레임입니다. 점수 매기기 시각에, 누락된 각 프레임 인덱스는 현재 Blender 장면 상태를 내보내어 채워집니다. 이는 정적이거나 부분적인 출력도 점수화할 수 있게 합니다.

사설 정점 맵은 각 실제 정점을 부품에 할당합니다. 에이전트가 토폴로지를 보존하면 정확한 정점 인덱스가 사용됩니다. 그렇지 않으면 각 에이전트 정점은 가장 가까운 실제 닫힌 상태 정점의 라벨을 받습니다. 토폴로지를 보존하는 출력의 경우, 부품 오차는 대응 정점 L2 거리의 평균입니다. 대체 방법은 $\max\{d_{\text{surf}}(\hat{V},V),d_{\text{surf}}(V,\hat{V})\}$ 입니다. 평가자는 이 대체가 사용되었는지 기록합니다.

**개방 정렬 및 MPE.** 이동 가능한 부품 $i \in \mathcal{P}_{\text{mov}}$ 에 대해, $V_i^{\text{cl}}$ 과 $V_i^{\text{op}}$ 를 각각 실제값 닫힌 상태와 열린 상태 정점으로 둔다. 전체 이동 거리는

$$g_i = \max \left\{ \max_k \|V_{i,k}^{\text{op}} - V_{i,k}^{\text{cl}}\|_2, 10^{-6} \,\mathrm{m} \right\}.$$

(8)

$\Delta_i^t$ 를 에이전트가 선택한 닫힌 프레임에서 프레임 t까지의 평균 변위라 두자. 토폴로지가 다르면 평가자는 부품 중심 변위를 대신 사용한다. 예측 개방 정도는

$$o_i^t = \frac{\Delta_i^t}{g_i}. (9)$$

평가자는 실제값 프레임 0–16을 검색하고, $\phi_i(t)$ 를 $o_i^t$ 의 절단된 값에 가장 가까운 개방 정도를 갖는 프레임으로 둔다.

$\operatorname{err}_i$ 를 해당 정점 L2 또는 위의 대체값으로 둔다. 방정식 3에서 사용되는 두 개의 양은

$$\epsilon_i = \max_t \operatorname{err}_i \left( \hat{V}_i^t, V_i^{\phi_i(t)} \right), \qquad \kappa_i = \min \left\{ \max_t o_i^t, 1 \right\}.$$

따라서 $\epsilon_i$ 는 가장 큰 개방 정렬된 기하학 오류이며, $\kappa_i$ 는 재현된 움직임 비율이다. 평균 부품 오류는 정렬된 부품별 오류를 최대값 대신 평균한다. 전역 개방 상태 ADD-S는 전체 에이전트 개방 키프레임을 실제값 프레임 16과 비교한다. MPE는 미터 단위로 직접 측정되며 물체 대각선 정규화가 없다. 이는 Overall에서 사용되는 유일한 Articulated 구성 요소이다.

**부품 선택 진단.** 이동 가능한 부품 i 에 대해, $a_i$ 를 선택된 닫힌 및 열린 키프레임 사이에서 예측 부품 중심의 변위라 두자. 부품은 $g_i>10^{-3}$ m 이고 $a_i>0.2g_i$ 인 경우 회복된다; 이동 가능한 부품 재현율(MR)은 회복된 이동 가능한 부품 비율이다. 정적 부품 s 에 대해, $h_s$ 를 그 부품의 가장 큰 1% 닫힌-열린 정점 변위 평균, 또는 부품이 100개 미만 정점을 가질 때 최대값으로 둔다. 가짜 이동률(FMR)은 $h_s>0.05$ m 인 정적 부품 비율이다. 토폴로지가 다르면, $h_s$ 는 양방향 가장 가까운 이웃 변위를 사용한다. 분모가 비어 있는 경우 0을 반환한다.

**조인트 진단.** 타입 및 방향 비율은 평균 예측 정점 변위가 $\max(0.05\,\mathrm{m},0.25g_i)$ 를 초과하는 이동 가능한 부품만 사용한다. 강체 회전은 맞춘 회전이 $15^\circ$ 를 초과할 때 추론된다. 그렇지 않으면, 맞춘 이동이 변위 조인트의 목표 범위의 0.1배를 초과하거나 회전 조인트의 경우 $0.05\,\mathrm{m}$ 를 초과하면 이동이 추론된다. 비강체 움직임은 MPE에 그대로 나타나며 타입 불일치로 표시되지 않는다. 타입 불일치율은 추론된 강체 타입이 목표 타입과 다른 적격 부품 비율이다. 방향은 예측 및 실제값 엔드포인트 기하학에서 맞춘다. 그 방향 코사인 값이 -0.7 미만이면 방향이 반전된다. 역방향율은 이 조건을 만족하는 적격 부품 비율이다. -0.7과 0.7 사이의 코사인 값은 반전이 아니라 비축성으로 기록된다. 동결된 부품은 MR에 영향을 주지만 이 조건부 비율에는 영향을 주지 않는다. 적격 부품이 없으면 두 비율 모두 0이 된다.

#### A.3.4 RECONSTRUCTION

**점 집합 및 전역 정렬.** 평가자는 모든 예측 메쉬 정점을 병합한 뒤, 메쉬당 최대 4,000 정점만 보존한다. $\hat{V}_{\text{scene}}$ 를 이 병합된 예측 표면, $V_{\text{scene}}$ 를 방 구조를 제외한 병합된 실제값 가구 표면으로 둔다. 두 표면은 최대 4,000 포인트로 샘플링된다

고정 스케일 ICP를 위해. 고정 스케일은 두 표면의 축 정렬 경계 상자 대각선 비율이다. ICP는 이후 회전과 이동만 최적화한다. 초기 요각은 $0^{\circ}$, $90^{\circ}$, $180^{\circ}$, $270^{\circ}$ 를 시도한다. 각 실행은 최대 30회 반복하며 평균 가장 가까운 이웃 거리가 $10^{-5}$ 미만으로 변할 때 중지한다.

정렬된 장면 표면에 대해, $\operatorname{Prec}_{\operatorname{scene}}(\tau)$와 $\operatorname{Rec}_{\operatorname{scene}}(\tau)$를 거리 임계값 $\tau$에서의 점 정밀도와 점 재현율이라고 하자. 그들의 조화 평균은

$$F_{\text{scene}}(\tau) = \frac{2 \operatorname{Prec}_{\text{scene}}(\tau) \operatorname{Rec}_{\text{scene}}(\tau)}{\operatorname{Prec}_{\text{scene}}(\tau) + \operatorname{Rec}_{\text{scene}}(\tau)}.$$

(10)

$F_{\rm scene}(\tau)$는 분모가 0일 때 0이 된다. $\delta_{\rm scene} = \delta(V_{\rm scene})$라 두자. 정렬된 장면 진단은 $\tau \in \{0.02, 0.05, 0.10\}\delta_{\rm scene}$를 사용하고, 대칭 표면 감사는 같은 4,000포인트 세트에서 $d_{\rm surf}^{\leftrightarrow}(\hat{V}_{\rm scene}, V_{\rm scene})$를 사용한다.

**객체 매칭 및 기본 F@5%.** N을 정답 객체 수라고 하자. DBSCAN은 정렬된 예측을 후보군으로 분리한다. 평균 정답 객체 대각선의 0.10, 0.15, 0.20, 0.25, 0.30, 0.40배의 반경을 테스트하며, 각각 $0.04\,\mathrm{m}$의 하한을 둔다. DBSCAN은 min_samples=10을 사용하고 30개 미만 포인트를 가진 클러스터를 제거한다. 우리는 N에 가장 가까운 클러스터 수 K를 선택하고, K < N일 때 병합된 객체를 억제하기 위해 0.5의 타이브레이크 페널티를 추가한다.

헝가리안 할당은 유클리드 거리를 이용해 클러스터 평균을 정답 객체 평균에 매칭한다. $0.6\delta_{\text{scene}}$보다 멀리 떨어진 매칭은 거부된다. 각 수락된 클러스터는 형태 점수 계산 전에 매칭된 정답 평균으로 변환된다. 매칭된 정답 객체 j에 대해, $\hat{V}_j$를 재중심화된 예측 클러스터, $V_j$를 샘플링된 정답 표면이라고 하자. $\delta_j = \delta(V_j)$, $\tau_j = 0.05\delta_j$라 두고, 점 정밀도와 점 재현율은

$$\operatorname{Prec}_{j} = \frac{1}{|\hat{V}_{j}|} \sum_{\hat{\mathbf{v}} \in \hat{V}_{j}} \mathbf{1} \left[ \min_{\mathbf{v} \in V_{j}} \|\hat{\mathbf{v}} - \mathbf{v}\|_{2} \le \tau_{j} \right],$$

$$\operatorname{Rec}_{j} = \frac{1}{|V_{j}|} \sum_{\mathbf{v} \in V_{j}} \mathbf{1} \left[ \min_{\hat{\mathbf{v}} \in \hat{V}_{j}} \|\mathbf{v} - \hat{\mathbf{v}}\|_{2} \le \tau_{j} \right].$$

(11)

매칭되지 않은 객체 j에 대해 $\operatorname{Prec}_j = \operatorname{Rec}_j = 0$으로 둔다. $\operatorname{Prec}_j + \operatorname{Rec}_j = 0$일 때 0의 기여를 갖는 Equation 4는 기본 F@5% 점수를 제공한다. 이는 Overall에서 사용되는 유일한 Reconstruction 구성 요소이다. $\hat{V}_{\text{scene}}$ 또는 $V_{\text{scene}}$ 중 어느 하나라도 10개 미만 포인트를 가진 장면은 무효이다.

기하학적 진단. 매치율은 수락된 매치 수를 N으로 나눈 값이다. 평균 중심점 오차는 수락된 매치에서 번역 전 클러스터-정답 평균 거리의 평균이다. 두 번째, 영역 기반 경로는 각 정답 박스를 $0.1\delta_{\rm scene}$만큼 확장하고 그 안에 정렬된 예측 포인트를 선택한다. 10개 미만 예측 포인트를 가진 영역은 지역 F@5%를 0으로 받는다. 영역 F@5%는 클러스터 매칭이나 재중심화 없이 이 값들을 평균한다. 객체 커버리지는 영역 F@5%가 최소 0.30인 정답 객체 비율이다. $F_{\rm scene}(\tau)$, $d_{\rm surf}^{\leftrightarrow}$, 그리고 영역 F@5%는 감사 지표이다. 이들은 Overall에 포함되지 않는다.

Point-BERT 및 시각 감사. Point-BERT 유사도 (Liu et al., 2023a; Yu et al., 2022)는 OpenShape openshape-pointbert-vitb32-rgb 임베딩 간의 코사인 유사도이다. 각 표면 세트는 10,000포인트로 샘플링하거나 반복하고, 중심을 맞추고, 최대 반경을 단위로 스케일링하며, 중립 회색 RGB 특징을 부여한다. 장면 유사도는 전역 정렬된 표면을 사용한다. 객체 유사도는 정답 박스를 $0.1\delta_{\rm scene}$만큼 확장한 것을 사용한다. 100개 미만 예측 포인트를 가진 영역은 0을 받는다. 객체 Point-BERT는 모든 정답 객체의 평균이다.

최종 실행 시각적 감사는 $384 \times 384$ 해상도에서 네 개의 궤도 각도에서 예측과 실제 값을 렌더링합니다. 각 궤도는 해당 장면 경계에 맞게 조정됩니다. 실제 값 패스는 가구 메쉬만 보존합니다. 예측 패스는 모든 내보낸 메쉬를 보존합니다. 두 패스 모두 동일한 EEVEE 조명 레시피를 사용합니다. 평가자는 카메라 감사와 동일한 SSIM, PSNR, OpenCLIP, LPIPS 값을 보고합니다. 이 값들은 재구성 점수에 영향을 주지 않습니다.

#### A.3.5 동적 (A.3.5 DYNAMIC)

**트랙 및 장면 스케일.** 실제 트랙은 Blender의 Z-up 프레임에서 읽어옵니다. 누락된 프레임은 앞으로 채워지고, 첫 관측 이전 프레임은 첫 번째 유효 위치를 사용합니다. 예측 트랙은

24fps에서 144프레임 동안 내보낸 GLB에서 샘플링됩니다. 동일한 최상위 장면 객체 아래의 모든 애니메이션 채널은 하나의 무브러 트랙으로 병합됩니다. 무브러 위치는 해당 서브트리에서 각 메쉬의 정점 중심점 평균입니다. GLB 좌표 (x,y,z)는 Blender 좌표 (x,-z,y)로 매핑됩니다.

$\mathcal{X}_{all}$ 은 모든 실제 정적 위치와 무브러 위치를 포함합니다. 장면 스케일은

$$S = \max \left\{ \left\| \max_{\mathbf{x} \in \mathcal{X}_{\text{all}}} \mathbf{x}_{xy} - \min_{\mathbf{x} \in \mathcal{X}_{\text{all}}} \mathbf{x}_{xy} \right\|_{2}, 5 \,\text{m} \right\}. \tag{12}$$

극값은 좌표별로 취합니다. $\mathcal{X}_{\text{all}}$ 가 비어 있으면 구현은 $S = 40 \,\text{m}$ 를 사용합니다.

전역 변환 및 궤적 매칭. 평가자는 먼저 원시 트랙에 대해 Hungarian 할당을 수행합니다. 그 비용은 공유 프레임 범위에서 프레임당 평균 유클리드 거리입니다. 이 거친 매칭에서 $\{(\hat{\mathbf{y}}_k,\mathbf{y}_k)\}_{k=1}^{K_{\mathrm{pool}}}$ 를 예측 및 실제 트랙 포인트의 풀링된 쌍으로 둡니다. 적용된 전역 변환은

$$\mathbf{t}_{xy}^{\text{glob}} = \frac{1}{K_{\text{pool}}} \sum_{k=1}^{K_{\text{pool}}} (\mathbf{y}_{k,xy} - \hat{\mathbf{y}}_{k,xy}), \qquad t_z^{\text{glob}} = \underset{1 \le k \le K_{\text{pool}}}{\text{median}} (y_{k,z} - \hat{y}_{k,z}).$$

(13)

같은 변환은 모든 예측 무브러와 정적 객체에 적용됩니다. 회전과 스케일은 보정되지 않습니다. 평가자는 변환된 트랙에 대해 Hungarian 할당을 다시 계산하여 최종 예측-실제 트랙 쌍 $\mathcal{M}_{\rm trk}$ 를 얻습니다. 여기서 $\sigma(i)$ 는 실제 무브러 i와 매칭된 예측 무브러이며, $\hat{N}_{\rm mov}$, $N_{\rm mov}$ 는 예측 및 실제 무브러 수입니다.

매칭된 실제 무브러 i에 대해 $m_i$ 를 더 짧은 트랙 길이로 두고, 정규화된 궤적 오차는

$$e_{i} = \frac{1}{m_{i}S} \sum_{r=1}^{m_{i}} \left\| \hat{\mathbf{p}}_{\sigma(i)}^{r} - \mathbf{p}_{i}^{r} \right\|_{2}.$$

(14)

매칭되지 않은 실제 무브러마다 $e_i=1$ 을 할당합니다. 추가 예측 무브러는 $\{e_i\}_{i=1}^{N_{\text{mov}}}$ 에 포함되지 않습니다. 방정식 5에서 최대값은 모든 $N_{\text{mov}}$ 실제 무브러에 대해 취합니다. 평균 무브러 오차(AME)는 $\text{AME} = N_{\text{mov}}^{-1} \sum_{i=1}^{N_{\text{mov}}} e_i$ 입니다. AME는 1.0 패널티를 포함합니다. 동적 움직임 재현율은 $|\mathcal{M}_{\text{trk}}|/N_{\text{mov}}$ 이고, 개수 오차는 $|\hat{N}_{\text{mov}}-N_{\text{mov}}|/N_{\text{mov}}$ 입니다. 예측 무브러가 없으면 MME와 AME는 1이고 움직임 재현율은 0입니다.

**모션-쉐이프 진단.** 트랙 P에 대해 길이가 0.3S보다 긴 세그먼트는 루프 텔레포트로 간주되어 경로 길이 L(P)에서 제외됩니다. 트랙이 움직이는 경우는 L(P)>0.05S입니다. 트랙이 움직이고 순이동이 0.1L(P) 이하인 경우 닫힌 트랙이라고 합니다. 다섯 구성 요소로 이루어진 q(P) 디스크립터는 정규화된 엔드포인트 변위, 경로 길이, 직선성, 수직 범위, 시작-끝 직선에서의 최대 편차를 포함합니다. 순서대로 이들은 $\|P_T-P_1\|_2/S$, L(P)/S, $\|P_T-P_1\|_2/(L(P)+10^{-9})$, $(\max P_z - \min P_z)/S$, 그리고 $\ell_\perp(P)/S$ 입니다. 경로-쉐이프 오차는

$$e_{\text{shape}} = \frac{1}{5|\mathcal{M}_{\text{trk}}|} \sum_{(k,i)\in\mathcal{M}_{\text{trk}}} \|q(\hat{P}_k) - q(P_i)\|_1.$$

(15)

이 값은 움직이는 객체가 매칭되지 않을 때 1로 설정됩니다.

방향은 각 중심화된 트랙의 첫 번째 주성분 축을 사용합니다. 축의 부호는 순이동을 따릅니다. 방향 오류율은 매칭되고 움직이며 닫히지 않은 실제 트랙 중에서 예측 축과 실제 축이 최소 $30^{\circ}$ 이상 차이 나는 비율입니다. 닫힌 트랙은 주성분 축의 부호가 불안정하기 때문에 제외됩니다.

헤딩은 속도 방향 $\theta_r = \mathrm{atan2}(\Delta y_r, \Delta x_r)$ 를 사용합니다. XY 단계가 0.005S 미만인 경우 제거합니다. XY 단계가 보존된 단계의 중앙값의 8배를 초과하는 경우도 텔레포트로 간주되어 제거됩니다. 총 회전량은 연속 헤딩의 절대값 래핑 변화를 합한 값입니다. 이동자 i에 대해 헤딩 오류는 예측과 실제 총 회전량의 절대 차이를 $2\pi$ 로 나눈 값이며, 1로 제한됩니다. 실제 트랙이 움직이는 매칭된 이동자에 대해 평균합니다. 닫힌 루프는 포함됩니다. 매칭된 실제 이동자가 움직이지 않을 때 오류는 0입니다.

코스 조정은 또한 중심화된 풀링 포인트에 대해 최소제곱법으로 등방성 XY 스케일을 추정합니다. 추정값은 [0.1, 10] 범위로 제한되지만 적용되지 않습니다. 스케일 오류는 이 추정값의 절대 로그이며, 스케일을 추정할 수 있는 변동이 부족할 때는 0입니다.

정적 레이아웃 및 크기 감사를 수행합니다. $\hat{\mathcal{X}}_{stat}$ 를 프레임 0에서 비애니메이션된 최상위 예측 서브트리의 변환된 중심점을 포함하도록 하고, $\mathcal{X}_{stat}$ 를 실제 정적 위치를 포함하도록 합니다. 이들의 양방향 최근접 이웃 거리는 다음과 같습니다:

$$d_{\text{stat}}(\hat{\mathcal{X}}_{\text{stat}}, \mathcal{X}_{\text{stat}}) = \underset{\hat{\mathbf{x}} \in \hat{\mathcal{X}}_{\text{stat}}}{\text{mean}} \min_{\mathbf{x} \in \hat{\mathcal{X}}_{\text{stat}}} \|\hat{\mathbf{x}} - \mathbf{x}\|_{2}$$

$$+ \underset{\mathbf{x} \in \mathcal{X}_{\text{stat}}}{\text{mean}} \min_{\hat{\mathbf{x}} \in \hat{\mathcal{X}}_{\text{stat}}} \|\mathbf{x} - \hat{\mathbf{x}}\|_{2}.$$

$$(16)$$

식 5는 이후 LE를 제공합니다. $\hat{\mathcal{X}}_{\mathrm{stat}}$ 가 비어 있으면 LE는 1입니다. $\mathcal{X}_{\mathrm{stat}}$ 가 비어 있으면 LE는 정의되지 않으며, 동적 장면은 무효가 됩니다. 레이아웃 수 오류는 다음과 같습니다:

$$\frac{\left||\hat{\mathcal{X}}_{\mathrm{stat}}| - |\mathcal{X}_{\mathrm{stat}}|\right|}{|\mathcal{X}_{\mathrm{stat}}|},$$

그리고 진단용으로 남습니다.

정적 장면 크기 오류는 예측 및 실제 박스 범위를 비교합니다. 실제 슬래브는 XY 범위가 중앙값 범위의 5배를 초과하고 높이가 그 범위의 1/8 이하일 때 제거됩니다. 축이 $0.1\,\mathrm{m}$ 보다 짧으면 생략됩니다. 장면 크기 오류는 유효한 축에 대해 $|\log(\hat{s}_a/s_a)|$ 를 평균합니다. 이동자 크기 오류는 매칭된 이동자 박스를 비교하며, 축이 $0.05\,\mathrm{m}$ 보다 짧으면 생략합니다. 스킨된 이동자는 Blender에서 평가된 경계 상자를 사용합니다. 먼저 각 이동자에 대해 유효한 축에 대한 로그 비율 오류를 평균하고, 그 다음 이동자 전체에 대해 평균합니다. 두 지표 모두 동적 평가에서 제외됩니다.

MME와 LE는 두 개의 필수 동적 작업 점수 구성 요소입니다. 두 값 모두 유한해야 합니다. 에이전트 GLB 또는 실제 트래젝터리 파일이 없으면 사례가 무효가 됩니다. 정의되지 않은 크기 감사는 유한한 MME와 LE를 무효화하지 않습니다. 저폴리 동적은 전체에 포함됩니다. 포토리얼리스틱 동적은 동일한 평가자를 사용하며 입력 조건 제거(ablation)로 남습니다.

범위. 두 실행 모두 Claude Sonnet 5 High를 사용했다. 공식 실행은 네이티브 이미지 읽기를 사용했고, 메인‑테이블 실행은 SceneActBench 인터페이스를 사용했다. 그들의 시스템 프롬프트와 컨텍스트 정책도 달랐다. 따라서 이 실험은 공유 작업과 점수 하에서 스택 민감도를 측정하며, 하나의 인과 인터페이스 요인을 고립시키지 않는다. 이것이 메인 순위가 하나의 공통 스택을 사용하는 이유다.

## C.4.3 대표적 상호작용 추적 (Representative Interaction Traces)

집계 단계 및 도구 호출 수는 에이전트가 상호작용 예산을 어떻게 사용했는지 보여주지 않는다. 따라서 Figure [15](#page-29-1)은 세 개의 점수화된 에피소드를 도구 호출 타임라인으로 표시한다: 입력 읽기, 코드 편집, 렌더 검사, 도구 오류, 그리고 정지 이벤트. 단일 호출은 점으로 표시되고, 같은 유형의 연속 호출은 겹침을 줄이기 위해 둥근 세그먼트로 결합된다; 정확한 총합은 각 에피소드에 대해 나열된다. 이것들은 각 패턴이 얼마나 자주 발생하는지에 대한 추정이 아니라 예시 에피소드이다.

Panel [15a](#page-29-1)는 짧은 닫힌 루프를 보여준다: 초기 코드 오류 한 번 이후 에이전트는 네 번의 렌더 체크를 수행하고, 이동 가능한 회상 1.00과 MPE 0.021로 19단계에서 스스로 중지한다. 의의와 범위. 이 사례들은 MaxSteps와 원시 호출 수가 충분한 프로세스 측정 지표가 아니라는 것을 보여준다. 렌더 체크는 이후 편집과 오류가 해결될 때만 도움이 되며, 렌더 활동만으로는 수렴이 보장되지 않는다. 이는 패널 [15c](#page-29-1)에서 보여진다. 에피소드는 가독성을 위해 선택되었으며, 인과성이나 유병률 주장보다는 프로세스 수준 진단을 지원하기 위해 선택되었다.

## D.2 카메라 (CAMERA)

#### **시스템 프롬프트 (System prompt)**

당신은 MCP 도구를 통해 Blender를 제어하는 3D 카메라 포즈 에이전트입니다.

장면은 이미 올바르게 배치되어 있습니다 (ground-truth 가구 배치가 로드되었습니다). 당신은 알려지지 않은 카메라 포즈에서 촬영된 하나의 참조 이미지를 받습니다. 당신의 임무: 참조 이미지를 최대한 가깝게 재현하는 카메라 포즈를 찾는 것입니다.

#### Workflow (작업 흐름):

- 1. 장면을 검사합니다 (get_scene_info).

- 2. execute_blender_code를 통해 카메라를 생성/배치하고, 그 세계 행렬과 렌즈를 설정합니다. render_scene_view로 렌더링하고 참조 이미지와 비교합니다.

- 4. 렌더링된 뷰가 일치하면 중지하고 최종 카메라 포즈(위치 + 시선 방향 또는 전체 matrix_world)를 보고합니다. 질문은 하지 마세요.

당신은 실제 카메라와의 카메라 포즈 오차, 그리고 렌더링과 참조 이미지 간의 이미지 유사도(LPIPS/CLIP/PSNR)를 기준으로 평가됩니다.
