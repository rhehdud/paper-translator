# **초록 (Abstract)**

GUI 에이전트는 기존 디지털 장치 위에서 일반 목적 실행기로 발전할 잠재력을 가지고 있다. 실세계 사용으로 진화시키기 위해, 우리는 실제 장치에서 신뢰성 있게 동작하고, 플랫폼 간 워크플로우를 실행하며, GUI 상호작용과 CLI 실행을 결합하고, 장기 목표를 완수하며, 유용한 서비스를 사전에 시작하고, 최소한의 인간 노력으로 자율적으로 역량을 향상시키는 에이전트를 상상한다. 이 비전을 바탕으로 우리는 모바일, 컴퓨터 사용, 웹, DeepSearch 환경을 아우르는 실세계 중심 기반 GUI 에이전트인 **Qwen-UI-Agent**를 제시한다. Qwen-UI-Agent는 다양한 샌드박스 환경과 대규모 실제 장치 모바일 런타임을 결합한다. 그 통합 액션 공간은 GUI 작업과 CLI 실행을 교차시키며, 단일 모델 턴에서 배치된 액션을 생성한다. AutoResearch 스타일의 데이터 플라이휠은 에이전트를 사용해 과제와 환경을 구성하고, 실패를 진단하며, 이후 반복을 계획한다. 온라인 RL 지원은 100턴을 초과하는 궤적에서 훈련을 진행하며, 10,000개 이상의 동시 환경이 롤아웃을 가속화한다. 가벼운 하니스 레이어는 모바일과 컴퓨터 전반에 걸쳐 사전 서비스 시작과 상태 기반 워크플로우를 지원한다. 광범위한 평가 세트에서 Qwen-UI-Agent는 모바일 사용 벤치마크에서 최첨단 성능을 기록하면서, Opus 4.8, Gemini 3.1 Pro, GPT-5.6 Sol 등 최첨단 모델과 비교해 컴퓨터 및 브라우저 사용 과제에서 경쟁력 있는 성능을 제공한다. 모바일 사용에서는 MobileWorld에서 **82.1%**, MobileWorld-Real에서 **92.2%**, AndroidDaily에서 **97.5%**를 달성한다. 컴퓨터 사용에서는 OSWorld-Verified에서 **79.5%**를, OSWorld-v2에서 **40.0%** 부분 진행 점수를 달성한다. 브라우저 사용 및 GUI 기반 작업에서는 WebArena에서 **73.6%**, ScreenSpot-Pro에서 **81.5%**를 각각 달성한다.

## <span id="page-2-0"></span>1 Introduction

그래픽 사용자 인터페이스(GUI)는 인간이 디지털 서비스와 애플리케이션에 접근하는 주요 인터페이스이다. 능력 있는 GUI 에이전트 [(Zhou et al.,](#page-50-0) [2025a;](#page-50-0) [Wang et al.,](#page-48-0) [2025a;](#page-48-0) [Qin et al.,](#page-47-0) [2025;](#page-47-0) [Xu et al.,](#page-49-0) [2026)](#page-49-0)는 기존 애플리케이션 생태계 위에서 범용 실행기로서의 잠재력을 갖는다: 사용자 의도를 이해하고, 애플리케이션 상태를 인지하며, 인터페이스를 조작하고, 모든 서비스가 전용 API를 노출할 필요 없이 작업을 완수할 수 있다. 멀티모달 기반 모델(multimodal foundation models)의 최근 진전은 이 방향을 점점 더 실용적으로 만들었으며, 모바일 및 데스크톱 GUI 에이전트 [(Cao et al.,](#page-45-0) [2026;](#page-45-0) [Gao et al.,](#page-45-1) [2026;](#page-45-1) [Huang et al.,](#page-46-0) [2026;](#page-46-0) [Shen et al.,](#page-48-1) [2026)](#page-48-1)에서 급속한 개선을 이끌었다.

이러한 진전에도 불구하고 GUI 에이전트는 여전히 시뮬레이션 벤치마크에 최적화되어 있어 벤치마크 성능과 실제 세계 유용성 사이에 상당한 격차가 존재한다. 이 격차를 해소하기 위해 우리는 실제 장치에서 안정적으로 동작하고, 장기 목표 작업을 완수하며, 플랫폼 간 워크플로우를 수행하고, 유용한 서비스를 선제적으로 시작하며, GUI 상호작용과 CLI 실행을 결합하고, 더 적은 인간 노력으로 지속적으로 역량을 진화시키는 차세대 GUI 에이전트를 상상한다. 이 비전을 실현하기 위해 우리는 여섯 가지 핵심 전환을 식별한다: **(1) 시뮬레이션 환경에서 실제 장치 실행으로.** 많은 GUI 에이전트, 특히 모바일 에이전트는 시뮬레이션 벤치마크에 최적화되어 있지만, 실제 모바일 장치는 훨씬 더 복잡한 애플리케이션 기능, 다양한 UI 레이아웃, 중단, 권한, 변화하는 환경을 포함한다. 시뮬레이션에서 잘 수행되는 모델은 실제 장치에서 자주 실패한다. **(2) 고립된 도메인에서 도메인 간, 플랫폼 간 워크플로우로.** 기존 에이전트는 모바일, 웹, 데스크톱을 별도로 구축하는 경우가 많지만, 실제 세계 작업은 여러 도메인에 걸쳐 있을 수 있고 휴대폰과 컴퓨터를 넘어 계속된다. **(3) GUI 전용 액션에서 GUI+CLI 및 배치 액션으로.** GUI 상호작용은 시각적 인터페이스에 대한 보편적 접근을 제공하지만, 멀티모달 기반 모델의 성장하는 코딩 능력은 데이터 처리 및 파일 조작과 같은 구조화된 작업에 CLI를 자연스러운 보완으로 만든다. 이러한 액션 유형을 결합하고 배치 액션을 지원함으로써 에이전트는 작업의 특성에 맞게 실행 방식을 더 잘 매칭하고, 실행 효율을 향상시키며, 작업 범위를 확장할 수 있다. **(4) 단기 목표 작업에서 신뢰할 수 있는 장기 목표 작업 완수로.** GUI 에이전트의 실용적 가치는 사용자가 완수할 수 있는 목표의 복잡성과 사용자를 대신해 수행할 수 있는 실행 단계 수가 증가함에 따라 커진다. 그러나 장기 목표 작업을 완수하려면 지속적인 계획, 상태 추적, 중간 검증, 실행 오류 복구가 필요하며, 이는 장기 목표 신뢰성을 도전적인 역량으로 만든다. **(5) 인간 집약적 훈련 파이프라인에서 AutoResearch 스타일로.** 현재 GUI 에이전트 개발은 여전히 수동으로 작업을 구성하고, 데이터를 수집하고, 모델을 훈련하고, 평가를 실행하고, 실패를 분석하는 데 크게 의존한다. 에이전트 역량이 향상됨에 따라 이 과정은 점점 더 자동화되어야 한다. **(6) 반응형 실행에서 선제적 서비스 시작으로.** 대부분의 에이전트는 명시적 사용자 지시를 기다리지만, 휴대폰이나 다른 장치의 디지털 신호에서 직접 유용한 작업이 발생할 수 있다. 이러한 실행 가능한 순간을 인식하고 적절한 다음 단계를 제안하는 에이전트는 근본적으로 다른 사용자 경험을 제공할 수 있다.

본 보고서에서는 다섯 가지 전환을 중심으로 개발된 실세계 중심 기반 GUI 에이전트 Qwen-UI-Agent를 소개한다. 이는 실세계 활용을 위한 차세대 GUI 에이전트로 나아가는 우리의 단계이다. 구체적으로, Qwen-UI-Agent는 다음과 같은 핵심 기능을 제공한다.

- **실제 장치 모바일 GUI 기반 (Real-device Mobile GUI Foundation)**. 우리는 시뮬레이션-실제 차이가 모바일 환경에서 특히 심각하다는 것을 발견한다. 이 차이를 해소하기 위해 100개가 넘는 물리적 장치와 150개가 넘는 애플리케이션을 지원하는 실제 장치 모바일 환경을 구축한다. 이를 실제 장치에서의 현실적인 작업 설계, 궤적 수집, 온라인 강화 학습, 평가에 활용한다. 실용성을 높이기 위해 고위험 행동에 대한 사용자 인수(over takeover)를 지원하고, 고빈도 워크플로우와 덜 자주 사용되는 앱 기능 모두를 커버하도록 범위를 확장한다. 이러한 노력 덕분에 Qwen-UI-Agent는 실제 휴대폰에서 기존 모델보다 크게 우수하다.  
- **다중 도메인 기능 및 교차 도메인 워크플로우 (Multi-domain Capabilities and Cross-Domain Workflows)**. Qwen-UI-Agent는 모바일, 웹, 컴퓨터 사용, 그리고 DeepSearch 환경에서 작업 실행을 지원한다. 이러한 기능을 격리된 모듈로 다루는 대신, 우리의 하네스 레이어는 이를 통합된 워크플로우 내에서 조합하여, 실행이 장치와 환경을 원활하게 이동함에 따라 컨텍스트와 작업 상태를 보존한다. 예를 들어, GUI 워크플로우는 DeepSearch를 호출하여 외부 정보를 효율적으로 검색하고 검증함으로써 GUI 기반 웹 탐색의 시간 소모를 피하고 원활하게 상호작용을 재개한다. 이는 다중 도메인 커버리지를 이질적인 디지털 환경에서 통합된 작업 실행으로 전환한다.

이러한 노력은 Qwen-UI-Agent가 실제 휴대폰에서 기존 모델보다 크게 우수하도록 한다.

- **Hybrid GUI+CLI and Batched Action Spaces.** Qwen-UI-Agent는 GUI 연산, bash 기반 CLI 명령, 그리고 배치된 액션을 지원하는 통합 액션 공간을 갖추고 있다. 모델은 단일 궤적 내에서 이러한 액션을 선택하고 조합할 수 있으며, GUI 상호작용과 CLI 실행을 각각 가장 적합한 상황에서 활용하고, 호환되는 액션을 배치하여 불필요한 단계를 줄인다. 컴퓨터 사용 과제에서는 CLI 명령과 GUI 클릭이 두 가지 주요 액션 유형으로 등장하며, 액션 출력의 40% 이상이 배치되어 실행 궤적을 크게 단축한다.  
- **Scalable Online RL for Long-horizon Tasks.** Hybrid GUI+CLI와 배치 액션은 로컬 실행 효율성을 향상시키지만, 장기 과제를 완수하려면 신뢰할 수 있는 계획, 상태 추적, 그리고 전체 궤적에 걸친 중간 의사결정이 필요하다. 따라서 우리는 검증자 가이드형 온라인 RL을 100단계 이상의 상호작용 궤적에 확장한다. 또한 약 10,000개의 시뮬레이션 환경을 동시에 실행해 롤아웃 생성을 가속화하고, 모델 적응형 커리큘럼이 중간 성공률이 높은 과제를 우선시하며, 숙달된 과제를 더 어려운 과제로 교체한다.  
- **AutoResearch-style Capability Acquisition.** 우리는 에이전트가 데이터 플라이휠을 위해 후보 과제를 생성·평가하고, 롤아웃 궤적을 처리하며, 실패를 분석하고, 다음 반복을 위한 계획을 제안하는 에이전트 주도 반복 루프를 구축한다. 모든 단계를 인간이 수동으로 주도하기보다, 시스템이 대부분의 역량 개발 과정을 자동화하고, 인간은 주로 감독과 목표 지향적 수정을 담당한다. 이 접근법은 인간의 노력을 줄이고 새로운 GUI 에이전트 역량의 획득 및 정제 속도를 가속화한다.  
- **Proactive Mobile Service.** 사용자의 휴대폰에 도착한 항공편 취소 알림을 예로 들면, 에이전트는 사용자가 알림을 인지하고 명령을 내리기 전에 영향을 받는 일정표를 식별하고, 대체 여행 옵션을 수집하며, 사용자의 일정과 비교하고, 확인을 위한 제안 계획을 제시한다. 이러한 경험을 지원하기 위해 모바일 알림 기반의 사전 서비스 하네스를 구축한다. 단순히 과제를 시작하는 것을 넘어, 하네스는 현실 세계 상황을 일관되게 이해하고, 개인화된 과제를 생성하며, 승인된 액션을 실행하고, 사용자 반응과 장기 상호작용 기록을 통해 지속적으로 진화한다.

### 2.1 시스템 개요 (System Overview)

Qwen-UI-Agent는 모바일, 데스크톱, 웹, 정보 탐색 시스템 등 다양한 디지털 환경에서 운영되는 현실 중심 기반 GUI 에이전트로 설계되었다. 본 절에서는 먼저 Qwen-UI-Agent의 작업 범위를 정의하고, 이어서 통합 관측 및 행동 공간을 소개하며, 마지막으로 이 정의가 지원하는 기능 지형을 요약한다.

#### <span id="page-5-0"></span>**2.1.1 작업 공식화 (Task Formulation)**

Qwen-UI-Agent는 상호작용형 디지털 작업 실행을 위해 설계되었다. 우리는 작업을 다음과 같이 정의한다:

$$\tau = (I, \mathcal{E}_{\tau}), \tag{1}$$

여기서 *I*는 사용자 지시이며, E*<sup>τ</sup>*는 작업에 사용 가능한 디지털 환경의 집합이다. 작업에 따라 E*<sup>τ</sup>*는 모바일 장치, 웹 브라우저, 컴퓨터 시스템, DeepSearch 시스템, 또는 이들의 조합을 포함할 수 있다. 이 공식화는 단일 환경에서 완료되는 작업과 다중 플랫폼을 아우르는 워크플로우를 모두 포괄한다 [(Xu et al.,](#page-49-0) [2026;](#page-49-0) [Lian et al.,](#page-46-1) [2026)](#page-46-1).

결정 단계 *t*에서 에이전트는 다양한 환경 피드백 형태를 결합할 수 있는 다중 채널 관측 *o<sup>t</sup>*를 받는다:

$$o_t = \left(o_t^{\text{GUI}}, o_t^{\text{CLI}}, o_t^{\text{API}}\right). \tag{2}$$

여기서 *o* GUI *t*는 현재 스크린샷을 나타내고, *o* CLI *t*는 명령 실행 결과를 포함하며, *o* API *t*는 검색 API와 같은 외부 서비스의 구조화된 응답을 포함한다. 해당 채널이 사용 불가능하거나 현재 작업에 필요하지 않을 때는 해당 컴포넌트가 비어 있다. 이 다중 채널 관측은 에이전트가 시각적 인터페이스 상태와 프로그래밍적 실행 피드백을 동시에 추론할 수 있게 한다 [(Hu](#page-46-2) [et al.,](#page-46-2) [2026;](#page-46-2) [Li et al.,](#page-46-3) [2026a)](#page-46-3).

에이전트는 중간 추론 출력 *r<sup>t</sup>*와 실행 가능한 행동 출력 **a***<sup>t</sup>*를 예측한다:

$$(r_t, \mathbf{a}_t) = \pi_\theta (I, o_t, h_t), \qquad (3)$$

여기서 *h<sup>t</sup>* = (*o*1,*r*1, **a**1, . . . , *ot*−1,*rt*−1, **a***t*−1)는 이전 상호작용 기록을 나타낸다.

특히, 하나의 모델 결정 단계는 단일 행동 또는 순서가 지정된 행동 시퀀스를 생성할 수 있다:

$$\mathbf{a}_t = \left(a_t^{(1)}, \dots, a_t^{(K_t)}\right), \qquad a_t^{(k)} \in \mathcal{A}_t, \tag{4}$$

여기서 A*<sup>t</sup>*는 현재 환경에서 사용 가능한 행동 집합이다. *K<sup>t</sup>* = 1일 때 모델은 단일 행동 실행을 수행한다. *K<sup>t</sup>* > 1일 때는 배치 행동 시퀀스를 생성한다. 배치 내의 행동은 이 결정 단계에서 연속적으로 실행되어, 추가 환경 피드백 없이 여러 작업을 완료할 수 있을 때 불필요한 추론 및 관측 단계를 줄인다.

#### <span id="page-5-1"></span>**2.1.2 행동 공간 (Action Space)**

Qwen-UI-Agent의 행동 공간은 세 가지 요구 사항을 중심으로 설계된다: 서로 다른 플랫폼에서의 GUI 상호작용 지원, GUI 조작을 넘어선 실행 확장, 그리고 결과적인 작업에 대한 사용자 제어 보존. GUI 행동 공간은 모바일, 웹, 데스크톱 환경에 필요한 행동들의 합집합으로 정의되며, 각 환경은 자체 네이티브 상호작용 메커니즘이 지원하는 하위 집합을 노출한다. GUI 상호작용을 보완하기 위해 cli_command를 도입하여 직접 bash 명령 실행을 가능하게 하고, api_call을 도입하여 구조화된 인수와 함께 외부 서비스를 호출한다. 또한 ask_user를 포함시켜 에이전트가 누락된 정보를 요청하거나 민감 데이터, 지불, 또는 기타 결과적인 작업을 처리하기 전에 명시적 확인을 얻을 수 있도록 한다. 이들 행동은 서로 다른 플랫폼에서의 GUI 상호작용, 하이브리드 GUI+CLI 실행, 그리고 실제 작업에서의 사용자 제어 작업을 위한 통합 인터페이스를 제공한다. 전체 행동 공간은 표 [1.](#page-6-3)에 표시된다.

#### <span id="page-6-0"></span>2.1.3 능력 현황 (Capability Landscape)

통합된 공식은 실제 세계 작업 실행을 중심으로 Qwen-UI-Agent의 네 가지 상호 보완적 기능을 지원한다. (1) **실제 장치 모바일 실행**. 실제 장치 모바일 환경을 구축하고 이를 모델 기능 개발 및 평가 전반에 활용함으로써 Qwen-UI-Agent는 시뮬레이션-실제 차이를 크게 줄이고 전문 GUI 에이전트와 최첨단 폐쇄형 모델 모두에 대해 선도적인 실제 세계 모바일 실행 성능을 달성한다. (2) **다중 도메인 작업 실행**. Qwen-UI-Agent는 모바일, 데스크톱, 웹, 그리고 DeepSearch 환경에서 작동하며, 도메인별 정책을 넘어 이질적인 디지털 작업을 위한 기초 GUI 에이전트로 나아간다. (3) **하이브리드 및 효율적인 상호작용**. Qwen-UI-Agent의 통합 행동 공간은 모델이 같은 경로에서 GUI 작업과 bash 기반 CLI 명령을 번갈아 선택하고 결합할 수 있게 하며, 배치된 행동은 실행 효율성을 크게 향상시킨다. (4) **하네스 활성화 서비스**. 경량 하네스 레이어는 핵심 에이전트를 고립된 작업 실행을 넘어선 것으로 확장하여 선제적 서비스 시작을 가능하게 하고 모바일과 컴퓨터 시스템을 아우르는 단일 워크플로우를 허용한다.

### <span id="page-6-1"></span>2.2 환경 인프라 (Environment Infrastructure)

환경은 에이전트의 능력 경계를 정의한다: 에이전트가 지각할 수 있는 것, 수행할 수 있는 행동, 그리고 상호작용을 통해 획득할 수 있는 경험을 결정한다. 따라서 GUI 에이전트를 벤치마크 중심 최적화에서 실제 세계 활용으로 전환하려면 더 강력한 모델뿐 아니라 에이전트가 학습하고 행동하며 적응할 수 있는 보다 넓고 현실적인 환경이 필요하다. 그림 3에 나타난 바와 같이, 우리의 환경 인프라는 네 가지 핵심 구성요소를 중심으로 조직된다. 첫째, **시뮬레이션 및 샌드박스 환경**은 데이터 생성, 에이전트 학습, 평가를 위한 확장 가능하고 제어 가능하며 재현 가능한 설정을 제공한다. 둘째, 이러한 시뮬레이션 환경을 **실제 장치**로 확장하면 동적 장치 상태, 시스템 제약, 사용자 상호작용을 포함한 현실적인 배포 조건에서 에이전트가 학습하고 운영할 수 있다. 셋째, **하이브리드 GUI 및 CLI 액션 스페이스**는 에이전트가 각 작업에 가장 적합한 상호작용 모달리티를 선택하도록 허용함으로써 보다 효율적이고 적응적인 실행을 지원한다. 마지막으로, **통합 크로스 플랫폼 환경**은 모바일 사용, 컴퓨터 사용, 브라우저 사용, 그리고 DeepSearch 전반에 걸쳐 통합 파이프라인을 제공하면서 플랫폼 간에 컨텍스트와 작업 상태를 보존한다. 이 네 가지 구성요소가 결합되어 환경을 에이전트 시스템의 핵심 부분으로 만들며, 에이전트가 학습하고 수행할 수 있는 작업 범위를 직접적으로 형성한다.

#### 2.2.1 Scaling Sandbox Environments

샌드박스 환경은 훈련, 평가, 그리고 ablation을 위해 제어 가능하고 재설정 가능한 작업 상태를 제공한다. 우리의 스위트는 모바일 사용, 컴퓨터 사용, 브라우저 사용, 그리고 DeepSearch 작업을 포괄한다. 각 도메인은 고유의 애플리케이션, 환경별 컨텍스트, 그리고 상태 기반 검증 메커니즘을 유지한다. 인프라의 핵심 강점은 확장성이다: 최대 **10,000**개의 격리된 샌드박스 환경을 병렬로 실행할 수 있어 대규모 롤아웃과 에이전트 훈련이 가능하다.

- Mobile Use. 우리는 MobileWorld가 제공하는 환경을 기반으로 모바일 샌드박스를 구축한다. MobileWorld는 20개의 애플리케이션을 갖춘 재설정 가능한 Android 시스템을 제공하며, GUI 작업 실행, 에이전트-사용자 상호작용, 그리고 MCP 툴 사용을 지원한다 (Kong et al., 2026).  
KVM 기반 에뮬레이터의 확장성 병목을 해결하기 위해, 우리는 redroid (Remote Android Project, 2024)를 사용해 MobileWorld 환경을 재구성하였다. redroid는 QEMU나 중첩 KVM 없이 호스트 커널에서 Android를 컨테이너로 실행한다.  
이 설계는 일반 컨테이너 호스트 전반에 걸쳐 완전한 장치 및 백엔드 환경을 복제할 수 있게 한다.  
컨테이너화된 장치 인스턴스와 자체 호스팅되는 애플리케이션 백엔드는 제어 가능한 초기 상태와 재현 가능한 상태 전이를 제공한다.  
이 인프라를 기반으로 우리는 다양한 작업 관련 환경 컨텍스트를 구성하고, 작업을 합성하며, 상태 기반 검증기를 생성한다.  
결과적으로 생성된 샌드박스는 트레젝터리 수집과 에이전트 훈련을 위한 안정적이고 확장 가능한 환경을 제공한다.  

- Computer Use. 우리는 OSWorld가 제공하는 Ubuntu 가상 머신 환경을 기반으로 컴퓨터 사용 샌드박스를 구축한다. OSWorld는 실제 데스크톱 애플리케이션, 운영 체제 작업, 그리고 교차 애플리케이션 워크플로우를 지원한다 (Xie et al., 2024).  
표준 OSWorld 상호작용 인터페이스는 GUI 기반이지만, 우리는 직접 bash 실행을 추가해 에이전트가 동일 트레젝터리 내에서 GUI 작업과 CLI 명령을 번갈아 수행할 수 있도록 한다.  
새로 구성한 작업을 위해, 우리는 일부 작업에 대해 작업별 초기 환경 상태와 상태 기반 검증기를 추가로 생성한다.  
이러한 확장 기능은 GUI 전용 및 하이브리드 GUI+CLI 상호작용 모두에서 트레젝터리 수집과 에이전트 훈련을 위한 제어 가능하고 확장 가능한 환경을 제공한다.  

- Browser Use. 우리의 웹 환경은 FastAPI, Playwright (Microsoft, 2020), 그리고 Chromium으로 구현된 독립형 브라우저 런타임이다.  
각 에피소드는 고립된 쿠키, 캐시, 로컬 스토리지를 갖춘 새 Playwright BrowserContext에서 실행되며, 작업별 페이지와 상태에서 시작한다.  
에이전트는 렌더링된 스크린샷을 받고 브라우저 네이티브 GUI 동작을 통해 상호작용한다.  
JavaScript 기반 검증기는 DOM과 지속적인 애플리케이션 상태를 검사하여 대체 행동 시퀀스를 허용한다.

#### <span id="page-8-0"></span>2.2.2 실제 장치 모바일 환경: 시뮬레이션 샌드박스에서 실제 세계 학습으로 (Real-Device Mobile Environment: From Simulated Sandboxes to Real-World Learning)

왜 실제 장치가 중요한가? 샌드박스 환경은 안정적이고 재설정 가능한 작업 상태를 제공하여 대규모 배포와 훈련에 필수적이다. 그러나 샌드박스는 진화하는 애플리케이션 상태, 권한 관련 제약, 예기치 않은 팝업 및 네트워크 불안정과 같은 실행 시간 중단을 완전히 포착하지 못한다. 실제 장치에서는 애플리케이션 인터페이스와 콘텐츠가 시간이 지남에 따라 변하고, 권한 및 CAPTCHA가 실행을 방해하며, 네트워크나 장치 고장이 언제든 발생할 수 있다. 중국 모바일 생태계는 슈퍼 앱, 복잡한 인터페이스, 빈번한 팝업으로 이러한 도전을 더욱 가중시켜, 샌드박스에서 이러한 실행 경로를 재현하는 것이 불가능하다. Qwen-UI-Agent가 이러한 조건에서도 신뢰성 있게 동작하도록 하기 위해, 우리는 실제 장치 모바일 런타임을 구축하고 이를 모델 훈련 및 평가에 사용한다. 또한 Section 3.2에서 소개되는 MobileWorld-Real을 구성하여 실제 장치에서 에이전트 성능을 체계적으로 평가한다.

**실제 장치 모바일 런타임.** 우리는 100개가 넘는 물리적 장치와 150개가 넘는 애플리케이션으로 구성된 실제 장치 모바일 런타임을 구축한다. 이 규모에서 각 작업에 신뢰할 수 있고 사용 가능한 실행 장치를 할당하는 것이 핵심 시스템 과제로 부각된다. 그림 4에 표시된 바와 같이, 건강 인식 스케줄러는 각 장치, 애플리케이션, 계정, 네트워크 연결 및 디스플레이의 상태와 가용성을 지속적으로 추적한다.

작업이 큐에 들어오면, 적합한 실행 대상이 선택되고 필요한 리소스가 작업에 할당되며, 실패가 발생하면 실행이 다른 대상으로 재전송된다. 이러한 건강 인식 오케스트레이션은 실제 휴대폰, 애플리케이션, 네트워크 연결의 고유 불안정성으로 인한 환경 측면 실패에도 불구하고 환경을 생산적으로 유지한다.

실제 장치 환경을 더욱 확장하기 위해, 우리는 단일 휴대폰이 별도 디스플레이에서 동시에 여러 애플리케이션 세션을 호스팅할 수 있는 가상 화면 메커니즘 [(Genymobile,](#page-45-5) [2018)](#page-45-5)을 활용한다. 런타임 컨트롤러는 각 가상 디스플레이를 해당 에이전트 세션에 바인딩하여 관측이 올바른 에이전트에 전달되고, 그 에이전트의 행동이 의도한 디스플레이에서 실행되도록 보장한다. 이 설계는 물리적 장치를 비례적으로 늘리지 않고도 활성 실행 환경 수를 증가시킨다. 또한 실제 작업은 종종 명시적 사용자 승인(데이터 민감 또는 결제 관련 작업) 또는 사용자가 제공해야 하는 누락된 정보를 포함한다. 따라서 우리는 누락된 정보를 제공하고, 데이터 민감 또는 결제 관련 작업에 대한 명시적 확인을 얻으며, CAPTCHA와 같은 직접적인 인간 개입이 필요한 작업이 있을 때 사용자가 제어를 인수하도록 하는 전용 User Agent를 도입한다. 필요한 입력이나 작업이 완료되면, 작업은 업데이트된 환경 상태에서 재개된다.

실제 장치 런타임은 또한 모델 실패와 실행 환경 자체의 실패를 구분해야 한다. 애플리케이션 제한, 서비스 불가, 불안정한 장치, 네트워크 오류는 모델의 결정이 유효하더라도 궤적을 중단시킬 수 있다. 스케줄러는 불건전 장치에 대한 동적 블랙리스트를 유지하고, 라우팅에서 제외한 뒤 수동 검토 후에만 복원한다. 우리는 VLM 기반 판사를 사용해 전체 궤적을 검토하고, 작업 성공, 모델 실패, 환경 실패 중 구분한다. 확인된 환경 실패는 스케줄러와 유지 보수 큐를 업데이트하고, 검증된 궤적은 훈련에 보존된다.

#### <span id="page-9-0"></span>**2.2.3 하이브리드 GUI+CLI 액션 공간**

실제 장치 환경은 에이전트가 직면할 수 있는 상태 범위를 확장하지만, 실제 세계에서의 활용도는 에이전트가 이를 얼마나 효과적으로 수행할 수 있는지에 달려 있다. GUI 상호작용은 사용자 인터페이스가 있는 애플리케이션과 시각적 컨텍스트에 대한 보편적 접근을 제공하지만, 순수 GUI 실행은 구조화된 작업을 기초화, 클릭, 입력과 같은 긴 시퀀스로 전환시킬 수 있다. CLI 실행은 파일, 코드, 시스템 설정 및 배치 작업에 대한 직접적인 프로그래밍 접근을 제공하지만, 작업이 시각적 이해, 애플리케이션별 인터페이스, 또는 프로그래밍 가능한 접근이 없는 서비스에 의존할 때는 덜 적합하다. 따라서 GUI와 CLI는 환경 접근의 상호 보완적인 형태를 제공한다: GUI는 광범위한 애플리케이션 커버리지와 시각적으로 기반된 상호작용을 가능하게 하고, CLI는 프로그래밍 상태에 대한 효율적인 실행을 제공한다.

따라서 우리는 Qwen-UI-Agent를 Section [2.1.2,](#page-5-1)에서 정의한 통합 GUI+CLI 액션 공간으로 장착하고, 우리의 환경은 단일 실행 인터페이스를 통해 두 가지 접근 방식을 모두 노출한다. 컴퓨터 사용 환경에서 모든 액션은 VM 내부의 경량 실행 서비스로 전달된다: GUI 액션은 네이티브 입력 이벤트로 변환되고, `cli_command`는 터미널 애플리케이션을 시각적으로 찾고 조작하지 않고 비대화형 셸에서 명령을 실행한다. 결과적으로 생성된 `stdout`, `stderr`, 그리고 종료 상태는 구조화된 관측값으로서 사후 액션 스크린샷과 함께 반환되어, 모델이 프로그래밍적 및 시각적 상태를 동시에 고려하여 다음 결정을 내릴 수 있게 한다.

<span id="page-9-1"></span>신뢰할 수 있는 CLI 실행은 셸을 생성하는 것 이상의 환경 측면 처리를 필요로 한다. 명령 실행은 종속성 설치와 같은 느린 작업을 위해 예산된 타임아웃에 의해 제한되며, 비영(0) 종료 및 타임아웃과 같은 실패는 에피소드를 중단시키는 대신 오류 관측값으로 반환되어 모델이 같은 궤적 내에서 진단하고 복구할 수 있게 한다. 배치 액션에서는 GUI와 CLI 하위 액션이 순서대로 실행되고, CLI 출력은 하나의 관측값으로 집계된다. 실행된 명령은 셸 히스토리에도 기록되어, 터미널 상태를 검사하는 검증자가 CLI 기반 솔루션을 인정하도록 한다.

#### **2.2.4 Heterogeneous 환경을 위한 통합 인터페이스 (Unified Interface for Heterogeneous Environments)**

모바일 사용, 컴퓨터 사용, 브라우저 사용, 그리고 DeepSearch 환경은 서로 다른 자원 모델, 액션 공간, 관측 형식, 그리고 검증 절차를 노출한다. 따라서 우리는 환경 수명 주기와 에이전트가 마주하는 입력 및 출력을 표준화하고, 실행, 재설정, 검증을 환경별 어댑터에 위임하는 통합 환경 인터페이스를 도입한다. 이를 통해 동일한 에이전트와 학습 파이프라인이 서로 다른 환경에서 동일한 런타임 시맨틱스를 강제하지 않고도 운영될 수 있다.

인터페이스는 acquire, reset, step, evaluate, tear_down, release로 구성된 공통 비동기 수명 주기를 노출한다. 각 획득된 환경은 백엔드에 바인딩된 임대 세션으로 표현되며, 필요에 따라 디스플레이 식별자와 연결되어 스크린샷, 액션, 평가를 동일한 격리된 컨텍스트로 일관되게 라우팅한다. 백엔드 어댑터는 자원 초기화, 관측 캡처, 액션 실행, 평가를 구현하고, 태스크 어댑터는 플랫폼별 재설정 및 검증 로직을 보존한다. 모든 환경은 관측값, 종료 신호, 보상 정보를 포함하는 공통 전이 형식을 반환한다.

정책과 환경은 각각 독립적으로 그들의 네이티브 액션 공간을 선언한다. 두 공간이 다를 경우, 지원되는 GUI 동작은 표준 중간 표현을 통해 번역되며, 좌표는 대상 플랫폼에 따라 정규화된다. Section [2.1.2](#page-5-1)에서 정의된 하이브리드 GUI, CLI, API 동작은 네이티브 어댑터를 통해 계속 사용 가능하며, 그 시각적 또는 구조화된 결과는 동일한 관측 스트림을 통해 반환된다. 이 설계는 공유된 롤아웃, 데이터 수집, 평가 파이프라인을 제공하면서 각 플랫폼의 네이티브 상호작용 의미론을 보존한다.

### <span id="page-10-0"></span>2.3 에이전트 주도 데이터 플라이휠 (Agent-Driven Data Flywheel)

GUI 에이전트를 지속적으로 개선하려면 과제 설계, 환경 구축, 검증기 개발, 데이터 선별, 모델 학습, 평가, 오류 분석을 아우르는 반복적이고 폐쇄된 루프가 필요하다. 인간이 이 단계들을 주도하면, 애플리케이션, 플랫폼, 역량 차원에서 범위가 확대될수록 반복이 느려지고 확장하기 어려워진다. 이 문제를 해결하기 위해 우리는 AutoResearch 스타일의 에이전트 주도 데이터 플라이휠을 도입한다. 이 플라이휠은 인간의 개입을 각 단계의 실행에서 고수준 감독과 목표 지향적 개입으로 전환한다.

**Overall Procedure.**  
그림 [5,](#page-11-0)에서 보듯이, 우리는 에이전트 기반 데이터 플라이휠(agent-driven data flywheel)을 두 단계로 구성한다: 도메인 역량 부트스트래핑(domain capability bootstrapping)과 반복적 정제 루프(iterative refinement loop). 부트스트래핑 단계에서는 강력한 기초 모델(foundation models)을 사용해 모바일, 데스크톱, 웹 등 다양한 도메인에 필요한 도메인 지식과 역량을 분석한다. 이 분석을 바탕으로 에이전트는 초기 작업 풀과 해당 작업에 대한 환경 컨텍스트를 생성하고, 그 중 후보 궤적을 수집한다. MAI-UI [(Zhou et al.,](#page-50-0) [2025a)](#page-50-0)에 따라, 우리는 먼저 여러 차례 거절 샘플링(rejection sampling)을 수행하고, 수락된 궤적을 하나의 통합 SFT 코퍼스(SFT corpus)로 집계한다. 이 과정은 목표 도메인을 광범위하게 커버하는 강력한 초기 정책(policy)을 생성한다. 이 정책을 기반으로 에이전트 기반 실패 분석(failure analysis)은 모델의 남은 약점을 식별하고, 이를 다음 주기에 대한 목표로 매핑한다. 이러한 목표는 새로운 작업, 환경 구성, 그리고 해당되는 경우 작업별 검증기(task-specific verifiers)의 생성을 안내한다. 수락된 궤적은 이후 훈련 코퍼스에 통합되어 모델을 더욱 향상시키며, 이를 통해 루프를 닫고 다음 반복을 시작한다. 초기 정책 구축 단계와 반복적 개선 단계 모두에서 강력한 기초 모델은 작업과 환경 구성을 생성하고, 작업별 검증기를 합성하며, 궤적을 평가하고, 실패를 분석하고, 이후 반복의 최적화 및 실행을 계획한다. 인간 개입(human involvement)은 주로 전체 시스템을 설계·구현하고 운영을 감독하며, 필요 시 워크플로를 개입하거나 수정하는 데 집중한다. 다음으로, 이 에이전트 기반 데이터 플라이휠을 확장 가능하고 효과적으로 만드는 네 가지 설계 선택을 설명한다.

Figure 5: Qwen-UI-Agent의 데이터 플라이휠. 도메인 역량 부트스트래핑은 훈련을 초기화하고, 반복 정제 루프는 역량 약점을 식별하고 목표 과제를 생성하며, 그 결과 데이터는 다음 훈련 반복을 개선한다.

지식 및 능력 인식 기반 작업 합성. 훈련 작업은 모델이 사용할 수 있는 학습 신호를 정의하며, 따라서 모델이 습득할 수 있는 지식과 행동을 형성한다. 우리는 작업 합성을 두 가지 개념적으로 구분되는 차원으로 구성한다: *지식 범위*, 이는 에이전트가 알아야 할 내용을 결정하고, *능력 수요*, 이는 에이전트가 작업을 완료하기 위해 어떻게 추론하고 행동해야 하는지를 결정한다. 지식 범위는 애플리케이션 기능, 인터페이스 규약, 도구 사용, 그리고 일반적인 워크플로우를 포함한 도메인 특화 운영 지식을 명시한다. 능력 수요는 장기 상태 추적, 정밀 제약 준수, 수치 및 시간 추론, 오류 복구와 같은 전이 가능한 추론 및 상호작용 능력을 포착한다. 각 대상 도메인에 대해 우리는 강력한 기초 모델을 사용하여 지식 범위에 대한 초기 계층적 함수 트리와 능력 수요에 대한 능력 프로필을 구축한다. 그런 다음 이를 재사용 가능한 작업 합성 스킬에 컴파일하여 구성 규칙, 난이도 제어, 환경 전제 조건, 대표 예시를 포함한다. 현재 반복의 목표에 따라 이 스킬은 에이전트가 필요한 지식과 능력에 맞춰 작업을 자동으로 생성하도록 한다.

**에이전트 주도 환경 및 검증자 합성.** 작업 합성은 훈련 인스턴스가 유도해야 할 역량을 결정하지만, 상호작용 훈련은 작업이 실행 가능하고 수행 가능한 재현 가능한 환경을 추가로 요구한다. 합성된 작업을 바탕으로 우리 에이전트는 *Environment State Synthesis* (섹션 2.4.3에 자세히 기술됨)를 사용하여 실행에 필요한 애플리케이션 상태, 파일, 기록, 계정 및 교차 애플리케이션 컨텍스트를 구성한다. 신뢰할 수 있는 결과를 검증할 수 있는 작업에 대해, 에이전트는 추가로 상태 기반 검증자를 합성하여 결과 애플리케이션, 파일, 데이터베이스 또는 시스템 상태를 검사하고 실행 가능한 작업-검증자 쌍을 생성한다.

**단계별 판단을 통한 확장 가능한 SFT 및 온라인 RL용 실행 검증.** 실행 가능한 검증자는 고정밀 결과 신호를 제공하지만, 하나를 구성하고 검증하는 데 비용이 많이 든다. 더 강력한 기초 모델을 사용하더라도 실행 가능한 검증자를 합성하고 검증하는 작업은 여전히 시간이 많이 걸리며, 반면 모델 기반 판정기의 정확도는 모델 개발과 함께 향상된다. 따라서 우리는 MAI-UI (Zhou et al., 2025a)에서 사용된 단계별 궤적 판정기를 확장하고, 모바일, 웹, 컴퓨터 사용 궤적에 VLM 기반 판정기를 적용한다. 여기에는 하이브리드 GUI+CLI 상호작용이 포함된다. 지시문, 궤적, 시각적 또는 구조화된 관찰을 바탕으로 판정기는 유용한 감독의 세 가지 형태를 추출한다: 작업을 올바르게 진행하는 최대 연속 단계, 각 반성 또는 탐색 단계의 시작을 촉발하는 첫 번째 단계, 그리고 오류 상태에서 정상 경로로 실행을 복구하는 복구 세그먼트가 to a

유효 경로. 첫 번째 반성 또는 탐색 단계만 보존하면 재고를 고려하는 유용한 결정을 포착하면서 잠재적으로 노이즈가 있는 분기점을 과도하게 보존하지 않는다. 이 세밀한 절차는 성공적이든 실패한 궤적이든 효과적인 훈련 신호를 복구한다. 실험적으로 우리는 단계별 데이터 필터링이 실행 가능한 검증기로 선택된 전체 궤적에 대한 훈련과 비교해 SFT 성능이 동등하거나 더 우수함을 발견한다. 따라서 우리는 세밀한 VLM 판단을 사용해 SFT의 프로세스 감독을 확장하고, 온라인 RL에 필요한 고정밀 결과 신호를 위해 실행 가능한 검증자를 구성한다.

**실패 분석 기반 반복.** 우리는 각 도메인마다 모델 성능을 추적하고 다음 반복의 최적화 목표를 정의하기 위해 광범위하고 진단적인 평가 세트를 구축한다. 실패한 각 작업에 대해 분석 에이전트는 전체 경로를 검토하고 모델 실패를 환경, 작업, 또는 검증자 실패와 구분한다. 모델 실패는 이후에 구조화된 원인으로 매핑된다. 예를 들어, 애플리케이션 지식 부족, 제약 위반, 상태 추적 오류, 또는 검증 부족 등이 있다. 시스템은 이러한 작업 수준 진단을 집계하여 현재 정책의 가장 흔하고 중대한 약점을 식별하고 이를 우선순위가 높은 최적화 목표 집합으로 변환한다. 이러한 목표와 작업 합성 기술에 따라 에이전트는 다음 주기에 맞는 목표 작업과 해당 환경 설정, 그리고 해당되는 경우 작업별 검증자를 생성한다. 모델과 무관한 문제는 환경 유지보수 또는 작업 및 검증자 개정으로 전달되어 에이전트가 식별된 문제를 진단하고 해결한다.

### <span id="page-12-0"></span>2.4 훈련 (Training)

#### <span id="page-12-1"></span>2.4.1 감독형 미세조정 (Supervised Fine-Tuning (SFT))

Qwen-UI-Agent는 모바일, 컴퓨터 사용, 웹, 그리고 DeepSearch 환경에서 작업 실행을 지원하도록 설계되었다. 이 범위는 SFT에 두 가지 상호 연결된 과제를 제시한다: 단일 모델 내에서 모든 대상 도메인에 걸쳐 강력한 역량을 동시에 획득하고, 견고한 실제 세계 작업 완료에 필요한 일반적인 추론 및 에이전트 역량을 보존하는 것이다.

**도메인-조건부 전문가 훈련.** 모바일, 데스크톱, 웹 각 도메인은 에이전트에 대해 서로 다른 요구를 제시한다. 모바일 작업은 실제 장치 환경에서 신뢰할 수 있는 실행을 필요로 하며, 인터페이스는 앱별이며, 워크플로우는 팝업에 의해 자주 중단되고, 안전에 민감한 동작은 사용자 제어 하에 있어야 한다. 데스크톱 작업은 GUI 제어와 Bash 기반 파일 및 시스템 운영을 결합하는 경우가 많다. 웹 작업은 동적 웹페이지와의 상호작용을 요구하며, DeepSearch 작업은 에이전트가 검색 API를 통해 증거를 검색, 검증 및 종합하도록 요구한다.

우리는 각 도메인에 대해 특화된 전문가를 훈련한 뒤 그 역량을 통합한다. 각 전문가는 주로 대상 도메인의 데이터로 훈련되며, 다른 도메인의 데이터와 통제된 혼합을 함께 사용한다. 이 교차 도메인 혼합은 각 전문가가 도메인 간에 전이되는 역량을 유지하도록 돕고, 대상 도메인에 과적합되는 것을 줄인다. 실용적인 배포는 모든 지원 설정에서 작동할 수 있는 단일 모델을 요구한다. 따라서 우리는 도메인-전문가 체크포인트를 통합하여 통합 모델을 만든다. 모델 병합은 그들의 상호 보완적인 강점을 단일 체크포인트 내에서 결합하여 개별 전문가가 획득한 역량을 거의 추가 훈련 오버헤드 없이 보존한다.

**일반 및 에이전트 역량 보존 (In-Distribution Data).** 일반적인 추론 및 에이전트 역량은 실제 세계 사용에 필수적이며, 에이전트는 다양한 개방형 사용자 요청에 대응해야 한다. 일부 요청은 GUI 작업과 전혀 관련이 없을 수 있지만, 모델은 여전히 적절히 대응해야 한다. GUI 작업 내에서도 실제 배포는 모델이 훈련 중에 예상하지 못한 지식, 추론, 지시 따르기, 검색, 코딩, 또는 도구 사용이 필요할 수 있는 OOD(Out-of-Distribution) 상태와 목표에 노출된다. 따라서 우리는 기본 모델에서 상속받은 일반적인 추론 및 에이전트 역량을 보존하고, 가능하다면 강화하려고 한다. 이는 익숙하지 않은 상황을 처리하고 일관된 사용자 경험을 유지하는 데 중요한 기반을 제공한다.

우리는 가장 효과적인 전략이 시작 모델이 생성할 수 있는 성공적인 행동을 강화하는 in-distribution 데이터를 사용하는 것임을 발견한다. 우리는 일반 질문 응답, 수학, 코딩, 시각적 이해, 검색, 그리고 에이전트형 도구 사용을 포괄하는 광범위한 질의 풀을 구성하고, 시작 모델의 응답을 샘플링하며, 형식 정규화 후 검증된 정답 예시만을 보관한다. 이 예시 중 일부를 SFT 과정에서 GUI 트래젝터리와 혼합한다. 실험 결과, 시작 모델이 해결할 수 있는 예시는 실패하는 어려운 예시보다 능력 보존에 훨씬 효과적이다. 전자는 모델 자체의 응답 분포와 정렬된 목표를 사용해 확립된 능력을 재연습하고, 후자는 학습을 능력 획득으로 전환하며 경쟁적 최적화 신호를 도입할 수 있다.

슬라이딩 윈도우 학습은 효율적인 장기 트래젝터리 SFT를 위해 사용된다. 장기 트래젝터리 SFT는 각 행동이 시각적·텍스트적 맥락과 함께 별개의 학습 샘플로 포장될 때 비용이 많이 들며, 인접 행동 간에 매우 겹치는 맥락이 반복적으로 처리된다. 따라서 우리는 각 트래젝터리를 연속된 5단계(n=5)의 윈도우로 나누고, 각 윈도우를 n−1=4 단계씩 이동시켜 인접 윈도우 사이에 한 단계 겹침을 둔다. 이 겹침은 이후 윈도우에서 처음 새로 감독되는 행동이 최소 두 개의 스크린샷을 조건으로 할 수 있게 한다. 이후 윈도우에서는 공유 경계 단계가 입력 맥락에 남아 있지만, 이전 윈도우에서 이미 감독되었으므로 손실이 마스킹된다. 따라서 각 완전한 이후 윈도우는 네 개의 새로운 행동을 감독한다. 현재 윈도우 이전의 스크린샷은 시각 입력에서 제외되고, 이전 텍스트 트래젝터리 기록은 맥락으로 유지된다. 공동 감독은 이 반복되는 맥락 처리를 줄이고, 처리된 맥락당 감독되는 행동 목표 수를 늘려 학습 효율을 향상시킨다.

#### <span id="page-13-0"></span>**2.4.2 행동 RL: 반복되는 행동 오류 수정 (Action RL: Correcting Recurring Action Errors)**

장기 GUI 과제에서 단일 지역 오류는 인터페이스를 잘못된 상태로 이동시키고 이후 결정에 영향을 미칠 수 있다. SFT는 성공적인 시연에서 학습하지만 반복되는 행동 오류를 명시적으로 억제하지 않는다. 따라서 우리는 행동 수준의 강화 학습 단계인 Action RL을 도입한다. 이 단계는 목표 지향적 오류 패턴 데이터와 행동 인식 보상을 결합해 지역 결정 신뢰성을 향상시킨다.

반복되는 행동-오류 패턴.

- *혼동 가능한 요소 기반 정착.* 화면에 시각적 또는 의미적으로 유사한 아이콘, 컨트롤, 또는 리스트 항목이 포함될 때, 모델은 올바른 대상이 아닌 인접한 방해 요소에 행동을 정착시킬 수 있다.  
- *정렬 및 순위.* 모델은 순서 요구사항(순위 위치, top-*k* 선택, 최신 vs. 오래된 순서, 다중 속성에 기반한 순위 등)을 잘못 해석하여 잘못된 항목을 선택하거나 항목을 잘못된 순서로 처리할 수 있다.  
- *수량 및 다중 대상 완전성.* 정확한 수량을 지정하거나 여러 관련 대상에 대한 행동을 요구하는 작업은 부분 완성에 취약하다. 모델은 너무 적거나 너무 많은 객체를 처리하거나 복합 목표의 한 구성 요소를 누락할 수 있다.  
- *조기 완료.* 모델은 최종 상태 변경 행동(편집 저장, 메시지 전송, 폼 제출, 콘텐츠 게시 등)을 실행하기 전에 의도된 결과를 준비한 뒤 성공을 선언할 수 있다.  
- **반복 행동 루프.** 모델은 인터페이스 상태가 변경되지 않았음을 인식하지 못하거나 복구 행동을 식별하지 못해, 작업과 관련된 진전을 이루지 못하고 같은 행동이나 짧은 행동 시퀀스를 반복 실행할 수 있다.  
- **롱테일 행동 선택 실패.** 모델은 드물지만 중요한 행동(열기, ask_user, long_press 등)을 호출하지 못하고 대신 부적절한 빈번한 행동(클릭 등)으로 대체할 수 있다.

이러한 실패의 공통 구조는 애플리케이션 전반에 걸쳐 행동 수준 최적화의 재사용 가능한 목표가 된다. 그러나 그 중요성은 자연적으로 수집된 궤적에서의 빈도에 반영되지 않는다: 드물지만 결과에 큰 영향을 미치는 패턴은 더 흔한 행동에 의해 압도될 수 있다.

**목표 지향 오류 패턴 데이터 구축.** 이 커버리지 불균형을 교정하기 위해, 우리는 과거 궤적 탐색과 적극적인 환경 상호작용을 결합한다. 기존 궤적에서 각 실패를 유발하는 행동을 위치화하고, 반복 행동의 경우 시각적 판단자가 비생산적 루프와 목적 있는 탐색을 구분한다. 역사적 커버리지가 부족한 패턴에 대해, 에이전트는 실행 가능한 환경을 적극 탐색하고 관련 인터페이스 구조를 식별하며, 이를 중심으로 과제를 구성하고 새로운 롤아웃을 수집한다. 결과 코퍼스는 현재 정책에서 현실적인 실패 맥락을 보존하면서, 드물지만 중요한 오류의 표현을 의도적으로 증가시킨다.

**행동 인식 보상 및 훈련.** 이 목표 지향 코퍼스를 사용하여 행동 RL은 단계 *t*에서 예측된 각 행동에 구조화된 보상을 부여한다:

$$r_t = F_t \left( w_{\text{type}} C_t + w_{\text{arg}} C_t Q_t - \lambda_{\text{sens}} S_t - \lambda_{\text{rep}} L_t \right). \tag{5}$$

여기서 *F<sup>t</sup>* ∈ {0, 1} 은 형식 유효성을 나타내고, *C<sup>t</sup>* 은 행동 유형 정확성을 측정하며, *Q<sup>t</sup>* 은 픽셀 거리, 어휘 유사성, 태그 매칭, 또는 LLM 기반 판단을 사용해 인수 품질을 측정한다. 항목 *S<sup>t</sup>* 와 *L<sup>t</sup>* 은 각각 잘못된 민감한 행동과 행동 이력에서의 반복을 처벌한다. 훈련 중에 우리는 토큰 엔트로피 감소와 점진적으로 짧아지는 추론 트레이스를 관찰한다. 따라서 정책 붕괴를 방지하면서 불필요한 장황함을 피하기 위해 엔트로피 정규화와 추론 길이의 하한 및 상한을 함께 적용한다.

#### <span id="page-14-0"></span> **2.4.3 온라인 RL: 장기 경로 의사결정 (Online RL: Learning Long-Horizon Decision Making)**

장기 경로 GUI 작업은 단순히 지역적으로 올바른 행동의 모음이 아니다. 행동은 현재 상태에서 합리적으로 보일 수 있지만, 에이전트를 미래 상태로 이끌어 작업이 어려워지거나 불가능해질 수 있다. 행동 RL은 지역적 의사결정 신뢰성을 향상시키지만, 이러한 지연된 궤적 수준의 결과를 완전히 포착하지 못한다; 따라서 우리는 온라인 RL을 도입하여 환경 상호작용을 통해 엔드투엔드 작업 성공을 최적화한다.

**확장 가능한 롤아웃을 위한 통합 환경 인프라스트럭처**

완전한 상호작용으로부터 학습하려면 이질적인 GUI 환경 전반에 걸쳐 대규모이며 신뢰할 수 있는 롤아웃 생성을 요구한다.  
섹션 [2.2.1,](#page-6-2)에서 설명한 샌드박스 인프라를 기반으로, 우리는 도메인 간에 환경 할당, 재설정, 상호작용 및 평가를 관리하는 통합 환경 인프라스트럭처를 개발한다.  
Alibaba Cloud에서, 이 인프라스트럭처는 모바일, 컴퓨터 사용, 웹 및 DeepSearch를 위한 샌드박스 환경을 배포하며 최대 10,000개의 동시 롤아웃을 지원한다.  
각 도메인은 자체 네이티브 애플리케이션, 액션 공간 및 검증 메커니즘을 유지하면서, 공유 인프라스트럭처는 공통 환경 수명 주기와 롤아웃 인터페이스를 학습 파이프라인에 노출한다.  
물리적 휴대폰에서 실행해야 하는 작업의 경우, 섹션 [2.2.2,](#page-8-0)에서 설명한 가상 화면(virtual-screen) 메커니즘을 사용하여 단일 기기의 별도 디스플레이에서 여러 애플리케이션 세션이 동시에 실행되도록 한다.  
우리의 실제 기기 클러스터 전반에서, 이 메커니즘은 가상 화면 없이 동일한 클러스터를 실행할 때보다 약 20배의 총 롤아웃 처리량을 증가시킨다.  
이 인프라스트럭처는 온라인 RL을 위해 샌드박스와 실제 기기 환경 모두에서 확장 가능한 롤아웃 용량을 제공한다.

**작업–검증자 합성.** 이 롤아웃 인프라를 기반으로, 우리는 실행 가능한 작업-검증자 쌍을 자동으로 구성하여 세 단계에 걸쳐 신뢰할 수 있는 결과 감독을 제공한다:

• **환경 상태 합성(Environment State Synthesis).** 코딩 에이전트는 각 샌드박스의 기반이 되는 코드베이스를 분석하고, 애플리케이션에 재사용 가능한 데이터 주입 기술(data-injection skills)을 추출한다. 이러한 기술을 활용해 에이전트는 여러 애플리케이션에 걸친 일관된 초기 환경 상태(environment state)를 구성한다. 예를 들어, 논문 제출을 준비 중인 컴퓨터 과학 박사 과정을 밴 학생을 나타내는 환경 상태는 학생의 휴대폰 전역에 걸쳐 상호 일관된 이메일, 사진, 파일, 캘린더 이벤트, 소셜 미디어 기록을 포함할 수 있다. 환경 상태 합성은 downstream 작업의 난이도와 다양성을 크게 결정하기 때문에 중요하다. 벤치마크에서 제공되는 상태만으로 직접 작업을 생성하면 작업 합성이 애플리케이션 상태와 이미 벤치마크에 존재하는 데이터에 한정된다.

- **작업 합성(Task Synthesis).** 각 합성된 환경 상태를 기준으로 LLM은 서로 다른 난이도 수준의 여러 작업을 생성하며, 이는 여러 애플리케이션을 아우르는 워크플로우를 포함한다. 독립적인 LLM 판정자(LLM judge)는 생성된 작업을 실현 가능성과 초기화된 환경 상태와의 일관성을 위해 필터링한다.
- **검증자 합성(Verifier Synthesis).** 통합된 환경 인프라를 활용해 코딩 에이전트는 해당 샌드박스를 자율적으로 실행하고, 합성된 환경 상태를 주입하며, 작업별 코드 기반 검증자(codebased verifiers)를 구성한다. 각 검증자는 여러 에이전트 모델의 롤아웃을 통해 검증되며, VLM 기반 판정자(VLM-based judge)는 검증자 출력이 관측된 롤아웃 증거와 일치하는지 평가한다.

이 자동화된 합성 및 실행-검증 파이프라인은 온라인 RL을 위해 약 10,000개의 검증된 작업–검증자 쌍을 생성한다.

**온라인 RL with a Model-Adaptive Task Curriculum.** 주어진 검증된 작업–검증자 쌍을 사용하여, 우리는 검증자-지향 온라인 RL을 통해 장기 경로 의사결정을 개선한다. MAI-UI [(Zhou et al.,](#page-50-0) [2025a)](#page-50-0)를 따라, 우리는 GUI 상호작용 궤적에 대해 Group Relative Policy Optimization (GRPO)의 맞춤형 변형을 채택한다. 각 작업마다 현재 정책은 *K*개의 완전한 상호작용 궤적 {*τi*} *K i*=1 을 샘플링한다. 검증자는 각 궤적의 최종 환경 상태 *s* (*i*) *T* 를 평가한다. 우리는 그 이진 결과 보상과 그룹-상대적 이점을 계산한다.

$$r_i = v_x(s_{\text{final}}^{(i)}) \in \{0, 1\}, \quad \bar{r}_x = \frac{1}{K} \sum_{j=1}^K r_j, \quad \hat{A}_i = \frac{r_i - \bar{r}_x}{\text{Std}(r_1, \dots, r_K) + \epsilon}.$$

(6)

평균(평균)과 표준편차(표준편차)는 같은 작업 *x*에 대해 샘플링된 *K*개의 롤아웃(롤아웃)에서 계산된다. GRPO는 이러한 상대적 이점(상대적 이점)을 사용해 정책(정책)을 업데이트한다. 행동 기반 강화학습(action RL)은 행동 수준 피드백(행동 수준 피드백)을 제공하는 반면, 이 단계는 종료 검증 결과(종료 검증 결과)를 이용해 완전한 경로(완전한 경로)를 최적화하며, 장기 계획(long-horizon planning), 상태 추적(state tracking), 중간 의사결정(intermediate decision making)을 목표로 한다.

작업의 훈련 가치는 고정되지 않는다: 처음에는 너무 어려운 작업이 정책이 다른 작업에서 관련 능력을 획득함에 따라 학습 가능해질 수 있다. 그룹 상대 목표 하에서는 모든 롤아웃이 실패하거나 모두 성공하는 작업은 보상 변동이 없으므로 즉각적인 학습 신호가 거의 제공되지 않는다. 그러나 어려운 작업을 영구적으로 제거하면 정책의 학습 프런티어에 진입하는 시점을 놓치게 된다. 따라서 우리는 작업 난이도를 현재 정책의 동적 특성으로 간주하고 커리큘럼을 활성 훈련 풀과 모니터링 풀로 구성한다. 중간 정도의 경험적 성공률을 가진 작업은 활성 풀에 들어가 전체 롤아웃 예산을 받으며, 현재 해결 불가능한 작업은 작은 예산으로 모니터링 풀에 남아 있다. 어려운 작업이 성공적인 롤아웃을 생성하기 시작하면, 전체 규모 훈련을 위해 활성 풀로 승격된다. 마스터된 작업도 작은 예산으로 모니터링되며 성능이 감소하면 재활성화된다. 이 폐쇄 루프 커리큘럼은 새로 학습 가능한 작업을 지속적으로 식별하면서 가장 유익한 상대 보상을 제공하는 곳에 롤아웃 계산을 집중한다.

### <span id="page-15-0"></span>2.5 Harness Layer: Proactive Service and Cross-Platform Task Execution (활성 서비스 및 크로스 플랫폼 작업 실행)

강력한 작업 실행은 필요하지만, GUI 에이전트가 단일 작업 실행을 넘어 사용자의 일상 디지털 생활에서 효과적인 도우미가 되기 위해서는 충분하지 않다. 기존 에이전트는 대부분 반응형이다: 사용자는 필요를 인식하고 명령을 수립하며 에이전트를 호출해야 하며, 그 필요가 이미 디지털 환경의 신호에서 명백히 드러나더라도 마찬가지다. 워크플로우는 장치를 초월할 수 있으며, 관련 정보가 휴대폰에 나타나고 이후 조치는 컴퓨터에서 완료되어야 할 수도 있다. 이는 두 가지 근본적인 격차를 만든다: *언제* 에이전트가 지원을 시작해야 하고, *어떻게* 그 결과 워크플로우를 장치 간에 맥락을 잃지 않고 전달할 수 있을까? 우리는 기본 GUI 에이전트 위에 공유 하네스 레이어를 통해 두 문제를 모두 해결한다. 하네스는 사용자의 디지털 환경에서 신호를 연결하고, 진행 중인 활동의 통합 표현을 유지하며, 이 컨텍스트를 사용해 모바일과 컴퓨터 환경 간에 작업을 시작하고 조정한다.

![](2026-08-01-2607.28227-qwen-ui-agent-technical-report-toward-next-generation-real-w/_page_16_Figure_0.jpeg)

그림 6: 프로액티브 서비스 시작 및 크로스 플랫폼 실행을 위한 하네스 개요. (I) 하네스가 없으면 사용자는 알림을 수동으로 해석하고 관련 컨텍스트를 검색하며 에이전트에 지시를 제공해야 한다. 프로액티브 하네스는 대신 항공편 취소를 감지하고 관련 사안을 추론하며 항공편 재예약, 철도 대안, 회의 충돌 검사를 사전에 수행하고 실행 가능한 계획을 보고한다. (II) 하네스는 또한 작업 상태를 유지하고 크로스 플랫폼 실행을 지원한다. 식당 선택 예시에서 Qwen-UI-Agent는 모바일에서 후보를 탐색하고, 데스크톱 스프레드시트에 정리하며, 승인용 아티팩트를 전송하고, 선택된 위치를 모바일에 다시 저장한다.

이 층을 기반으로 우리는 두 가지 기능을 개발한다. *Proactive service*는 명시적 지시에서 사용자의 디지털 신호에서 추론된 실행 가능한 이벤트로 작업 시작을 전환함으로써 첫 번째 격차를 해소한다. 이를 통해 에이전트는 사용자가 요청하기 전에 유용한 지원을 식별하고 준비할 수 있다. *Cross-platform task execution*는 휴대폰과 컴퓨터 간에 워크플로우를 옮기면서 공유된 컨텍스트, 종속성, 작업 상태를 보존함으로써 두 번째 격차를 해결한다. 이 두 기능은 GUI 에이전트를 두 가지 상호 보완적인 차원으로 확장한다: *when* 작업이 언제 시작될 수 있는지와 *where* 작업이 어디에서 이어질 수 있는지.

#### <span id="page-16-0"></span>2.5.1 사전 서비스 기반 모바일 알림 (Proactive Service Based on Mobile Notifications)

**모바일 알림은 고가치 신호원이다.** 사전 에이전트는 시기적절하고, 광범위하게 이용 가능하며, 사용자가 제어할 수 있는 신호가 필요하다. 우리는 이 인터페이스로 모바일 알림을 사용한다. 휴대폰은 통신, 여행, 금융, 물류, 일정 관리 등에서 신호를 집계하고, 알림은 항공편 취소, 결제 마감, 일정 변경 등과 같이 실행 가능해지는 순간에 많은 이벤트를 노출한다. 연속 화면, 오디오, 또는 비디오 모니터링과 비교할 때 알림 접근은

경량이며 애플리케이션별 명시적 권한에 의해 관리된다. 알림은 그럼에도 불구하고 부분적이고 잡음이 많다: 애플리케이션이 노출하기로 선택한 것만 보고한다. 따라서 하네스는 이를 완전한 세계 상태가 아니라 관측치로 간주하고, 필요할 때만 추가 정보를 수집한다.

**알림에서 사전 워크플로우로.** 사용자의 다음날 아침 항공편이 취소되었다는 야간 알림을 가정해 보자. 전통적인 GUI 에이전트는 대안 탐색 전에 명시적 지시를 기다린다. 우리는 대신 단순 검색을 넘어서는 사전 워크플로우를 상상한다. 항공편 취소는 드물게 고립된 사건이 아니다: 중요한 회의를 위태롭게 하거나 호텔 예약을 변경해야 하며, 재예약과 철도 여행 중 선택을 강요한다. 핵심 질문은 에이전트가 사용자가 요청하기 전에 이러한 상호 의존적인 후속 조치를 예측하고 준비할 수 있는가이다. 우리의 하네스는 사용자의 주의를 요청하기 전에 더 넓은 문맥을 재구성함으로써 이를 수행한다. 취소를 구조화된 이벤트로 파싱하고, 진행 중인 여행 및 관련 회의 마감일과 연결하고, 메모리에서 사용자 선호도를 검색하고, 실행 가능한 대안을 조회하고, 이를 사용자의 기본 목표와 비교 평가하며, 결정 준비가 된 제안을 제시한다. 재예약이나 예약 변경과 같은 외부 결과를 초래하는 행동은 여전히 사용자 확인이 필요하다. Figure [11](#page-30-0)과 Figure [28](#page-55-0) of Appendix [A.3](#page-52-0)은 이 행동의 두 대표 예시를 보여준다: 사용자의 약속과 실시간 날씨 및 통근 상황을 결합한 예정된 아침 브리핑, 그리고 항공편 취소 알림에 의해 트리거된 사전 여행 복구 계획.

하네스는 이 워크플로우를 상태를 보존하는 파이프라인으로 구현한다. 알림을 구조화된 이벤트로 파싱하고, 이를 지속적인 *affair*와 연결하며, 실행 가능한 작업을 도출하고, 실행 결과를 사용해 메모리와 향후 행동을 업데이트한다. 이 시스템의 핵심 추상화는 지속적인 현실 세계 사건을 나타내는 *affair*이다. *event*는 특정 시점에 발생한 일을 기록하고, *affair*는 이벤트, 애플리케이션, 일 across events, applications, days를 통해 아직 진행 중인 일을 포착하며, *task*는 다음에 수행해야 할 일을 명시한다. 이 분리는 하네스가 사용자의 기본 목표를 추론할 수 있게 한다.

- **이벤트 인식.** 수신되는 알림은 짧은 시간 창에서 처리된다. 이벤트 파서는 낮은 가치의 잡음을 제거하고 유용한 알림을 소스, 엔티티, 타임스탬프, 긴급성, 사용 가능한 행동을 포함하는 구조화된 이벤트로 변환한다. 이러한 이벤트는 시간 순서와 출처와 함께 저장되어 이후 추론을 위한 증거 기반을 제공한다.  
- **사건 상태와 메모리.** 각 신규 이벤트에 대해, 하네스는 관련 최근 이벤트, 활성 사건, 현재 컨텍스트 상태, 프로필 메모리를 검색한다. 그 후 이벤트를 기존 사건에 연결하거나 새 사건을 생성하여 사건의 수명 주기, 핵심 엔티티, 마감일, 미해결 격차 및 지원 증거를 업데이트한다. 사건은 개별 여행, 구매, 회의 또는 가족 문제의 진화하는 상태를 보존하고, 프로필 메모리는 사용자 선호도, 관계, 행동 패턴과 같은 보다 안정적인 지식을 저장한다. 이 두 형태의 메모리는 상황별 추론과 장기 개인화를 결합한다.  
- **사건 수준 추론 및 과제 형성.** 하네스는 업데이트된 사건을 기반으로 예상되는 다음 단계, 누락된 정보, 미완료 행동, 시간 압박, 사건 간의 종속성 또는 충돌을 식별한다. 결론은 관찰된 이벤트 또는 저장된 사용자 정보를 근거로 하며 신뢰도 추정과 연결된다. 과제 생성기는 그 후 즉시 개입이 충분한 가치를 제공할지 여부를 평가한다. 이때 긴급성, 결과, 증거 지원, 절약된 사용자 노력량과 같은 요인을 고려한다. 이 평가에 따라 과제는 즉시 제안되거나 수동 할 일 목록에 배치되거나 억제된다.  
- **적극적 준비 및 제어된 실행.** 선택된 과제에 대해 하네스는 정보 탐색 도구, 모바일 GUI 에이전트, 컴퓨터 사용 에이전트 등 적절한 실행자를 선택한다. 사용자를 방해하기 전에 대체 기차 검색, 이동 시간 비교, 환불 상태 확인과 같은 낮은 위험의 준비 작업을 수행할 수 있다. 결과적으로 생성된 과제 카드는 또 다른 알림이 아니라 구체적이고 결정 준비가 된 옵션을 제시한다. 결제, 예약, 메시지 전송 등 외부 결과를 포함하는 작업은 여전히 사용자 확인이 필요하다.  
- **개인화 및 지속적 진화.** 하네스는 지속적으로 그 이해를 정제한다

사용자와 그 사전적 행동에 대한. 프로필 메모리는 명시적 사용자 입력과 증거 기반 관찰에서 구축되며, 시스템이 선호도, 관계 및 루틴을 학습하도록 허용한다. 피드백 메모리는 사용자가 제안된 작업에 어떻게 반응하는지를 기록하며, 승인, 수정, 거절, 무시 및 완료를 포함한다. 이러한 신호는 프로필 항목을 강화하거나 수정하고, 향후 작업의 가치, 타이밍 및 자동화 정도를 조정한다. 따라서 진화는 두 단계에서 발생한다: 프로필 메모리는 사용자가 *무엇* 중요하게 여기는지를 학습하고, 피드백 메모리는 에이전트가 *언제 그리고 어떻게* 언제 어떻게 개입해야 하는지를 학습하여 사전적 지원을 점점 더 개인화되고 유용하게 만든다.

#### <span id="page-18-0"></span>**2.5.2 교차 플랫폼 작업 실행 (Cross-Platform Task Execution)**

사용자의 디지털 활동은 주로 모바일 기기와 컴퓨터에 분산되어 있다. 따라서 많은 실제 워크플로우가 인터페이스, 기능, 상태가 다른 여러 플랫폼에 걸쳐 있다. 예를 들어, 사용자는 에이전트에게 모바일 사진 갤러리에서 영수증을 식별하도록 요청하고, 선택된 이미지를 데스크톱으로 전송한 뒤, 인식된 날짜에 따라 이름을 바꾸고, 구조화된 지출 스프레드시트를 생성하도록 할 수 있다. 이 워크플로우는 휴대폰에서의 시각적 선택, 기기 간 아티팩트 전송, 컴퓨터에서의 파일 처리를 결합한다. 각 기기를 독립적인 에피소드로 다루면 작업 상태가 분산되고, 의존성과 실패가 가려지며, 사용자가 전환을 조정해야 한다. 부록 [A.3](#page-52-0)의 Figure [12](#page-31-2)와 Figure [29](#page-55-1)은 우리 하네스가 실행한 두 개의 워크플로우를 보여준다: 앞서 언급한 영수증 정리 작업과, 여러 모바일 앱을 동시에 실행한 뒤 결과를 컴퓨터에서 요약하는 병렬 식당 검색; 두 경우 모두 모바일 하위 작업은 가상 화면에서 실행되어 사용자가 기기를 계속 사용할 수 있다. 따라서 우리는 하네스를 장치 주소가 지정된 액션, 공유 실행 상태, 명시적 크로스 플랫폼 연산을 갖춘 계층적 플래너–실행기 시스템으로 구현한다:

- **글로벌 인식 및 장치 기반화.** 하네스는 먼저 사용 가능한 장치, 애플리케이션, 디스플레이 및 워크스페이스를 열거한다. 각 관측은 애플리케이션, 장치 및 디스플레이로 태그되며, 스크린샷은 라벨이 붙은 멀티-디바이스 뷰로 조합된다. 이를 통해 플래너는 모바일과 데스크톱 상태를 함께 검사할 수 있다. 공유 상태는 지시문, 애플리케이션–장치 매핑, 최근 관측, 아티팩트, 도구 출력 및 하위 작업 결과를 저장한다. 장치-태그된 업데이트는 나머지 컨텍스트를 보존하면서 해당 플랫폼 상태만 변경한다.
- **의존성 인식 플래닝 및 실행기 선택.** 우리는 지속적인 세션, 워크스페이스 및 도구 레지스트리를 갖춘 OpenClaw 유사 플래너를 구현한다 [(OpenClaw Contributors,](#page-47-4) [2026)](#page-47-4). 플래너는 목표를 의존성 인식 하위 작업으로 분해하고 각 작업에 적절한 실행기를 선택한다. 시각적 기반 애플리케이션 상호작용을 위해 GUI 서브에이전트로 노출된 Qwen-UI-Agent를 호출한다. 검색, 파일, CLI 및 API 도구는 정보 탐색, 결정론적 시스템 운영 및 합성을 처리한다. 각 GUI 호출은 지시문과 대상 애플리케이션 및 장치를 명시한다. 반환된 결과는 세션을 업데이트하여 이후 단계가 최신 상태에서 재플래닝될 수 있도록 한다.
- **병렬 다중 에이전트 실행.** 서로 다른 애플리케이션 또는 환경에 대한 독립 호출은 동시에 실행된다. 고유 식별자와 관측 큐는 각 하위 작업의 행동과 피드백을 격리한다. 그 행동–관측 루프는 순차적이지만, 서로 다른 하위 작업은 병렬로 진행된다. 안드로이드에서는 디스플레이 매니저가 애플리케이션별 하위 작업을 하나의 물리적 장치에 있는 별도 가상 디스플레이에 할당한다. 각 디스플레이는 독립적인 캡처와 디스플레이 주소 지정 입력을 제공하여 여러 Qwen-UI-Agent 인스턴스가 서로 다른 애플리케이션을 동시에 운영할 수 있게 한다.
- <span id="page-18-1"></span>• **Qwen-UI-Agent를 이용한 하이브리드 실행.** 각 GUI 하위 작업은 Section [2.1.2.](#page-5-1)에서 언급한 하이브리드 액션 공간을 사용한다. Qwen-UI-Agent는 시각적 기반 상호작용을 위해 GUI 액션을, 구조화된 작업, 파일 처리 및 외부 서비스를 위해 CLI 또는 API 액션을 사용한다. 데스크톱 CLI 액션은 셸 명령을 실행하고, 안드로이드 액션은 ADB 셸 명령을 사용한다; 그 출력, 오류 및 종료 상태는 구조화된 관측으로 반환된다. 호환 가능한 작업은 배치될 수 있다. 플랫폼 어댑터는 액션을 지정된 환경으로 라우팅하고 장치 간 아티팩트를 전송한다.

### 3.1 실험 설정 (Experimental Setup)

**Models and implementation details.** 우리는 Qwen-UI-Agent의 세 가지 변형(27B, 35B-A3B, 4B 모델)을 평가한다. 27B 모델은 모바일, 컴퓨터 사용, 브라우저, DeepSearch, 일반 에이전트 벤치마크 전반에 걸친 종단 간 에이전트 평가의 주요 변형으로 사용된다. 모델들은 해당 베이스 체크포인트에서 초기화되며, 섹션 [2.4.](#page-12-0)에 설명된 파이프라인을 사용해 훈련된다. 별도로 명시되지 않는 한, 각 벤치마크의 공식 상호작용 예산 및 평가 구성을 따른다.

**Benchmarks.** 우리는 Qwen-UI-Agent를 실제 기기 모바일 사용, 컴퓨터 사용, 브라우저 사용, DeepSearch, GUI 그라운딩, 일반 및 에이전트 기능을 포함한 다섯 그룹의 벤치마크에서 평가한다.

- **Real-device mobile use.** 우리는 MobileWorld-Real과 AndroidDaily에서 모바일 작업 실행을 종합적으로 평가한다. MobileWorld-Real은 섹션 3.2에서 소개된 대로 중국 모바일 생태계에서 실제 Android 기기에서 실행되는 복잡한 인간이 작성한 작업을 포함한다. AndroidDaily는 실제 Android 기기에서 고빈도 일상 작업에 초점을 맞추며 일반 모바일 사용 시나리오에 대한 보완적 평가를 제공한다. 우리는 또한 MobileWorld에서 추가 평가를 수행한다. MobileWorld는 도전적인 장기, 교차 애플리케이션 작업을 위한 안정적인 시뮬레이션 환경을 제공한다.

- **Computer use.** 우리는 OSWorld-Verified와 OSWorld-v2에서 데스크톱 작업 실행을 평가한다. OSWorld-Verified는 광범위한 데스크톱 애플리케이션과 운영 체제 워크플로우 전반에 걸친 작업 진행 상황을 평가한다. OSWorld-v2는 장기 작업에 더 중점을 두고 부분 진행 상황과 이진 작업 완료를 모두 보고한다. 이 벤치마크는 모델이 시각적 상호작용, 명령줄 작업, 배치 동작을 결합하여 복잡한 컴퓨터 사용 워크플로우를 완수할 수 있는지를 평가한다.

- **Web navigation and DeepSearch.** 우리는 WebArena를 사용해 기능적 웹사이트에서 종합적인 브라우저 상호작용을 평가한다. 이 작업은 모델이 변화하는 페이지 상태를 추적하고 다단계 사용자 목표를 완수해야 한다. 우리는 BrowseComp과 BrowseComp-ZH에서 DeepSearch를 별도로 평가한다. 이 두 벤치마크는 영어와 중국어 웹에서 지속적인 정보 탐색, 교차 소스 증거 검증, 답변 합성을 측정한다. 이들 벤치마크는 웹 인터페이스와 직접 상호작용하는 작업과 정보 집계 및 검증이 필요한 연구 집약적 작업을 구분한다.

- **GUI grounding.** 우리는 ScreenSpot-Pro, ScreenSpot-V2, MMBench-GUI L2, OSWorld-G-Refined, UI-Vision에서 요소 위치 지정(로컬라이제이션)을 평가한다. 이 벤치마크는 고해상도 전문 소프트웨어, 모바일 및 웹 인터페이스, 데스크톱 애플리케이션, 텍스트 및 아이콘 목표, 공간 추론, 기능적 추론, 목표 지향적 근거 지침을 포괄한다.

- **General and agentic capabilities.** 우리는 GUI 사후 훈련이 기반 모델의 일반 능력을 보존하는지 MMMU-Pro, RealWorldQA, CharXiv-RQ, MathVision, AI2D, MMLU-Pro, IFEval에서 평가한다. 우리는 또한 Tau2-Bench, Terminal-Bench 2.0, Claw-Eval, BFCL-v4, SkillsBench, QwenClawBench에서 보다 광범위한 에이전트 능력을 평가한다. 이 평가들은 멀티모달 추론, 지시 따르기, 도구 사용, 터미널 운영, 다중 턴 상호작용, 일상 GUI 탐색을 넘어서는 자율 작업 실행과 같은 능력을 측정한다.

**벤치마크 설계 및 작업 범위.** MobileWorld-Real은 인간 기여자가 식별한 일상적 필요에서 파생된 104개의 앱에 걸쳐 409개의 종단 간(end-to-end) 작업을 포함한다. 이 작업들은 일상 모바일 사용의 7개 도메인으로 분류된다: 콘텐츠 소비, 생활 서비스, 생산성, 전자상거래, 시스템 설정, 금융 서비스, 그리고 소셜 커뮤니케이션. 각 도메인 내에서 작업은 여러 사용자 의도를 다룬다. 예를 들어, 콘텐츠 소비는 콘텐츠 검색, 피드 탐색, 게시, 공유를 포함한다. 이러한 작업을 현실적인 조건에서 평가하기 위해, 우리는 섹션 [2.2.2,](#page-8-0) 에서 설명한 실제 기기 런타임에서 실시간 계정 상태와 동적으로 변하는 온라인 콘텐츠와 함께 실행한다. 이는 GUI 에이전트가 팝업, 만료된 로그인, 권한 요청, CAPTCHA 및 사방 환경에서 드물게 발생하는 기타 조건에 노출되도록 한다.

이러한 환경적 도전 과제를 넘어, 많은 작업은 복잡하고 다단계 워크플로우를 포함한다. 거의 절반이 어려운(hard)으로 분류되며, 일반적인 도전 과제로는 장기 실행, 비교 및 순위 매기기, 변화하는 정보에 대한 추론, 깊이 중첩된 앱 기능으로의 탐색, 팝업 복구, 그리고 앱 간 조정이 있다. 벤치마크는 또한 실제 사용자 요청의 모호성을 포착한다. 이는 성공적인 실행에 필요한 모든 정보를 항상 제공하지 않는다. 이러한 경우, 에이전트는 누락된 정보를 식별하고, ask_user를 사용해 필요한 세부 정보를 얻거나, 사용자 개입이 필요한 단계에 대해 사용자 인수(user takeover)를 요청해야 한다.

우리는 MobileWorld-Real의 현실성을 반복 평가의 필요와 균형을 맞춘다. MobileWorld-Real은 특정 과거 주문, 장바구니 상태, 은행 카드, 또는 신뢰성 있게 설정하거나 복원할 수 없는 기타 조건에 의존하는 작업을 피한다. 이는 평가 결과의 높은 안정성을 보장한다. 그림 [7](#page-20-1)은 MobileWorld-Real의 작업 범위, 도전 프로필, 그리고 대표 예시를 요약한다.

#### **3.3.2 컴퓨터 사용 평가 (Computer-Use Evaluation)**

우리는 Qwen-UI-Agent의 컴퓨터 사용 능력을 OSWorld-Verified [(Xie et al.,](#page-49-1) [2024)](#page-49-1) 및 OSWorld-v2 [(Yuan et al.,](#page-49-2) [2026)](#page-49-2)에서 평가한다. 두 벤치마크를 별도로 보고한다. OSWorld-Verified는 361개의 컴퓨터 사용 과제에 대해 부분 진행률을 측정하며, OSWorld-v2는 장기 워크플로우에 초점을 맞추고 부분 진행률과 이진 완료를 모두 보고한다.

표 [4,](#page-24-0)에 나타난 바와 같이 Qwen-UI-Agent는 OSWorld-Verified에서 79.5%의 성공률을 달성하며, 비교된 모든 모델 중 두 번째로 순위를 차지하고 Claude Opus 4.8만이 앞서 있다. 이는 Seed 2.1 Pro, GPT-5.5, Gemini 3.5 Flash, Gemini 3.1 Pro 등 다른 선도적인 폐쇄형 기반 모델과 모든 평가된 오픈-웨이트 기반 모델을 능가한다. 이 결과는 Qwen-UI-Agent가 가장 강력한 폐쇄형 모델과 경쟁할 수 있음을 보여주며, 현재 오픈-웨이트 모델에 비해 상당한 우위를 확보하고 있음을 시사한다.

표 [5,](#page-24-0)에 나타난 바와 같이 Qwen-UI-Agent는 OSWorld-v2에서 부분 점수 40.0%와 이진 완료율 13.9%를 달성하여 최첨단 폐쇄형 모델들 사이에서 경쟁력 있게 위치한다. 특히, 이진 완료에서는 GPT-5.5를 0.9 퍼센트 포인트 앞지르지만, 부분 점수에서는 9.5 포인트 뒤처진다. Qwen-UI-Agent는 또한 평가된 모든 오픈-웨이트 모델을 크게 능가한다. 가장 강력한 오픈-웨이트 기준 모델인 MiniMax M3와 비교할 때, Qwen-UI-Agent는 부분 진행률을 17.7 퍼센트 포인트, 이진 완료를 9.3 포인트 향상시킨다. 이 차이는 Kimi K2.6에 대해 17.9/9.3 포인트, Qwen 3.7 Plus에 대해 18.5/11.1 포인트로 확대된다. 또한 Qwen-UI-Agent는 작업당 평균 135.8 단계만 필요로 하며, 이는 MiniMax M3와 Qwen 3.7 Plus보다 현저히 적다. 이러한 결과는 하이브리드 GUI+CLI 및 배치형 액션 설계가 장기 컴퓨터 사용 워크플로우에서 강력한 작업 성능과 실행 효율성을 모두 제공함을 시사한다.

Qwen-UI-Agent의 핵심 기능은 배치 실행이 가능한 통합 GUI+CLI 액션 공간이다. 대신

<span id="page-25-1"></span>![](2026-08-01-2607.28227-qwen-ui-agent-technical-report-toward-next-generation-real-w/_page_25_Figure_0.jpeg)

Figure 9: **컴퓨터 사용 과제에서 하이브리드 GUI+CLI 실행 시연.** 핵심 프레임은 발행된 액션과 함께 표시되며, CLI 명령은 파란색으로, GUI 액션은 빨간색으로 강조되고 각 단계는 의도를 간단히 주석한다. 이 예시에서 에이전트는 대상 사진을 선택하고 모든 후보를 CLI를 통해 하나의 몽타주로 결합하여 일회성 시각 검사를 수행한다. 각 이미지를 개별적으로 여는 대신이다. 이후 하이브리드 실행을 활용해 CLI 기반 처리와 GUI 기반 검증을 결합하여 최종 출력을 만든다.

CLI를 가끔 fallback으로 사용하는 대신, 모델은 같은 궤적 안에서 GUI와 CLI 액션을 선택하고 교차하도록 학습한다. OSWorld-Verified와 OSWorld-v2에서 CLI 액션은 각각 전체 액션의 **40.7%**와 **55.1%**를 차지하며, 배치 형태로 발행된 액션의 비율은 각각 **39.6%**와 **41.6%**이다. Qwen-UI-Agent가 GUI와 CLI 액션을 결합하는 방식을 Section 4.2에서 자세히 분석한다.

**질적 예시.** Figure 9와 Figure 26은 Appendix A.3에 수록되어 있으며, Qwen-UI-Agent의 두 대표적인 다중 애플리케이션 워크플로우에서의 하이브리드 실행 동작을 추가로 보여준다. 각 키 프레임 아래에 CLI 명령어(파란색)와 GUI 동작(빨간색)이 강조 표시되고, 단계 의도를 짧게 주석으로 달아준다. Figure 9에서는 에이전트가 많은 후보 이미지 중에서 대상 도시 사진과 사용 가능한 날씨 필터를 식별해야 한다. 순수 GUI 실행은 모든 이미지를 개별적으로 열어 검사해야 하지만, 에이전트는 모든 후보를 하나의 CLI 스크립트로 한 번에 모음으로 결합하고 한 번에 검증한 뒤, 합성 및 프레젠테이션 편집을 위해 GUI 동작으로 돌아간다. 두 인터페이스를 보완적으로 사용하는 것은 GUI 또는 CLI 단독보다 하이브리드 실행을 현저히 효율적으로 만든다. 또한 에이전트는 다중 키 단축키 시퀀스나 명령 뒤에 대기(wait)가 있는 연산과 같은 호환 가능한 작업을 한 번의 모델 턴으로 묶는다.

**DeepSearch.** 단순 검색은 종종 웹 탐색 자체의 일부이다: 에이전트가 브라우저에 쿼리를 입력하고, 순위가 매겨진 결과를 검사하며, 잠재적으로 관련 있는 페이지를 여는 과정이다. DeepSearch는 많은 반복적인 GUI 동작을 API 기반 검색과 증거 합성으로 대체함으로써, 에이전트가 GUI 워크플로를 계속하기 전에 외부 컨텍스트를 보다 효율적으로 확보하도록 한다.

DeepSearch는 GUI 실행 전에 지식 및 추론 문제를 해결하며, 모호한 교차 소스 요청을 명시적 목표로 변환한다: Qwen-UI-Agent는 DeepSearch를 통해 월드컵 녹아웃 단계에서 가장 큰 역전 승리를 식별하고, RedNote를 열어 지난 주 가장 높은 참여도를 기록한 관련 게시물을 직접 탐색한다, 앱 내 무작위 검색 없이.

우리는 Qwen-UI-Agent를 BrowseComp와 BrowseComp-ZH에서 평가한다. 이 두 벤치마크는 각각 영어와 중국어 웹에서 지속적인 정보 탐색을 평가한다. 표 7에 나타난 바와 같이, Qwen-UI-Agent는 BrowseComp에서 64.1%, BrowseComp-ZH에서 75.0%를 달성한다. BrowseComp에서 Qwen-UI-Agent는 Qwen3.5-27B, Tongyi-DR-30B, UI-TARS-2를 능가한다. 비록 최첨단 독점 모델과 훨씬 큰 시스템에 비해 성능이 뒤처지지만, 27B 규모에서 경쟁력 있는 영어 DeepSearch 기능을 입증한다. BrowseComp-ZH에서는 Qwen-UI-Agent가 비교된 모든 시스템 중 두 번째로 좋은 결과를 얻으며, Qwen3.5-27B, Tongyi-DR-30B, UI-TARS-2를 크게 앞선다. 이 결과는 Qwen-UI-Agent가 후보 웹페이지를 찾는 것뿐만 아니라, 여러 소스에 분산된 증거를 신뢰할 수 있는, 과제 관련 정보로 합성해 이후 추론 및 GUI 실행에 활용할 수 있음을 보여준다.

정성적 예시. 우리는 GUI 실행과 DeepSearch가 통합되는 상호 보완적인 방식을 보여주는 두 개의 GUI 실행 데모를 추가로 제시한다. GUI 동작은 애플리케이션과의 상호작용을 처리하고, DeepSearch는 외부 지식 획득, 비교 및 의사결정을 담당한다. 첫 번째 데모(그림 10)에서는 GUI 작업이 시작되기 전에 지식 및 추론 문제를 해결해야 한다. 현재 월드컵에서 가장 큰 역전을 기록한 탈락 단계 경기(knockout‑stage match)를 식별하는 것이다. 상단 패널은 키워드 기반 DeepSearch가 순위가 매겨진 소스를 통해 수행되는 다단계 검색 과정을 추적한다. 타깃 웹 가져오기(targeted web fetches)를 통해 경기 점수를 추출하고 교차 검증한 뒤, 검색 요약(search summary)이 아르헨티나의 0–2 뒤처진 뒤 3–2 역전(Argentina's 3–2 comeback after trailing 0–2)을 식별한다. DeepSearch는 모호하고 교차 소스에 걸친 사용자 요청을 실행이 시작되기 전에 명시적인 GUI 목표로 변환한다. 따라서 아래의 경로에서 에이전트는 RedNote를 열고, 식별된 경기를 직접 검색하며, 지난 일주일간의 게시물을 필터링하고, 블라인드 인앱 검색이나 시행착오 없이 가장 많이 논의된 게시물을 연다. 두 번째 데모(그림 27, 부록 A.3)는 DeepSearch가 GUI 실행 중간에 필요에 따라 호출되는 경우를 보여준다.

#### <span id="page-29-0"></span>**3.3.5 일반 및 에이전트 역량 (General and Agentic Capabilities)**

### 3.4 하네스 기반 워크플로우 (Harness-Enabled Workflows)

벤치마크 평가를 넘어, 우리는 Section [2.5,](#page-15-0) 에서 도입한 하네스 레이어가 제공하는 워크플로우를 정성적으로 검토한다. 이 레이어는 사전 서비스 시작과 크로스 플랫폼 작업 실행을 다룬다.

## 4 GUI 에이전트 실행의 행동 분석 (Behavioral Analysis of GUI Agent Execution)

집계 벤치마크 점수는 에이전트가 작업을 완료했는지를 보여 주지만, 작업을 어떻게 수행하는지, 왜 실패하는지, 그리고 RL 훈련 후에 행동이 어떻게 변하는지에 대해서는 덜 드러낸다. 따라서 우리는 Qwen-UI-Agent의 실행 행동에 주로 초점을 맞춘 네 가지 질문을 살펴본다. **(1)** 시뮬레이션 벤치마크에 최적화된 모델이 물리적 장치에서 왜 어려움을 겪는가? **(2)** Qwen-UI-Agent는 작업 실행 중에 GUI, CLI, 그리고 배치 액션을 어떻게 결합하며, 이러한 선택에서 어떤 독특한 실행 패턴이 나타나는가? **(3)** 액션 RL은 단계별 실행 행동을 어떻게 바꾸는가? **(4)** 온라인 RL은 장기 경로에서 경로 수준 행동을 어떻게 재구성하는가? 이 분석들은 집계 지표를 보완하여 에이전트가 도전적인 환경에 어떻게 반응하고, 액션 공간을 어떻게 활용하며, RL 훈련 후에 어떻게 변하는지를 보여준다.

### <span id="page-31-1"></span>4.1 모델의 제한된 실제 장치 경험이 실행 행동에 미치는 영향

**실제 장치 실패에 대한 행동 분석.** 대부분의 모델은 훈련 중 물리적 장치 상호작용에 직접적인 노출이 제한적이다. Qwen 3.7 Plus와 같은 최첨단 모델은 광범위한 벤치마크에서 강력한 성능을 보이지만, MobileWorld-Real에서의 결과는 물리적 장치에서의 신뢰할 수 있는 실행이 여전히 어려움을 겪고 있음을 시사한다. 이는 보다 구체적인 행동 질문을 제기한다: 훈련 중 실제 장치 상호작용이 제한적일 때 어떤 실행 패턴이 나타나며, 이러한 패턴이 작업 실패에 어떻게 기여하는가? 이 질문을 조사하기 위해 우리는 MobileWorld-Real과 AndroidDaily에서 실패한 모든 Qwen 3.7 Plus 경로를 검토하여 주요 실패 모드를 식별한다.

표 [10,](#page-32-0)에 나타난 바와 같이, 우리는 훈련 중 실제 상호작용 경험 부족에 기인한 두 차원으로 실패를 정리한다: *실행 능력 제한* (40.3%) – 시뮬레이션 환경이 탐색, 오류 복구, 상태 추적을 학습하도록 유도하지 못함, 그리고 *실제 시나리오 도전* (52.0%) – 정제된 시뮬레이터가 거의 포함하지 않는 인터페이스 현상에 의해 유발됨. 그림 [13,](#page-32-1)에서 우리는 대표 사례에 대해 모델의 축약된 사고와 두 개의 핵심 프레임을 짝지어 보여준다.

각 패턴의 사례를 제시하고, 아래에서 각 패턴을 자세히 분석한다.

**실행 능력 한계.** Qwen 3.7 Plus의 이 차원에서의 실패(40.3%)는 세 가지 실행 능력의 한계를 반영한다: 덜 흔히 사용되거나 깊이 중첩된 앱 기능을 찾는 것, 예기치 않은 피드백이나 인터페이스 상태에서 복구하는 것, 그리고 긴 경로에서 작업 상태를 유지하는 것.

• *탐색 실패* (19.5%)는 목표가 여러 진입점이나 깊은 페이지 계층 뒤에 숨겨진 덜 흔히 사용되는 기능일 때 발생한다. 이러한 경우 Qwen 3.7 Plus는 대체 경로를 탐색하기보다 얕은 페이지 몇 개를 반복적으로 방문한다 (Figure [13(](#page-32-1)a)). 반면 Qwen‑UI‑Agent는 경로를 확정하기 전에 여러 개의 가능성 있는 진입점을 검토한다.

- *오류 행동 루프* (14.3%)는 실제 서드파티 애플리케이션의 긴 꼬리에서 비롯되며, 여기서 동작이 기대되는 전환을 자주 실패한다. 이러한 기대 위반을 처리하는 것은 시뮬레이터가 예측 가능한 상호작용 결과를 제공하기 때문에 학습 기회가 거의 없으며, 학습 시 물리적 장치와의 상호작용 노출이 제한된 모델은 실패를 진단하고 계획을 수정하기보다는 같은 동작을 반복하거나 두 개의 인터페이스 상태를 번갈아 가며 수행한다 (Figure [13(](#page-32-1)b)).  
- *실행 상태 상실* (6.5%)는 앱 전환, 중단, 다중 하위 작업을 거치면서 중간 정보와 완료된 진행 상황을 보존해야 하는 장기 목표 작업에서 나타난다. 이러한 경로에서 Qwen 3.7 Plus는 이전 진행 상황을 잃어버리고 완료된 하위 작업을 반복하거나 워크플로우의 일부를 처음부터 다시 시작할 수 있다 (Figure [13(](#page-32-1)c)).

**실제 시나리오 도전 과제**. 이 차원에서의 실패(52.0%)는 물리적 장치에서 흔히 발생하지만 훈련 중에 덜 자주 나타나는 인터페이스 조건을 포함한다: 모호한 페이지 의미, 예기치 않은 인터페이스 중단, 세밀한 조작이 필요한 인터랙티브 위젯.

- *UI 오독* (24.7%)는 실제 페이지가 순수 시각적 외형만으로는 해석할 수 없는 상태를 갖고 있기 때문에 발생한다. 예를 들어 사전 입력된 검색어, 자리 표시자 힌트, 동적으로 새로 고쳐지는 목록 등이 있으며, 시뮬레이터 인터페이스는 깨끗하고 정적이다. 시뮬레이션 환경에서 훈련된 모델은 인터페이스 상태를 잘못 판단하며, 가장 흔히 회색 자리 표시자를 사용자 입력 텍스트로 착각하고 이를 지우려다 다시 입력하는 대신 반복적으로 지우려 한다 (Figure [13(](#page-32-1)d)).  
- *팝업 간섭* (18.2%)은 광고, 결제 장벽, CAPTCHA, 반응 없음 또는 빈 페이지를 포함하며, 시뮬레이터는 재현성을 위해 설계상 이러한 비결정적 중단을 제외한다. 회복 절차가 없으므로 모델은 원래 작업에서 벗어나거나 차단된 경로를 계속 재시도한다 (Figure [13(](#page-32-1)e)).  
- *물리적 위젯 제어* (9.1%)는 스크롤 휠, 슬라이더, 날짜 선택기 등과 같이 점진적 폐쇄 루프 조작이 필요한 경우를 다룬다. 에이전트는 현재 값을 관찰하고 스와이프 크기를 조정해야 한다. 시뮬레이션 환경에서는 이러한 값이 일반적으로 직접 텍스트 삽입이나 단일 탭으로 설정되므로, 에이전트는 고정 크기 스와이프를 적용해 양쪽 방향으로 목표를 초과하고 결합하지 못한다 (Figure [13(](#page-32-1)f)).

위의 결과는 Section [2.2.2](#page-8-0)에서 설명한 실제 장치 기반 훈련 및 평가 인프라를 동기화하며, Qwen-UI-Agent가 실제 모바일 장치에서 뛰어난 성능을 보이는 이유를 설명한다.

### <span id="page-33-0"></span>4.2 GUI–CLI 조정 및 배치 실행에 대한 자세한 살펴보기 (A Closer Look at GUI–CLI Coordination and Batched Execution in Qwen-UI-Agent)

Qwen-UI-Agent는 GUI와 CLI 액션을 교차하는 궤적을 통해 컴퓨터 사용 작업을 수행하며, 선택적으로 여러 액션을 배치 형태로 함께 방출한다. 이 하이브리드 실행 프로세스는 두 가지 질문을 제기한다: 모델은 GUI와 CLI 사이에서 어떻게 작업을 분할하고, 언제 여러 액션을 배치하도록 선택하는가? 우리는 OSWorld-Verified와 OSWorld-v2에서 Qwen-UI-Agent가 생성한 궤적을 분석하고, 그 결과 행동 패턴을 아래에 제시한다.

### <span id="page-38-0"></span>4.3 단계별 행동 교정 후 Action RL (Step-Level Behavioral Corrections after Action RL)

**전반적 성능 및 행동 변화.** 우리는 Action RL 훈련 전후 모델 행동을 비교 분석한다. Action RL의 주요 효과는 단순히 전체 작업 성공률이 향상되는 것이 아니라, 세분화된 단계별 수준에서 오류가 있는 행동 결정을 체계적으로 교정한다는 점이다. 전체 작업 SR을 7% 이상 향상시키는 것 외에도, Action RL은 추론 토큰 수를 21.3% 감소시키고 평균 상호작용 단계 수를 8.4% 증가시킨다. 이러한 변화는 업데이트된 정책이 불필요한 추론을 줄이고 환경 기반 행동으로 결정을 더 빈번히 전환한다는 것을 시사한다. 더욱이, 성능 향상은 반복되는 행동 오류를 체계적으로 교정하는 명확한 행동 패턴 변화를 동반한다. 아래에서 이를 자세히 살펴본다.

**반복되는 오류 패턴 교정.** Table [12,](#page-38-1)에 표시된 바와 같이 Action RL은 다섯 가지 오류 패턴별 테스트 세트에서 일관되게 성능을 개선한다. 시각적 또는 의미상 유사한 후보 중 올바른 타깃을 선택해야 하는 기반 작업에서 Action RL은 SR을 6.3% 향상시킨다. 또한 정렬 및 순위, 수량 및 다중 타깃 완전성, 조기 완료 작업에서 각각 3.8%, 4.4%, 5.2%의 SR 향상을 보인다. Action RL의 효과는 특히 단거리 행동 루프를 교정하는 데 두드러진다. 다수의 타깃에 걸친 반복 작업이나 긴 스크롤 가능한 인터페이스를 탐색하는 작업에서 Action RL은 SR을 9.5% 향상시킨다. 이 이득은 최근 행동이 작업 관련 상태 변화를 생성하지 못했을 때 이를 인식하고 대체 행동으로 전환하는 능력이 강화되었음을 나타낸다. ### 4.4 온라인 RL 이후 트레저리 수준 행동 변화 (Trajectory-Level Behavioral Shifts after Online RL)

다양한 도메인에서 온라인 RL 전후에 생성된 트레저리리를 신중히 비교함으로써, 우리는 세 가지 바람직한 행동 패턴의 출현을 확인한다.

가정된 성공에서 검증된 완료로. 온라인 RL 이전에는 정책이 최종 상태 변화를 일으킨 직후 바로 종료하며, 의도된 효과를 검증하지 않고 작업이 완료된 것으로 가정한다. 온라인 RL 이후에는 정책이 종료 전에 결과 상태를 더 자주 검사하고, 검증에서 실행이 불완전함을 발견하면 복구한다. Figure 19는 대표적인 예시를 보여준다. 온라인 RL 이전에는 정책이 Bash 명령 시퀀스를 수행하고 그 효과를 확인하지 않고 완료를 선언한다. 온라인 RL 이후에는 정책이 동일한 Bash 기반 경로를 따르되 검증 단계를 추가하고, 의도된 출력의 일부가 생성되지 않았음을 발견하고 대체 접근법으로 전환한 뒤 결국 작업을 성공적으로 완료한다. OSWorld에서의 집계 결과는 같은 추세를 보인다: 최소 하나의 검증 액션을 포함하는 트레저리리 비율이 14.7% 증가하고, 최종 검증기를 통과하지 못한 자가 선언 성공 에피소드 비율인 거짓 정지율이 11.2% 감소한다.

**Bash를 손으로, GUI를 눈으로: 출현하는 교차 모달 협업.**  
온라인 RL 이후, 정책은 Bash 중심 전략에서 Bash와 GUI 행동을 보다 균형 있게 사용하는 방향으로 전환된다: GUI 행동의 비중이 6% 증가하고, GUI와 Bash를 모두 사용하는 궤적 비율이 10.6% 증가한다. 특히, 모달리티 조정에 대한 명시적 목표가 없음에도 불구하고 유용한 교차 모달 협업 패턴이 나타난다: 정책은 Bash를 사용해 상태 변화를 효율적으로 실행하고 GUI를 사용해 그 효과를 검사한다. 이 패턴과 일치하게, 두 모달리티를 모두 사용하는 궤적 비율이

Figure 21: **온라인 RL이 장기 탐색 및 검증을 향상시킵니다.** 온라인 RL 없이, 모델은 잘못된 엔티티 연관을 따르고 지원되지 않는 답변인 광저우에 도달한다. 온라인 RL을 사용하면, 모델은 하이 얀, *Nirvana in Fire*, 황위드, 그리고 청두의 핵심 체인을 식별한다.

실행–검증 전이—상태를 변경하는 Bash 동작 뒤에 읽기 전용 GUI 검사가 따라오며, 비율이 40.2%에서 52.4%로 증가한다. **장기 수평에서 제약 조건 유지.** 장기 수평 작업은 종종 양, 형식, 범위, 제외 등 주요 목표에 추가 제약을 부과한다. 온라인 RL 전후의 행동을 비교하면, 정책이 지침에서 앞서 도입된 제약을 실행 전반에 걸쳐 보존하는 데 더 신뢰할 수 있게 된다. 두 벤치마크 전반에서, 모든 지침 제약을 만족하는 작업 비율이 OSWorld에서 8.6%, BrowseComp-ZH에서 7.5% 증가한다. Figure [21](#page-41-1)은 네 가지 제약이 포함된 대표적인 BrowseComp-ZH 예시를 보여준다. 이 경우, 정책은 한 제약만 만족하고 잘못된 결론에 이르던 것에서 모든 네 제약을 보존하고 공동으로 적용함으로써 올바른 답변을 도출한다.

## <span id="page-41-0"></span>5 관련 연구 (Related Work)

최근 *mobile-use*, *browser-use*, 및 *computer-use* 전반에 걸친 GUI 에이전트 연구는 프롬프트 전용 오케스트레이션보다 네이티브 다중모달 정책을 점점 더 선호하며, 자체 진화 데이터 엔진, 온라인 강화 학습, 구조화된 메모리의 활용이 강화된다 [(Seed,](#page-48-11) [2025;](#page-48-11) [Zhou et al.,](#page-50-0) [2025a;](#page-50-0) [Gao et al.,](#page-45-1) [2026;](#page-45-1) [He et al.,](#page-45-13) [2024;](#page-45-13) [Wang et al.,](#page-48-10) [2025b;](#page-48-10) [Huang et al.,](#page-46-0) [2026)](#page-46-0). 이 분야는 또한 벤치마크 전용 최적화에서 실제 장치 실행, 프라이버시, 운영 신뢰성, 안전성, 지연 시간 등 실질적 배포 문제로 전환하고 있다 [(Cao et al.,](#page-45-0) [2026;](#page-45-0) [Qin et al.,](#page-47-0) [2025;](#page-47-0) [Zhou et al.,](#page-50-0) [2025a;](#page-50-0) [Huang et al.,](#page-46-0) [2026)](#page-46-0).

**모바일 사용.** 최근 모바일 에이전트 연구는 스크린샷 기반 행동 예측-

tion은 메모리, 반성, 강화학습(RL), 그리고 에이전트 기반 활용을 갖춘 보다 강력한 시스템으로의 전환을 의미한다. Mobile-Agent-v3.5 [(Xu et al.,](#page-49-0) [2026)](#page-49-0)와 UI-Venus-1.5 [(Gao et al.,](#page-45-1) [2026)](#page-45-1)은 다양한 플랫폼과 작업에 걸쳐 통합 GUI 모델을 확장한다. MAI-UI [(Zhou et al.,](#page-50-0) [2025a)](#page-50-0)은 하이브리드 GUI-MCP 운영과 디바이스–클라우드 협업을 탐구한다. Xiaomi-GUI-0 [(Cao et al.,](#page-45-0) [2026)](#page-45-0)은 상태 역학을 포착하는 실제 디바이스 폐쇄 루프 훈련을 연구한다. 기존 모바일 에이전트 평가는 주로 세 가지 측면에 초점을 맞춘다: 근거화 능력(예: ScreenSpot-Pro [(Li et al.,](#page-46-6) [2025a)](#page-46-6)), 제어된 환경에서의 상호작용 작업 완료(예: AndroidWorld [(Rawles et al.,](#page-47-9) [2024)](#page-47-9)), 그리고 보다 현실적인 일상 사용 시나리오(예: MobileWorld [(Kong et al.,](#page-46-4) [2026)](#page-46-4), AndroidDaily [(Sui et al.,](#page-48-3) [2026)](#page-48-3), RealMobile [(Cao et al.,](#page-45-0) [2026)](#page-45-0)).

**브라우저 사용.** 모바일 에이전트와 달리 브라우저 사용 에이전트는 DOM 트리, 접근성 트리, 브라우저 API와 같은 구조화된 정보를 추가로 활용할 수 있다. WebVoyager [(He et al.,](#page-45-13) [2024)](#page-45-13)와 SeeAct [(Zheng et al.,](#page-50-6) [2024)](#page-50-6)은 다중모달 LLM이 시각적 이해와 브라우저 동작을 결합하여 엔드-투-엔드 웹 탐색을 수행할 수 있는 능력을 입증한다. 최근 프로젝트인 OpenAI Operator [(OpenAI,](#page-47-15) [2025)](#page-47-15), Google Project Mariner [(Google,](#page-45-14) [2025)](#page-45-14), 그리고 UI-TARS [(Seed,](#page-48-11) [2025)](#page-48-11)은 웹 에이전트를 복잡한 웹사이트와 다양한 디지털 환경과의 자율 상호작용으로 확장한다. WebWorld [(Xiao et al.,](#page-49-11) [2026)](#page-49-11)와 WebEvolver [(Fang et al.,](#page-45-15) [2025)](#page-45-15)은 웹 에이전트를 위한 세계 모델 기반 접근법을 탐구한다. 웹 에이전트 평가는 단기 웹페이지 탐색에서부터 여러 웹사이트와 복잡한 목표를 포함하는 현실적인 장기 워크플로우로 진화했다 [(Zhou et al.,](#page-50-1) [2024;](#page-50-1) [Xue et al.,](#page-49-12) [2025;](#page-49-12) [Jang et al.,](#page-46-11) [2026)](#page-46-11).

**컴퓨터 사용.** 컴퓨터 사용 에이전트(CUA)는 다양한 소프트웨어와 생산성 애플리케이션을 포함한 데스크톱 환경과의 일반적인 상호작용을 가능하게 하는 것을 목표로 한다. 모바일 및 웹 에이전트와 달리 CUAs는 훨씬 더 큰 행동 공간, 다양한 상호작용 상태, 그리고 긴 시야를 갖추고 있어 신뢰할 수 있는 근거화와 실행 검증이 중요하다. UI-TARS [(Qin et.,](#page-47-0) [2025)](#page-47-0), DART-GUI [(Li et.,](#page-46-12) [2025b)](#page-46-12), OpenCUA [(Wang et.,](#page-48-10) [2025b)](#page-48-10), UltraCUA [(Yang et.,](#page-49-13) [2025b)](#page-49-13), EvoCUA [(Huang et.,](#page-46-0) [2026)](#page-46-0)은 다중모달 사전학습, 대규모 상호작용 데이터, 그리고 에이전트 기반 추론을 활용하여 확장 가능한 GUI 기반 모델을 조사한다. 최근 CUA 벤치마크는 점점 더 견고성, 확장성, 그리고 실제 배포 과제를 강조한다. OSWorld-Verified는 엄격한 검증 프로토콜과 성공 평가의 모호성을 줄여 평가 신뢰성을 향상시킨다 [(Xie et.,](#page-49-1) [2024)](#page-49-1). OSWorld-v2는 보다 복잡하고 장기 워크플로우, 그리고 다양한 실제 컴퓨터 작업으로 평가를 확장한다 [(Yuan et.,](#page-49-2) [2026)](#page-49-2).

## <span id="page-42-0"></span>6 결론 (Conclusion)

우리는 실제 세계 중심의 기초 GUI 에이전트인 Qwen-UI-Agent를 제시하였다. 실제 기기에서 동작하고, 플랫폼 간 워크플로우를 유지하며, GUI 상호작용과 CLI 실행을 결합하고, 유용한 서비스를 사전에 시작하는 에이전트의 비전을 바탕으로, Qwen-UI-Agent는 확장 가능한 샌드박스 환경과 견고한 실제 기기 모바일 런타임, 통합된 GUI+CLI 액션 공간, 에이전트 주도형 데이터 플라이휠, SFT, 액션 RL, 온라인 RL을 결합한 훈련 프레임워크, 그리고 사전 서비스 시작과 교차 플랫폼 작업 실행을 위한 하네스 레이어를 통합한다. 실험적으로 Qwen-UI-Agent는 MobileWorld에서 **82.1%**, MobileWorld-Real에서 **92.2%**, AndroidDaily에서 **97.5%**를 달성한다. 또한 OSWorld-Verified에서 **79.5%**, OSWorld-v2에서 **40.0%**를 기록한다. Qwen-UI-Agent는 브라우저 사용, DeepSearch, GUI-그라운딩 분야에서도 선도적이거나 경쟁력 있는 성능을 확보하며, 강력한 일반 추론 및 에이전트 능력을 보존한다. 이러한 결과는 모델, 환경, 데이터 플라이휠, 훈련, 하네스를 실제 세계 사용을 중심으로 공동 설계한 GUI 에이전트 개발의 시스템적 관점을 뒷받침한다.

## 7 제한 사항 및 향후 방향 (Limitations and Future Directions)

**제한 사항.** 첫째, 우리는 결정론적 검증자나 수동 전문가 검토 대신 AutoJudge를 사용해 실제 기기 모바일 궤적을 평가한다. 결정론적 상태 기반 검증은 제3자 애플리케이션의 내부 상태에 대한 접근이 제한되기 때문에 물리적 휴대폰에서는 일반적으로 불가능하다. 한편, Qwen-UI-Agent와 10개의 기초 모델의 궤적을 수동으로 판정하려면 상당한 전문가 노력이 필요하며 주석자 간 변동성을 초래한다. 일관된 비교를 위해 우리는 모든 시스템에 동일한 AutoJudge 프로토콜을 적용한다. 전문가가 독립적으로 검토한 666개의 예시에서 AutoJudge는 92.8%의 정확 일치 정확도를 달성한다. 그럼에도 불구하고 남은 오류는 보고된 실제 기기 결과에 소폭의 불확실성을 도입할 수 있다. 둘째, 35B-A3B 규모의 CUA 및 DeepSearch 훈련은 이 기술 보고서가 발표될 때 아직 진행 중이었으므로 해당 결과는 포함되지 않았다. 이러한 결과가 공개되면 arXiv 버전을 업데이트할 계획이다. 셋째, 본 보고서에 기술된 실제 기기 환경을 넘어, 실제 애플리케이션을 보다 정밀하게 재현하는 고충실도 합성 환경은 시뮬레이션-실제 차이를 좁히는 또 다른 경로를 제공한다. 우리는 이러한 환경을 구축했지만, 훈련에 이를 활용한 모델은 아직 보고된 모델에 포함되지 않았으므로 현재 보고서에서는 이 구성 요소를 제시하지 않는다. 향후 작업에서 환경 합성 방법론을 오픈소스로 공개할 계획이다. 넷째, GUI 기능 개발을 완전히 자동화하려는 시도는 현재 기초 모델이 전체 프로세스를 신뢰성 있게 관리할 수 없음을 보여주었다. 따라서 우리의 파이프라인은 완전 자율이 아니라 에이전트 주도형이며, 진행 상황을 모니터링하고 오류를 수정하기 위해 상당한 인간 감독 및 개입이 필요하다.

**향후 방향.** 우리는 GUI 에이전트가 신뢰할 수 있고 실용적인 실제 세계 사용으로 나아갈 때 추가 연구가 필요하다고 생각되는 몇 가지 방향을 논의한다.

- **Efficient GUI Execution.** GUI 에이전트는 실제 장치에서 점점 더 복잡한 워크플로우를 직접 수행할 수 있어 실용적 사용으로 가는 유망한 단계이다. 그러나 단지 기능만으로는 충분하지 않다. 실행 효율, 특히 상호작용 지연(latency)은 실용적 사용에 있어 주요 장애물이다. 각 GUI 단계는 일반적으로 새로운 관측, 모델 추론, 환경 전이 등을 필요로 하여 긴 경로에서 지연이 누적된다. 모바일과 데스크톱 시스템 전반의 가상 디스플레이 메커니즘은 백그라운드 또는 병렬 실행을 가능하게 하여 이 문제를 부분적으로 완화할 수 있지만, 인식–추론–행동 루프의 기본적인 단계별 비용을 제거하지는 못한다. 더 빠른 추론, 적응형 관측, 비동기 실행, 그리고 상호작용 라운드 감소를 통해 이 비용을 줄이는 것은 GUI 에이전트를 실용적 현실 세계 사용으로 가져오는 데 있어 중요한 과제이다.  
- **Harness-Assisted Long-Horizon Workflows.** 우리의 하이브리드 GUI+CLI 액션 공간과 배치 액션 지원은 실행 효율을 향상시키며, 온라인 RL은 긴 경로에서 의사결정을 강화한다. 보완적인 방향은 모델 자체를 넘어 하이렌스가 장기 지원의 원천으로 활용되는 것을 더 탐구하는 것이다. 컨텍스트 압축, 작업 분해, 메모리 관리, 진행 추적, 구조화된 도구 사용 등 하이렌스 수준 설계는 다른 관점에서 장기 워크플로우의 효율성과 신뢰성을 향상시킬 수 있다.  
- **Large-Scale Cross-Domain Online RL.** 장기 GUI 작업은 롤아웃이 느리고 길이가 변동적이며 보상이 드물거나 지연되는 경우가 많아 온라인 RL을 비용이 많이 든다. 향후 연구는 이러한 환경에 대해 보다 효율적이고 안정적인 학습 전략을 개발하고, 브라우저 사용, 모바일 사용, 컴퓨터 사용 환경을 동시에 학습시켜 데이터 효율성과 도메인 간 일반화를 향상시켜야 한다 [(Wang et al.,](#page-48-0) [2025a;](#page-48-0) [Hou et al.,](#page-45-16) [2026)](#page-45-16).  
- **Scalable Synthesis of High-Fidelity Environments.** 실제 장치 환경은 가장 충실한 상호작용 역학을 제공하지만, 확장, 재설정, 검증 비용이 높다. 고충실도 합성 환경은 실제 세계 애플리케이션 동작을 대규모로 생성 및 제어할 수 있는 형태로 근사함으로써 보완적인 경로를 제공한다. 이러한 환경의 확장 가능한 합성은 시뮬레이션-실제 차이를 좁히고 현실 지향적 훈련을 확장하는 데 중요하다. 우리는 이러한 환경을 구축했으나, 불행히도 그 통합이 모델 훈련에 적시에 완료되지 않았다

이 보고서에. 우리는 향후 연구에서 환경 합성 방법론을 오픈소스로 공개할 예정이다.

• **Safety, User Control, and Personalization.** GUI 에이전트가 애플리케이션과 장치를 가로질러 작동할 수 있는 능력을 갖추면서, 그 행동이 안전하고 사용자 제어 하에 유지되는 것을 보장하는 것이 점점 더 중요해진다. 본 연구에서는 모델이 call_user 액션을 호출하고 추가 입력이나 권한 부여가 필요할 때 사용자에게 제어를 반환하도록 가르치는 안전 민감한 훈련 시나리오를 포함한다. 보다 체계적인 안전 평가, 안전 지향 훈련 목표, 그리고 에이전트 행동을 이해하고 제약하기 위한 해석 기반 방법은 여전히 중요한 방향이다. 개인화는 현실 세계 사용자 경험을 향상시키는 데에도 똑같이 중요하다. 우리의 프로액티브-서비스 harness는 초기 탐색을 제공하지만, 유용한 사용자 메모리와 프로필을 구축하고, 이를 신뢰할 수 있는 정보원에 기반을 두며, 사용자가 보존되는 정보를 제어하도록 허용하는 것은 모두 추가 조사가 필요하다.

# <span id="page-51-1"></span>A.1 AutoJudge를 실기기 평가에 검증하기 (Validating AutoJudge for Real-Device Evaluation)

샌드박스 벤치마크와 달리, 실기기 작업은 일반적으로 결정론적이고 상태 기반 검증기에 의존할 수 없다. 제3자 앱은 내부 상태를 노출하지 않으며, 작업 결과는 변동하는 온라인 콘텐츠, 계정 상태, 또는 여러 앱 간 상호작용에 따라 달라질 수 있다. 모든 경로를 수동으로 검토하는 것은 규모를 확장하기 어렵고 주석자 간 변동성을 초래할 수 있다. 따라서 우리는 대규모 실기기 평가에 사용하기 전에 AutoJudge를 독립 인간 주석과 검증한다.

<span id="page-51-3"></span>**AutoJudge와 독립 인간 주석 간의 일치** 행은 AutoJudge 결정, 열은 인간 주석을 나타낸다. pass는 결합된 perfect/fair_enough 범주에 해당한다. 일치는 불분명으로 표시된 인간 주석을 제외한 뒤 계산된다.

|  | 인간 주석 |  |  |  |  |
|--------------------|-------------------------------------------|------------------|----------------------|---------|--------------------|
| AutoJudge 결정 | 통과 | Model<br>실패 | Environment<br>오류 | 불명확 | Class<br>일치 |
| 통과 | 455 | 17 | 1 | 1 | 96.2% |
| 실패 | 15 | 144 | 9 | 1 | 85.7% |
| env_error | 1 | 5 | 19 | 0 | 76.0% |
| Overall | 666개의 결론적 사례 중 618건이 일치했다 |  |  |  | 92.8% |

표 [14](#page-51-3)은 비교 결과를 보고한다. AutoJudge는 결론적 인간 라벨이 있는 666개의 트래젝터리 중 618개에서 인간 주석과 일치하며, 이는 전체 일치율이 92.8%임을 의미한다. 성공적인 트래젝터리에서는 일치율이 96.2%에 이른다. 모델 실패와 환경 오류는 구분하기가 더 어렵다. 유사한 관측은 잘못된 에이전트 행동이나 라이브 실행 환경의 문제 중 어느 하나에서 발생할 수 있기 때문이다.

우리는 AutoJudge와 초기 인간 주석이 불일치하는 경우를 전문가 리뷰어에게 검토하도록 요청한다. 전문가 판정은 더 자주 AutoJudge 결정을 지지하며, 이는 앞서 보고된 일치율이 정확도의 보수적 추정임을 시사한다. 이 검증을 바탕으로 우리는 AutoJudge를 실기기 실험의 주요 평가자로 사용한다. AutoJudge는 모델 실패와 라이브 환경에 의해 발생한 오류를 별도로 식별하면서 보다 정확하고 확장 가능한 평가 프로토콜을 제공한다.
